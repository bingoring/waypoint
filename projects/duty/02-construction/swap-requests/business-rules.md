# business-rules — 2-8 근무 교환 요청

| ID | 규칙 |
|---|---|
| R-SWAP-1 | 요청은 로그인한 간호사(교대 근무자)가 보낸다. 요청자는 당사자에 자동 포함, 당사자 2~10명, 모두 교대 근무자·그날 재직. 관리자는 교환 요청 대신 2-7 직접 편집. |
| R-SWAP-2 | 대상 달은 CONFIRMED, 오늘이 그 달의 협의 기간(`negotiationStart ≤ today ≤ negotiationEnd`) 안. 밖이면 「근무 조정」 버튼 비활성 + "협의 기간(10/16 – 10/20)에만 교환 요청을 보낼 수 있습니다". |
| R-SWAP-3 | 당사자의 그날 칸은 모두 `swappable`(D·E·N·OFF regular). before·after 코드 다중집합이 같아야 한다(같은 날 D/E/N 개수 유지). 바뀌는 사람이 1명도 없으면 거부. |
| R-SWAP-4 | 보낼 때 서버가 2-2 검사기로 재검사: 교환으로 새로 생기는 필수 위반이 있으면 거부(권고 위반은 문구만 보여 주고 허용). 브라우저 검사와 같은 입력(월초 잔여 채움). |
| R-SWAP-5 | 요청 당시 칸(before)이 현재 칸과 다르면 거부("그 사이 근무가 바뀌었습니다"). |
| R-SWAP-6 | 겹침: 같은 (사람, 날짜)가 걸린 대기 요청이 있으면 팝업에 "먼저 보낸 요청이 있습니다" 경고, 보내기는 허용. |
| R-SWAP-7 | 응답은 그 요청의 당사자만, PENDING에서만, 협의 기간 안에서만. 거절 1명 = REJECTED. 수락하면 본인 response만 ACCEPTED. |
| R-SWAP-8 | 전원 수락이 되는 순간(마지막 수락 트랜잭션): 계획 행 잠금 → 칸 재확인(R-SWAP-5) → 필수 위반 재검사 → 통과면 칸 반영(`source='swap'`, `editedBy=요청자`) + 편집마다 `cell_edit_logs(reason='swap')` + APPLIED, 실패면 INVALID(사유). |
| R-SWAP-9 | 반영되면 같은 (사람, 날짜)가 걸린 다른 대기 요청은 INVALID("다른 교환이 먼저 반영되었습니다"). 2-7 관리자 저장·휴가 승인·휴가 취소로 칸이 바뀌면 걸린 대기 요청도 INVALID("관리자가 근무를 바꿨습니다"). |
| R-SWAP-10 | 요청자는 PENDING 요청을 철회(CANCELLED)할 수 있다. 협의 기간이 끝나면 조회 때 PENDING → EXPIRED. |
| R-SWAP-11 | 권한: 요청·코멘트는 당사자만 본다(DTO에서 걸러냄). 관리자는 이 달 요청 현황을 읽기 전용으로 본다. |
| R-SWAP-12 | 알림: 받은 대기 요청 수 = 근무 조정 메뉴 배지 · 패널 탭 배지 · 근무표 띠 "받은 교환 요청 N건 → 근무 조정". 반영된 칸은 당사자에게 2-7 "바뀐 근무" 안내(요청자 본인 칸은 제외). |
| R-SWAP-13 | 칸 표시: `source='swap'`은 외곽선 없음(핸드오프 "외곽선 없음 또는 별도 표기 없음"). 칸 설명(title)에 "교환 반영". |
