# Business Rules — 2-4 관리자 설정

## 1. 규칙 표

### 1.1 간호사 (S10)

| ID | 규칙 | 근거 |
|---|---|---|
| R-STAFF-ADD-1 | 사번은 필수이고 전역에서 유일하다(제거된 사용자 포함). 추가 후 바꿀 수 없다 | 1-2 §6-1, 원문 §12-2 |
| R-STAFF-ADD-2 | 추가하면 계정(credentials)을 만들고 12자 임시 비밀번호(`generateTempPassword`)를 **응답에 한 번만** 돌려준다. DB에는 해시만, 로그에는 남기지 않는다. `must_change_password = true` | 1-3 §5, R-BOOT-2 |
| R-STAFF-ADD-3 | 새 간호사의 `seniority_rank` = 현재 최대 + 1(표 맨 아래) | Q1 |
| R-STAFF-ADD-4 | 초기 원장(`initial_input`, 0은 생략): 연차·잔여 N·이월 오프. 자동 부여(`year_grant`, ref_year = 올해): 특휴 `specialLeaveDays(employedDaysInYear(올해, 입사일 또는 오늘, null))`, 검진 0.5, 병가 60, 개원오프(올해 개원기념일에 재직하면 1) | Q2, 1-2 §4 |
| R-STAFF-ADD-5 | 신규 체크 시 트레이닝을 만든다: 시작 = 입사일(필수), 끝 = `defaultTrainingEnd`, 3인 배정 마지막 날 = 시작 + 7 × `tripleWeeks` − 1(기본값은 종류별 규칙 수치). 프리셉터는 활성 교대 근무자이고 본인이 아니어야 한다 | 2-2 Q5, 응급실 §6 |
| R-STAFF-EDIT-1 | 수정 가능: 성명·입사일·K-tass·연차 구분·노조·근무 방식·권한·표 순서·트레이닝(프리셉터·3인 기간·종료). 표 순서를 바꾸면 사이 사람들의 순서를 한 칸씩 민다 | Q1 |
| R-STAFF-EDIT-2 | 트레이닝 해제 = 진행 중 트레이닝의 끝을 어제로 당긴다(이력 보존). 오늘 이후 시작 예정이면 삭제 | 1-2 §2 Training 이력 |
| R-STAFF-DEL-1 | 제거 = `active = false`, `deactivated_at = now`, 그 사람의 세션 전부 삭제. 과거 근무표·원장은 보존. 확인 모달 필수 | 1-2 §2, R-AUTH-14 |
| R-STAFF-DEL-2 | 자기 자신과 마지막 활성 관리자는 제거할 수 없다 | 운영 안전 |
| R-STAFF-PW-1 | 비밀번호 재발급 = 새 임시 비밀번호, `must_change_password = true`, 실패 횟수·잠금 초기화, 세션 전부 삭제. 새 비밀번호는 한 번만 보여 준다 | 1-1 Q8 |
| R-STAFF-BAL-1 | 잔여치 조정 = 입력한 새 값 − 원장 현재 합계를 `admin_adjust`로 넣는다(메모 필수, 차이 0이면 넣지 않음). 화면의 현재값은 원장 합계(마감 안 된 달 사용분 제외)라고 안내한다 | Q2, 1-2 §2 원장 |

### 1.2 규칙 (S11)

| ID | 규칙 | 근거 |
|---|---|---|
| R-RULE-EDIT-1 | 수치는 `RULE_PARAM_LIMITS` 범위와 상호 제약(목표 ≤ 상한, K-tass ≤ 최소 인원, 마감 < 협의 시작 ≤ 끝, 전담 31일 상한 ≥ 전담 상한, 전담 최대 ≥ 최소)을 지켜야 저장된다 | 핸드오프 S11 "범위 검증" |
| R-RULE-EDIT-2 | 금지 패턴은 `normalizePattern` 후 `PATTERN_REGEX`를 만족해야 하고 중복은 하나로 합친다 | 2-1 스키마 |
| R-RULE-SAVE-1 | 저장 = 새 `rule_versions`(version + 1, changedBy, diff = 바뀐 항목 `{ key, before, after }`). 바뀐 것이 없으면 저장하지 않는다. 이전 버전은 수정하지 않는다 | 1-2 §2·§6-5 |
| R-RULE-SAVE-2 | `baseVersion`이 현재 최신이 아니면 거부("다른 관리자가 먼저 저장했습니다. 새로고침 후 다시 저장해 주세요.") | 동시 편집 |
| R-RULE-APPLY-1 | 헤더 문구 "다음 듀티 생성({M}월)부터 적용", M = 생성 중·확정·마감 계획이 있는 가장 늦은 달 + 1(없으면 오늘의 다음 달) | 핸드오프 S11, 1-2 §2 |
| R-RULE-APPLY-2 | 운영 수치(마감일·협의 기간)는 이후 새로 만드는 달 계획의 기본값이다. 이미 있는 달 계획의 날짜는 바꾸지 않는다 | 1-2 §2 MonthPlan |
| R-RULE-HIST-1 | 변경 이력: 버전 내림차순, `MM/DD {이름} · {라벨} {before} → {after}`(항목마다 한 줄), v1은 "초기 설정" | 핸드오프 S11 |

### 1.3 공휴일

| ID | 규칙 | 근거 |
|---|---|---|
| R-HOL-API-1 | 가져오기 = `getRestDeInfo(solYear, numOfRows=100, _type=json)`에서 `isHoliday = 'Y'`만. 분류: 이름에 "대체" → substitute, "선거" → election, "노동절"·"근로자" → labor_day, 그 외 public. `source = 'api'` | Q3 |
| R-HOL-API-2 | upsert: 같은 날짜가 없으면 추가, `seed`·`api` 항목은 이름·분류를 API 값으로 갱신, `admin` 항목은 건드리지 않는다. API에 없는 기존 항목은 지우지 않는다. 결과 "추가 n · 갱신 n · 유지 n" | Q3 |
| R-HOL-API-3 | `HOLIDAY_API_KEY`가 없으면 버튼 대신 안내("공공데이터포털 인증키를 .env에 설정하면 가져올 수 있습니다"). 타임아웃 5초, 오류면 아무것도 쓰지 않고 오류 문구 | Q3 |
| R-HOL-EDIT-1 | 관리자 추가: 병원 지정일·노사 협의일·개원기념일(그 외 분류도 허용). 날짜 유일. 개원기념일은 연도당 1개 | 1-2 §2 Holiday |
| R-HOL-EDIT-2 | 삭제는 어느 항목이나 가능(확인). 이미 마감된 달의 정산 스냅샷은 바뀌지 않는다는 안내를 보여 준다 | 1-2 §4 |
| R-HOL-FOUND-1 | 개원기념일을 추가·삭제하면 그해 개원오프 부여를 재계산: 사용자마다 목표(그날 재직 = 1, 아니면 0) − 현재 그해 `founding_off` `year_grant` 합을 `year_grant`로 넣는다 | 1-2 §4 개원오프 |

### 1.4 연초 처리

| ID | 규칙 | 근거 |
|---|---|---|
| R-YEAR-1 | `ensureYearStart(today)`는 인증된 요청마다 호출된다. 올해 `year_reset`(ref_year = 올해) 항목이 하나라도 있으면 아무것도 하지 않는다 | Q4 |
| R-YEAR-2 | 전년 12월 계획이 `CONFIRMED`(미마감)이면 미룬다(12월 사용분이 아직 원장에 없음). 12월 계획이 없거나 생성 중·마감이면 실행 | Q4, 2-3 원장 |
| R-YEAR-3 | 활성 사용자마다: 연차·특휴·개원오프·검진·병가를 `year_reset`(−현재 합)으로 0으로 만든 뒤 `year_grant`: 특휴 `specialLeaveDays(employedDaysInYear(올해, 입사일, null))`, 검진 0.5, 병가 60, 개원오프는 R-HOL-FOUND-1. 연차는 0으로 두고 관리자가 잔여치 조정으로 입력(원문 §11-1 "1월 1일마다 리셋") | 1-2 §4 |
| R-YEAR-4 | 누적 OFF·잔여 N은 건드리지 않는다(연말 정산 없이 이월) | 원문 §14·§15 |
| R-YEAR-5 | 한 트랜잭션 + `pg_advisory_xact_lock`으로 동시 요청에서도 한 번만 실행 | 멱등 |
| R-YEAR-7 | 원장 항목이 모두 올해(서울) 생성됐으면 시스템 첫해로 보고 처리하지 않는다(초기 입력이 이미 올해 값) | 구현 중 추가 |
| R-YEAR-6 | 미뤄진 동안 S10 상단에 안내: "{전년} 12월을 마감하면 {올해}년 잔여치가 자동으로 시작됩니다" | Q4 |

## 2. 검증 메시지

| 입력 | 문구 |
|---|---|
| 사번 없음 | "사번을 입력해 주세요." |
| 사번 중복 | "이미 등록된 사번입니다." |
| 성명 없음 | "성명을 입력해 주세요." |
| 신규인데 입사일 없음 | "신규 간호사는 입사일(트레이닝 시작일)이 필요합니다." |
| 프리셉터 없음·본인 | "프리셉터를 선택해 주세요." |
| 규칙 범위 | "{라벨}은 {min}~{max}{단위} 사이여야 합니다." |
| 상호 제약 | "월 나이트 목표는 상한 이하여야 합니다." 등 항목별 |
| 금지 패턴 | "D·E·N·S·OFF를 '-'로 두 개 이상 이어 주세요. 예: E-D" |
| 개원기념일 중복 | "{연도}년 개원기념일이 이미 있습니다." |

## 4. 불변식

- INV1: `rule_versions`, `balance_entries`는 추가만 한다.
- INV2: 임시 비밀번호 평문은 DB·로그에 없다.
- INV3: 연초 처리 뒤 활성 사용자의 특휴·검진·병가 합 = 그해 부여량, 연차 = 0.
- INV4: 비활성 사용자는 세션이 없다.

## 5. 엣지케이스

| 케이스 | 기대 동작 |
|---|---|
| 입사일이 없는 기존 간호사 | 특휴는 1년 재직으로 계산(5일) |
| 연중 입사 | 특휴 = 입사일~12/31 일수 산식 |
| 프리셉터를 제거하려 함 | 허용하되 경고 "진행 중 트레이닝의 프리셉터입니다. 트레이닝을 먼저 수정해 주세요."로 막는다 |
| 공휴일 API가 같은 날 두 이름(예: 설날 연휴 겹침) | 첫 항목만 |
| 두 관리자가 동시에 규칙 저장 | 뒤 저장은 R-RULE-SAVE-2로 거부 |
