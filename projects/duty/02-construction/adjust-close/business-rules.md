# business-rules — 2-7 근무 조정·월 마감

## §1. 조정 (R-ADJ)

| ID | 규칙 |
|---|---|
| R-ADJ-1 | 칸 편집·저장·협의 기간 변경·마감은 관리자만. 액션 첫 await는 `adminOnly()`(정적 가드 테스트). |
| R-ADJ-2 | 편집 가능한 달 = `CONFIRMED`. `CLOSED`는 읽기 전용("마감한 달입니다 · 마감 취소 후 수정"), `DRAFTING`은 "생성안 확인 중 → 듀티 생성", 계획·칸이 없으면 "듀티 미생성 → 듀티 생성으로". |
| R-ADJ-3 | 지난 날짜도 고칠 수 있다(당일 결원 교체 기록, 1-2 §3). 재직일이 아닌 칸은 만들지 않는다. |
| R-ADJ-4 | 즉시 검사: 편집안을 적용한 격자를 2-2 검사기로 검사하고, 적용 전에 없던 위반(키: ruleId·날짜·사람·듀티·data)만 보여 준다. 필수(hard)는 적용 차단, 권고(soft)는 경고 후 적용. |
| R-ADJ-5 | 예외 허용(Q2): 필수 위반이 있으면 「적용」은 비활성, 「그래도 적용」은 사유(1~200자) 입력 뒤 활성. 사유는 그 편집의 `override`로 저장된다. |
| R-ADJ-6 | 저장 시 서버가 다시 검사한다. 새 필수 위반 v마다 "가려 주는" 예외 편집 e가 있어야 한다: `e.date ∈ v.dates` 이고 (v가 H-STAFF·H-KTASS이거나 `e.userId ∈ v.userIds`). 없으면 저장 전체를 거부하고 위반 문구를 돌려준다. |
| R-ADJ-7 | 동시 수정: 편집마다 `before`가 현재 DB 칸과 다르면 저장 전체를 거부("다른 곳에서 먼저 바뀐 칸이 있습니다: 정하늘 10/13")하고 화면을 새로 불러오게 한다. |
| R-ADJ-8 | 저장 = 한 트랜잭션: 칸 갱신(`source='admin'`), 편집마다 `cell_edit_logs`(reason `manual`, 예외면 `note`=사유). 저장 즉시 간호사 근무표에 보인다("재배포"). |
| R-ADJ-9 | 맞바꾸기: 같은 날 두 사람의 칸 코드를 서로 바꾼다(편집 2개, kind `swap`). 휴가 칸은 대상이 아니다. |
| R-ADJ-10 | 대체 후보(1j·4a): 그날 쉬는(OFF regular) 교대 근무자, 재직 중, 휴가 칸 아님. 정렬 = (K-tass가 모자란 듀티면 K-tass 먼저) → 표 순서. 후보마다 "그 사람을 그 듀티로 바꿨을 때 새 필수 위반"을 미리 계산해 있으면 흐리게 + 이유. |
| R-ADJ-11 | 협의 기간 변경: `requestDeadline < start ≤ end ≤ 대상 월 말일`, 즉시 저장(일괄 저장과 별개). 2-8 교환 요청의 만료 기준이 된다. |
| R-ADJ-12 | 출처 표시: 관리자 편집 칸 = 파란 인셋 2px(신청 반영보다 우선). 간호사가 신청해서 반영된 칸은 OFF·D·E·N 모두 빨간 인셋 1.5px(2-3 R-VIEW-6 그대로). |

## §2. 확정된 달 휴가 (R-LEAVE-C)

| ID | 규칙 |
|---|---|
| R-LEAVE-C1 | 4a 확정된 달 카드의 「승인 · 대체 지정」 = 승인(2-5 그대로, 칸 즉시 휴가) 뒤 `/adjust?ym=…&focus=날짜&shift=부족 듀티`로 이동해 그 날짜의 대체 지정 팝오버를 연다. 인원 영향이 없으면 이동하지 않는다. |
| R-LEAVE-C2 | 승인 휴가 취소(확정·미마감 달, 관리자): S9 휴가 칸 팝오버의 「휴가 취소」. 칸 복원은 domain-entities §3. 잔여치는 월 마감 정산에서 반영되므로 원장은 바꾸지 않는다. |
| R-LEAVE-C3 | 마감한 달의 휴가는 취소할 수 없다("마감 취소 후"). 신청 중인 달의 승인 휴가 취소는 2-5 규칙(칸 없음, 상태만). |

## §3. 월 마감 (R-CLOSE)

| ID | 규칙 |
|---|---|
| R-CLOSE-1 | 마감 가능: 상태 CONFIRMED, 오늘 > 대상 월 말일(`nextPlanStatus` CLOSE), 앞 달 계획이 CONFIRMED가 아님(없거나 CLOSED). 아니면 버튼 비활성 + 이유("11월이 끝난 뒤 마감할 수 있습니다", "10월을 먼저 마감하세요"). |
| R-CLOSE-2 | 미리보기: 칸이 있는 사람마다 `settleMonth`(월초 = 원장 + 앞선 확정 달 투영, 2-3). 확인 창 표: 성명 · 실제 OFF/기준 · 누적 OFF 전→후 · N · 슬리핑 · 잔여 N 전→후. |
| R-CLOSE-3 | 마감 = 한 트랜잭션: 계획 행 잠금 → 상태 재확인 → `month_settlements` 인당 1행 → 원장 `month_settlement` 항목(0 제외, R-SETTLE-5) → CLOSED·closedBy·closedAt. |
| R-CLOSE-4 | 마감 취소: 가장 최근에 마감한 달만(뒤 달이 CLOSED면 거부). 그 달 `month_settlement` 항목을 `reverseEntries`로 뒤집어 `settlement_reversed`로 넣고, 스냅샷을 지우고, CONFIRMED로. |
| R-CLOSE-5 | 12월 마감은 2-4 연초 처리(R-YEAR)의 선행 조건이다. 12월 마감 취소는 이미 연초 처리가 끝났으면 거부("연초 처리 뒤에는 12월 마감을 취소할 수 없습니다"). |

## §4. 안내 (R-NOTICE, Q3)

| ID | 규칙 |
|---|---|
| R-NOTICE-1 | 근무표(`/`) 상단 띠: 내 칸을 다른 사람(관리자, 2-8부터 교환 상대)이 바꾼 이력 중 마지막 확인 이후 것. 문구 "내 근무가 바뀌었습니다 · 10/13 (화) E → OFF · 한수정 10/12 14:05". |
| R-NOTICE-2 | 날짜를 누르면 그 달 근무표로 이동, 「확인」은 띠를 닫고 `changes_seen_at` 갱신. 남의 변경은 절대 싣지 않는다(DTO 테스트). |
| R-NOTICE-3 | 마감 취소·휴가 취소로 되돌린 칸도 안내에 나온다(before → after 그대로). |
