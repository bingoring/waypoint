# [Stage 2-11] 수간호사 S 근무·칸 출처 표시·최초 로그인(동의·초기 설정)

## 목적

운영 데이터를 가져오기 전에 사용자 피드백 6건을 반영한다(3-1 진행 중 발견, DECISIONS 2026-10-09).

1. 수간호사의 기본 근무를 D가 아니라 **S**로 한다. D는 본인 신청·조정·"정말 근무표가 안 나올 때"만.
2. 간호사 근무 조정(교환) 화면에 수간호사를 넣는다(S ↔ D).
3. 신청·조정으로 반영된 칸을 외곽선으로 구분한다(교환은 빨간 점선, 파랑은 관리자 개입만).
4. 외곽선이 있는 칸에 마우스를 올리면 출처·특이사항을 보여 준다.
5. 최초 로그인 때 본인 정보(입사일·K-tass·연차 구분·근무 방식·노조·연차·잔여 N·이월 오프·신규/프리셉터·기간)를 확인·입력하고, 관리자가 수정한다. **2-10 Q1 「S2 만들지 않음」을 뒤집는다.**
6. 최초 로그인 때 개인정보 수집·이용 동의를 받고, 동의한 사용자만 메인으로 보낸다.

## 입력 (Inputs)

- 사용자 요청·답변(2026-10-09): 수간호사 D 조건, 미리 채우고 본인 확인·수정, 교환 = 빨간 점선, 동의서 초안 작성 후 병원 검토
- [`../inputs/requirements_v3.md`](../inputs/requirements_v3.md) 근무일정표 지침 §10·11(본인 입력), 응급실 지침 §5(신청 빨강·수간호사 파랑)·§6(신규 등록 시 기간)·§7(S 근무)
- [`../inputs/design-handoff_v5/README.md`](../inputs/design-handoff_v5/README.md) S1 동작, S2(1e) 초기 설정, S3 범례·외곽선
- 2-3 R-VIEW-6·7, 2-4 S10 간호사 관리, 2-5 신청, 2-6 솔버 `heads`, 2-8 교환 R-SWAP-1~13, 2-1 인증 가드

## AI 제안 (AI Proposal)

> ⚠️ 이 섹션은 AI가 작성합니다. 사람이 직접 수정하지 마세요.

Build Spec(standard): [`head-firstlogin/build-spec-index.md`](head-firstlogin/build-spec-index.md) (READY 후보)

요지:
- **수간호사 S:** 평일 기본 S, 빨간 날 OFF. 수간호사도 근무 신청 화면에서 OFF·D를 신청한다(빨간 외곽선). 솔버는 수간호사의 기본 S 칸을 **인원·K-tass 필수 조건을 달리 채울 수 없을 때만** D로 바꾼다(가장 큰 벌점). 이렇게 바뀐 칸은 툴팁에 "인원 부족 보충"으로 나온다.
- **교환에 수간호사:** 간호사가 교환 요청에 수간호사를 넣을 수 있고, 수간호사 칸은 S ↔ D만 바뀐다(S는 그날 교대 인원 계산에서 OFF와 같게 본다). 수간호사는 근무 조정(관리자) 화면의 "받은 교환 요청"에서 수락·거절한다.
- **외곽선:** 신청 반영 = 빨간 실선, 교환 반영 = 빨간 점선, 관리자 수정 = 파란 실선(우선). 휴가(연차·경조·병가·공가)도 신청으로 생긴 칸이므로 빨간 실선을 그린다(R-VIEW-6 변경).
- **툴팁:** 브라우저 기본 `title` 대신 즉시 뜨는 툴팁 카드. 출처별로 신청 내용·교환 상대·관리자 수정 시각·이전 근무를 보여 주고, 사유·메모는 본인과 관리자만 본다(R-1 ①).
- **최초 로그인:** 로그인 → 개인정보 동의 → 비밀번호 변경 → 초기 설정 → 근무표. 초기 설정은 가져온 값을 미리 채우고 본인이 확인·수정한다. 잔여치·자격 값을 바꾸면 원장(`self_input`)과 제출 기록에 남고, 간호사 관리에 "본인 입력 확인 필요"로 표시되어 관리자가 확인·되돌린다. 해마다 1월 첫 로그인에는 올해 연차만 다시 묻는다.
- **동의:** 필수 항목 동의와 민감정보(노조 가입 여부·병가 사유) 별도 동의 2개. 문구 버전이 바뀌면 다시 동의받는다. 문구는 초안이며 운영 전에 병원 개인정보 담당이 검토한다.
