### 1. 제품 컨텍스트 요약

**「벌써 근무표짤 때가 됐어?」** — 동부시립병원 응급실 병동 간호사 약 11명(수간호사 1 + 일반 10)이 쓰는
3교대(D/E/N) 근무표 웹. 데스크톱 우선(1280px), 업무용 존댓말 카피, hi-fi 디자인(픽셀 재현 대상).

**지금의 업무(종이):** 수간호사가 매월 종이 양식(성명 | 이월 off | 이월 N | 1~31일 | 누적 off | ⓝN |
특휴/개원 | 검진 | 보)에 손으로 근무를 짜고, 신청 반영 근무는 빨간 글씨, 수간호사 수정은 파란 글씨로 표시한다.
이 웹은 그 양식을 격자 UI로 옮기고, **신청 수집 → 규칙 기반 자동 생성 → 수동 조정 → 확정·공개 → 월 정산**을
시스템화한다.

**월간 루프 (한 달 주기):**
1. **1일~15일 · 신청:** 간호사가 다음 달 격자 위에서 날짜별로 가능한 근무(OFF·D·E·N 복수 선택 = or 조건),
   연차, 교육을 신청하고 코멘트(수간호사만 열람)를 단다. 서로의 신청은 격자에서 보인다.
2. **마감 후 · 생성:** 수간호사가 규칙(하드 제약 + 가중치 소프트 제약)으로 듀티를 자동 생성하고,
   마음에 들 때까지 리롤한다(n번째 안 이력 보관). 확정하면 간호사에게 공개된다.
3. **16~20일 · 협의 수정:** 간호사끼리 협의한 교환을 반영한다. 수간호사는 셀 단위로 조정하며 시스템이
   규칙 위반·인원 미달을 즉시 검사한다.
4. **월 마감 · 정산:** 누적 OFF(±)와 잔여 나이트·슬리핑오프를 이월한다(연말 리셋 없음, 연차만 1/1 리셋).

**권한:** 간호사(일반) / 관리자(수간호사). 같은 앱·같은 메뉴에 관리자 항목이 추가되는 구조.

### 3. 업무 규칙 분류 (→ 1-2 business-rules, 1-3 솔버 선택의 입력)

**A. 하드 제약 — 생성 시 절대 위반 불가, 조정 시 적용 차단**
- 교대 사이 최소 휴식 16h (D 07:00–15:30 · E 14:30–23:00 · N 22:30–07:30 · S 09:00–18:00에서 계산)
- 금지 패턴 E-D · N-E · N-off-D · E-S (관리자가 추가/삭제 가능 → 패턴은 데이터)
- 월 나이트 ≤ 7, 연속 나이트 ≤ 3
- 듀티(D/E/N)당 최소 2명, 그중 K-tass 권한자 ≥ 1
- 신규 간호사: 트레이닝 기간 프리셉터와 동일 근무, 첫 3주는 해당 듀티 인원을 3인으로 계산
- 최대 연속 오프 10일 (OFF·연차·휴가 합산)
- 주 5일 근무 (※ 하드/소프트 경계는 질문 Q4)
- 확정된 연차·휴가·교육(S/보수·노조 교육 = OFF)은 고정 셀

**B. 소프트 제약 — 가중치로 최대한 반영, 미충족은 "권고 미충족"으로 보고**
- 근무 신청 반영 (복수 옵션이면 그중 하나)
- N 후 OFF 2개 (불가피 시 N-OFF-E 허용)
- 월 나이트 6 이하 목표
- 월 1회 주말 이틀(토·일) 통 OFF, 전달 미배정자는 최우선
- 저연차만으로 한 듀티 구성 금지
- 특정 근무자 반복 겹침 최소화 (트레이닝 페어 제외)
- D→E→N 순환 편성
- 누적 OFF가 낮을수록·잔여 N이 높을수록 OFF 배정 우선 (S6 안내 문구)

**C. 운영 파라미터** — 신청 마감(기본 15일), 협의 수정 기간(기본 16–20일, 관리자가 월별로 수정), 야간 전담
운영 토글(꺼짐, 켜면 월 15일/31일 달 16일 상한).

**D. 정산·휴가 규칙** — 월 기준 OFF(주휴+공휴일) 대비 실제 OFF 차이를 누적 OFF에 ± 반영, 나이트 누적 6개마다
슬리핑오프 1, 특별휴가 = round(5×근무일수/365), 검진 반차 0.5, 경조휴가 11종 일수표, 병가 연 60일, 공가 4종.

> 모든 수치는 **규칙 설정(S11) 값에서 파생**하며 하드코딩하지 않는다(핸드오프 S7·S11 요구). 규칙은 병동별
> 버전 관리 대상이다.

### 5. 주요 결정 · 리스크

1. **자동 생성 솔버가 이 제품의 핵심 난제다.** 11명 × 31일 × 5코드의 조합 탐색 + 하드 제약 10여 개 +
   가중 소프트 제약 8개. 규모는 작지만 제약 밀도가 높아서, 단순 그리디로는 하드 제약을 만족하지 못하는 달이
   생긴다. 후보는 ① CP-SAT(OR-Tools, Python 서비스 분리) ② TS 내 휴리스틱 + 지역 탐색(시뮬레이티드 어닐링)
   ③ 정수계획 솔버의 WASM/JS 포팅. **1-3의 ⚠️ 비가역 결정**으로 다룬다. 리롤 = 시드 변경이므로 결정적 재현
   (seed → 동일 결과)이 필요하다.
2. **규칙 검사 엔진을 생성기와 공유해야 한다.** S8(생성 결과 검사), S9(셀 편집 시 즉시 검사), S5(휴가 승인 시
   인원 재검사)가 같은 규칙을 쓴다 → 규칙 검사는 **순수 함수 모듈**로 분리하고 클라이언트(즉시 피드백)와
   서버(최종 검증)에서 모두 실행하는 구성이 유력하다. 자동화 테스트의 최우선 대상이다.
3. **기술 스택:** 핸드오프 권장은 Next.js + TypeScript + Tailwind/CSS Modules + Postgres(Supabase 등).
   코드베이스가 없으므로 1-3에서 확정한다.
4. **개인정보·권한:** 사번·근무·휴가 사유·증빙 서류(경조/병가)는 민감 정보다. 코멘트는 **API 레벨에서**
   관리자에게만 응답해야 한다(일반 사용자에게는 존재 여부만). 증빙 파일 저장소 선택도 1-3 항목이다.
5. **공휴일 데이터:** 기준 OFF(주휴+공휴일)와 격자 음영이 공휴일 달력에 의존한다. 대체공휴일·병원 지정일까지
   포함해야 하므로 관리자 편집 가능한 `Holiday` 테이블 + 초기 시드(공공 API 또는 수기) 방식을 제안한다.
6. **인쇄:** S3 격자만 A4 가로로 출력해야 한다(종이 결재 관행 유지). 프린트 CSS로 해결 가능한 범위로 본다.

### 7. 질문 해소 (2026-09-26, 사용자 승인 시)

- **Q1~Q4, Q6~Q8:** 기본안대로 확정.
- **Q5:** 「보」 = 보수교육(오프라인, 연 1회). 「특휴/개원」 = 특별휴가 / 개원기념일 오프. "-"는 입사일이
  최근이라 개원오프 대상이 아니라는 뜻이다. 특휴 산식은 요구사항 원문 §6-7.
  노란 이름 표시는 요구사항 원문의 명단과 대조한 결과 **수간호사를 제외한 K-tass 권한자**(박서연·정하늘·
  오민지·윤채원·임소라·배지현)와 정확히 일치한다(AI 추론, 1-2에서 표시 여부를 다룸).
- **요구사항 원문에서 새로 확인한 사실:** 실제 사번은 5자리이고 앞자리 0이 있다(00101 등, 문자열로 저장).
  근무자는 고연차·중간연차·저연차로 구분되며 표 순서가 연차 순서다. 노조원 여부가 있다(노조교육 대상).
  수간호사는 교대하지 않고 빨간 날에만 쉰다. "듀티가 공평하게 돌아가야 하는 것이 1순위"(원문 §15).
  야간 전담은 연속 1~6개월로 제한한다.
