# [Stage 3-7] 의사 근무표 — 직군 추가 (응급실 의사 5명)

## 목적

같은 앱에 **의사 직군**을 추가한다. 의사는 간호사와 근무 코드·규칙·관리자·화면 형식이 모두 다르고, 두 직군은 서로의 **확정 근무표만** 읽기 전용으로 본다.

## 입력 (Inputs)

- 핸드오프 새 버전 `inputs/design_handoff_nurse_duty_scheduler/` — README 「의사 근무표 (turn-6, 6a·6b·6c)」, HTML 캔버스 turn-6(최신, 하위 턴과 충돌하면 turn-6 우선)
- 현재 코드(3-6까지): 직군 개념 없음, 사용자 = 간호사, 로그인 = 사번

## 핸드오프 요약 (의사)

- **권한:** 직군 `nurse` / `doctor`. 메뉴·근무 코드·규칙·관리자가 직군마다 따로. 의사 메뉴: 근무표 · 근무 신청 · 근무 조정 · 규칙 안내 → (관리자) 듀티 생성 · 의사 관리 · 규칙 설정 → 내 설정.
- **상호 공개:** 근무표 상단 「간호사 / 의사」 탭, 상대 직군은 확정 근무표만 읽기 전용.
- **로그인:** 의사는 사번 대신 **생년월일 6자리**를 로그인 ID로, 관리자가 나중에 「사번으로 변경」(ID만 바꾸고 기록 유지).
- **근무:** D 10:00–20:00 · N 20:00–익일 10:00 · O(휴무). 같은 날 D·N을 한 사람이 하면 **올데이**. 매일 D 1명·N 1명.
- **개수:** 30일 달 의사별 D 6·N 6. 31일 달은 2명이 하나씩 더(D +1 한 명, N +1 한 명), 대상은 달마다 순환(관리자 변경 가능).
- **없는 것:** 연차·휴가 메뉴, 연속 휴무 제한, 금지 패턴·16시간 휴식(N-O-D, 올데이-O-D 허용).
- **개인 조건(매달 자동 적용):** 한 달 올데이 개수 범위(없음/1~2/2~3/전부/직접) = 권고, 고정 조건(요일 × D|N|근무 × 필수|금지, on/off) = 필수.
- **일정:** 매월 20일 신청 마감, 25일까지 조정, 그 전에 확정되면 조기 배포.
- **화면:** S-D1 주 단위 달력 근무표(Day/Night 줄, 이름 칩, 올데이 배지, 다음 근무·의사별 집계), S-D2 월 달력 신청(팝오버 없이 우측 패널, D/N/O/올데이 복수 선택, 내 근무 조건 카드), S-D3 의사 관리 + 듀티 생성(리롤·확정·조기 배포). 의사 근무 조정은 간호사 S9(교환 요청 + 하단 도크) 패턴을 달력 레이아웃으로.

## AI 제안 (AI Proposal)

### 설계 방향

1. **직군은 사용자·계획·규칙에 붙는 축으로 둔다.** `users.role_group`('nurse'|'doctor'), `users.login_id`(로그인용, 간호사는 사번과 같음), `month_plans.role_group`, 의사 규칙은 간호사 규칙 버전과 **따로**(`doctor_rule_versions`). 세션·권한 검사는 「관리자 + 같은 직군」으로 바꾼다(간호사 관리자가 의사 근무표를 고치지 못하게).
2. **의사 근무는 하루 한 행**(`doctor_shifts`: date, day_user, night_user, source) — 달력 렌더·「매일 D1·N1」 검사·올데이 판정이 그대로 된다(핸드오프 제안과 같음). 간호사 칸 테이블·검사기와 섞지 않는다.
3. **의사 생성은 별도 작은 CP-SAT 모델**(같은 솔버 서비스에 `/solve/doctor`). 변수 = 날짜 × {D,N} × 의사, 제약 = 매일 D1·N1, 개수(6/6, 31일 달 +1 대상), 고정 조건(필수). 목표 = 올데이 범위 이탈·신청 미충족 최소 + 공평. 5명 × 31일이라 1초 안에 최적해가 나온다(간호사 모델의 시간 문제와 무관).
4. **검사기는 도메인에 의사용 순수 함수 하나**(`checkDoctorMonth`) — 생성 재검사·관리자 조정·교환 수락에 같이 쓴다.
5. **화면은 새로 만든다:** 의사 근무표(주 단위 달력), 의사 신청(월 달력 + 우측 패널), 의사 관리·듀티 생성. 근무표 「간호사 / 의사」 탭은 두 직군 모두에.
6. **로그인 ID = 생년월일**은 핸드오프대로 지원하되 보안을 보완한다: 생년월일은 추측이 쉬우므로 의사 계정도 임시 비밀번호 + 첫 로그인 변경(기존 흐름), 잠금 5회·IP 제한 유지. 공개 화면에 로그인 ID를 노출하지 않는다.

### 설계에서 바꾼 것 (AI 판단)

- **로그인 ID = `users.employee_no` 그대로.** 따로 `login_id`를 두지 않았다 — 간호사는 원래 사번이 로그인 ID이고, 의사는 처음에 생년월일 6자리를 넣고 「사번으로 변경」이 그 값만 바꾼다(근무·신청은 사용자 id에 붙어 그대로). 구분 표시용 `users.login_id_kind`(`birthdate`·`employee_no`)와 `users.role_group`(`nurse`·`doctor`)만 추가. 간호사 코드의 사용자 생성 경로를 건드리지 않으려는 것.
- **의사 계획·신청·생성안은 의사 전용 테이블.** 제안의 `month_plans.role_group` 대신 `doctor_month_plans`·`doctor_requests`·`doctor_candidates`(+`_shifts`)·`doctor_shifts`(하루 한 행)·`doctor_shift_logs`·`doctor_swap_requests`·`doctor_prefs`·`doctor_rule_versions`. 간호사 쿼리가 의사 행을 볼 일이 없게 했다. 간호사 쪽 변경은 사용자 목록 쿼리의 직군 필터(근무표·생성 입력·신청·연초 처리·개원 OFF·간호사 관리·순서·프리셉터 등)와 직군 가드뿐. 마이그레이션은 0012 하나(drizzle-kit 생성 그대로, 손댄 줄 없음).
- **확정 = 공개.** 「이 안으로 확정」과 「지금 배포」(조정 마감 전 = 조기 배포)는 같은 동작. 확정된 달만 의사·간호사가 서로 본다.
- **±1 대상 순환:** 날짜 수 − 인원 × 기준 개수만큼 대상이 필요(31일 = D 1·N 1, 2월 = −1). 기본은 직전 대상 다음 사람부터 표 순서로(10월 백승우·진하람 → 12월 허재민·고은서), 생성 화면에서 바꾼다. 인원이 바뀌어 맞출 수 없으면 규칙 설정에서 개수를 바꾸라고 막는다.
- **교환 = 두 칩(날짜·D|N)의 주인 맞바꾸기.** 같은 날 D↔N, 다른 날끼리 모두. 의사 규칙만 검사 — 조정에서 필수는 매일 D1·N1·고정 조건, 개수는 권고(교환하면 개수가 바뀌므로). 관리자는 칸 재배정·두 칩 맞바꾸기를 바로 적용(필수 위반이면 사유). 칩 주인이 바뀌면 대기 요청은 무효, 날짜가 지나면 만료.
- **권고 벌점(솔버):** 신청 미반영 > 신청 미반영 최대(공평) > Night 다음 날 Day > 올데이 범위 이탈 > 시드 동점 깨기. Night 다음 날 Day(24시간 넘게 연속)는 규칙에 없지만 10월 실제 근무표에 0번이라 권고로 피한다.
- **고정 조건 충돌 예외:** 신청을 저장할 때 고정 조건과 부딪히면 묻고, 확인하면 그 날만 조건 예외(`doctor_requests.fixed_exception`)로 저장 → 생성 입력에서 그 날 조건이 빠진다. 복수 신청(or)은 하나라도 조건을 지키면 충돌이 아니다.
- **테스트 기간 공개 스위치:** 의사 규칙 설정 「간호사에게 의사 근무표 공개」(규칙 값 `published`, 운영 기본 끔). 끄면 간호사 근무표의 「의사」 탭에 「공개 전(테스트 기간)」만 보이고, 의사 화면에는 「테스트 기간 · 간호사에게 공개 전」 배지. 12월분 실제 사용 때 관리자가 켠다. 11월 실제 근무표는 `db:import-doctor-schedule --replace`로 덮어쓴다.
- **의사는 초기 설정(연차·KTAS) 단계가 없다.** 동의 → 비밀번호 변경까지만. 내 설정은 비밀번호만.

### 화면

- `/doctor` S-D1 주 단위 달력(올데이 배지·오늘 열·강조 칩·다음 근무 4개·의사별 집계 ±1·인쇄) + 「간호사 / 의사」 탭. 간호사 홈 `/`에도 탭(의사 확정본 읽기 전용). 다른 직군 화면은 자기 홈으로 보낸다.
- `/doctor/requests` S-D2 월 달력 + 우측 패널(D/N/O/올데이 복수, 코멘트는 본인·관리자만), 내 근무 조건(올데이 프리셋·직접 입력·고정 조건 on/off·추가), 다른 의사 신청·고정 조건 표시. 마감(전월 20일) 뒤에는 관리자만.
- `/doctor/admin/generate` S-D3 생성·리롤·±1 대상·검사 결과·조기 배포. `/doctor/admin/staff` 의사 관리(추가·사번으로 변경·관리자 지정·임시 비밀번호·제거). `/doctor/admin/rules` 규칙 설정(D·N 개수, 신청·조정 마감일). `/doctor/rules` 규칙 안내.
