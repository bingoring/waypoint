# [Stage 3-7] 의사 근무표 — 직군 추가 (응급실 의사 5명)

## 목적

같은 앱에 **의사 직군**을 추가한다. 의사는 간호사와 근무 코드·규칙·관리자·화면 형식이 모두 다르고, 두 직군은 서로의 **확정 근무표만** 읽기 전용으로 본다.

## 입력 (Inputs)

- 핸드오프 새 버전 `inputs/design_handoff_nurse_duty_scheduler/` — README 「의사 근무표 (turn-6, 6a·6b·6c)」, HTML 캔버스 turn-6(최신, 하위 턴과 충돌하면 turn-6 우선)
- 현재 코드(3-6까지): 직군 개념 없음, 사용자 = 간호사, 로그인 = 사번

## 핸드오프 요약 (의사)

- **권한:** 직군 `nurse` / `doctor`. 메뉴·근무 코드·규칙·관리자가 직군마다 따로. 의사 메뉴: 근무표 · 근무 신청 · 근무 조정 · 규칙 안내 → (관리자) 듀티 생성 · 의사 관리 · 규칙 설정 → 내 설정.
- **상호 공개:** 근무표 상단 「간호사 / 의사」 탭, 상대 직군은 확정 근무표만 읽기 전용.
- **로그인:** 의사는 사번 대신 **생년월일 6자리**를 로그인 ID로, 관리자가 나중에 「사번으로 변경」(ID만 바꾸고 기록 유지).
- **근무:** D 10:00–20:00 · N 20:00–익일 10:00 · O(휴무). 같은 날 D·N을 한 사람이 하면 **올데이**. 매일 D 1명·N 1명.
- **개수:** 30일 달 의사별 D 6·N 6. 31일 달은 2명이 하나씩 더(D +1 한 명, N +1 한 명), 대상은 달마다 순환(관리자 변경 가능).
- **없는 것:** 연차·휴가 메뉴, 연속 휴무 제한, 금지 패턴·16시간 휴식(N-O-D, 올데이-O-D 허용).
- **개인 조건(매달 자동 적용):** 한 달 올데이 개수 범위(없음/1~2/2~3/전부/직접) = 권고, 고정 조건(요일 × D|N|근무 × 필수|금지, on/off) = 필수.
- **일정:** 매월 20일 신청 마감, 25일까지 조정, 그 전에 확정되면 조기 배포.
- **화면:** S-D1 주 단위 달력 근무표(Day/Night 줄, 이름 칩, 올데이 배지, 다음 근무·의사별 집계), S-D2 월 달력 신청(팝오버 없이 우측 패널, D/N/O/올데이 복수 선택, 내 근무 조건 카드), S-D3 의사 관리 + 듀티 생성(리롤·확정·조기 배포). 의사 근무 조정은 간호사 S9(교환 요청 + 하단 도크) 패턴을 달력 레이아웃으로.

## AI 제안 (AI Proposal)

### 설계 방향

1. **직군은 사용자·계획·규칙에 붙는 축으로 둔다.** `users.role_group`('nurse'|'doctor'), `users.login_id`(로그인용, 간호사는 사번과 같음), `month_plans.role_group`, 의사 규칙은 간호사 규칙 버전과 **따로**(`doctor_rule_versions`). 세션·권한 검사는 「관리자 + 같은 직군」으로 바꾼다(간호사 관리자가 의사 근무표를 고치지 못하게).
2. **의사 근무는 하루 한 행**(`doctor_shifts`: date, day_user, night_user, source) — 달력 렌더·「매일 D1·N1」 검사·올데이 판정이 그대로 된다(핸드오프 제안과 같음). 간호사 칸 테이블·검사기와 섞지 않는다.
3. **의사 생성은 별도 작은 CP-SAT 모델**(같은 솔버 서비스에 `/solve/doctor`). 변수 = 날짜 × {D,N} × 의사, 제약 = 매일 D1·N1, 개수(6/6, 31일 달 +1 대상), 고정 조건(필수). 목표 = 올데이 범위 이탈·신청 미충족 최소 + 공평. 5명 × 31일이라 1초 안에 최적해가 나온다(간호사 모델의 시간 문제와 무관).
4. **검사기는 도메인에 의사용 순수 함수 하나**(`checkDoctorMonth`) — 생성 재검사·관리자 조정·교환 수락에 같이 쓴다.
5. **화면은 새로 만든다:** 의사 근무표(주 단위 달력), 의사 신청(월 달력 + 우측 패널), 의사 관리·듀티 생성. 근무표 「간호사 / 의사」 탭은 두 직군 모두에.
6. **로그인 ID = 생년월일**은 핸드오프대로 지원하되 보안을 보완한다: 생년월일은 추측이 쉬우므로 의사 계정도 임시 비밀번호 + 첫 로그인 변경(기존 흐름), 잠금 5회·IP 제한 유지. 공개 화면에 로그인 ID를 노출하지 않는다.

### 단계 나누기 (각각 Build Spec → 구현 → 승인)

| 단계 | 내용 |
|------|------|
| 3-7a 기반 | 직군·로그인 ID 마이그레이션, 의사 계정(관리자 추가·임시 비밀번호, 로컬 CSV 가져오기), 직군별 메뉴·권한, 「사번으로 변경」, 의사 규칙 버전·규칙 설정·규칙 안내 |
| 3-7b 근무표 | `doctor_shifts`, 의사 근무표 달력(S-D1)·집계·다음 근무, 「간호사 / 의사」 탭(확정만 상호 공개), 인쇄 |
| 3-7c 신청·조건 | 의사 신청(S-D2, D/N/O/올데이 복수, 코멘트), 내 근무 조건(올데이 범위·고정 조건), 고정 조건과 충돌 시 예외 확인 |
| 3-7d 생성 | 의사 CP-SAT 모델·검사기, 듀티 생성·리롤·확정·조기 배포(S-D3), 31일 달 +1 순환 |
| 3-7e 조정 | 의사 근무 조정(관리자 칸 편집, 의사 간 교환 요청) — 간호사 S9 패턴 |

### 확인이 필요한 질문

- **Q1 운영 시작:** 의사 근무표를 언제부터 이 앱으로 짜는가(예: 12월분)? 그 전 달 확정본은 직접 입력·가져오기가 필요한가? *(권장: 첫 달 전 달 확정본은 관리자가 달력에서 직접 입력)*
- **Q2 의사 휴무 신청:** 연차 메뉴가 없으면 휴가·학회 등은 「O」 신청 + 코멘트로 충분한가? *(권장: 그렇게)*
- **Q3 공휴일:** 의사 근무에서 공휴일은 표시만(색)이고 규칙 차이는 없는가? *(권장: 표시만)*
- **Q4 조정 범위:** 3-7e(의사 교환 요청)까지 첫 운영에 필요한가, 3-7d까지 먼저 운영하고 나중에 붙여도 되는가? *(권장: a~d 먼저, e는 운영 피드백 뒤)*
- **Q5 개인정보:** (결정됨 2026-10-18) 저장소엔 가명본, 실명·생년월일 ID는 로컬 CSV → 운영 DB 가져오기(3-7a에 의사 명단 가져오기 `db:import-doctors` 추가). 시드는 가명.

### 위험·영향

- 권한 모델 변경(관리자 → 직군별 관리자)은 기존 간호사 기능 전체에 닿는다. 3-7a에서 관리자 액션 가드 테스트를 직군까지 넓힌다.
- 간호사 화면에 탭이 생기는 것 외에 간호사 기능은 바뀌지 않는다.
