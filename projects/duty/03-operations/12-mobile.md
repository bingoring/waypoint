# [Stage 3-12] 모바일 대응 — 아래 탭·내 근무 달력·날짜별 명단·신청/교환 시트·관리자 승인과 급한 변경·홈 화면 추가

## 요구사항 (사용자 2026-10-29)

- 휴대폰에서도 쓸 수 있게. 주로 **본인의 오늘 근무**를 확인한다. 앱 배포는 나중으로 미루되 「홈 화면에 추가」는 넣는다.
- 근무 신청·교환 요청도 휴대폰에서. **데스크톱에서 되는 일은 모바일에서도 돼야 한다**(교환의 여러 명 재배정 포함).
- 내 근무가 먼저 보이고 동료 근무는 필요할 때 본다. 모바일 UX에 맞게 새로 설계한다.
- 그날 누가 무엇을 신청했는지도 보고 싶다.
- 관리자 화면은 휴가 승인과 급한 근무 변경 정도만 휴대폰에서. 데스크톱 화면을 확대·축소해서 쓰게 하지 말고, 정보가 많은 화면은 「PC에서 이용해 주세요」로 안내한다. 새 근무표 생성은 데스크톱에서.

## AI 해석 (구현 계획)

### 1. 화면 전환 방식

- 주소는 데스크톱과 같다. 같은 서버 컴포넌트가 같은 데이터를 읽고, 화면 트리만 고른다.
- **단순한 화면은 한 트리 반응형**(Tailwind `md:` = 768px): 로그인·동의·첫 로그인·비밀번호, 내 설정, 규칙 안내, 동료 현황, 의사 규칙 안내·설정. 데스크톱 모양은 `md:` 클래스로 지금과 같게 유지한다.
- **복잡한 화면은 서버가 트리를 하나만 렌더링한다:** 근무표, 근무 신청, 근무 조정(교환·급한 변경), 관리자 PC 전용 화면. 두 트리를 모두 그리고 CSS로 숨기면 DOM이 두 배가 되어 기존 E2E의 텍스트 locator가 숨은 쪽까지 잡고(strict mode 위반), 휴대폰이 무거운 데스크톱 격자까지 hydrate한다.
  - `proxy.ts`가 기기를 판정해 `x-device: mobile|desktop` 헤더를 넣는다. 판정 순서는 뷰포트 쿠키(`duty_vp`) → `user-agent`(Next `userAgent`, 휴대폰 = mobile)다. 페이지·레이아웃은 `headers()`로 읽는다(모든 페이지가 이미 동적).
  - 클라이언트가 마운트 뒤 `matchMedia('(max-width: 767px)')`로 확인하고, 서버 판정과 다르면 `duty_vp` 쿠키를 쓰고 `router.refresh()`한다(데스크톱 창을 좁히면 모바일, 태블릿 가로는 데스크톱). 고르지 않은 서버 트리는 RSC 페이로드에 없으므로 클라이언트 혼자 바꾸지 않는다.
  - 트레이드오프: UA 추측이 틀린 기기는 처음 한 번 화면이 다시 그려진다. 대신 기존 데스크톱 E2E는 수정 없이 통과해야 한다(1차 PR의 판정 기준, 기존 테스트는 데스크톱 UA·폭 1280 이상).
- 셸: `AppShell`과 `AuthFrame`의 `min-w-[1280px]`를 `md:` 이상에만 적용. 셸도 `x-device`로 사이드바와 모바일 셸 중 하나만 그린다(`navigation`이 둘이 되지 않게). 모바일 셸은 위쪽 제목 줄 + **아래 탭**(DOM에서 본문 뒤, 안전 영역 `env(safe-area-inset-bottom)`)이고 `SessionKeeper`를 포함한다.

### 2. 아래 탭

| 탭 | 간호사 | 의사 |
|---|---|---|
| 근무표 | `/` | `/doctor` |
| 신청 | `/requests` | `/doctor/requests` |
| 교환 | `/adjust` (모바일은 교환 화면) | `/doctor/adjust` (모바일은 교환 화면) |
| 관리 (관리자만, 교환 탭 대신) | `/manage` 새 화면 | `/doctor/manage` 새 화면 |
| 더보기 | `/more` 새 화면 | `/doctor/more` 새 화면 |

- 간호사 관리자(수간호사) 탭은 **근무표·신청·관리·더보기**다(교환 탭 없음, 데스크톱과 같음). 신청 탭은 날짜별로 누가 무엇을 신청했는지 보는 화면이고, 대신 신청은 PC에서 한다(사용자 답변 2026-10-29). 의사 관리자도 같다(데스크톱 `/doctor/adjust`에서 관리자는 직접 편집만 하고 교환 요청을 보내지 않는다).
- 배지: 교환 = 받은 교환 요청 수, 신청 = 받은 휴가 변경 요청 수(간호사), 관리 = 승인 대기 휴가 수(간호사).
- `/manage`·`/more`는 모바일용 모음 화면이다. 데스크톱 사이드바에는 넣지 않고, 데스크톱 폭으로 열면 같은 내용을 한 열로 보여 준다.
- 권한: 페이지마다 가드를 부른다. `/manage` = `requireAdmin`, `/doctor/manage` = `requireDoctorAdmin`(`page-guards.test.ts`에 의사 manage 규칙 추가), `/more` = `requireNurse`, `/doctor/more` = 의사 가드.
- 「관리」 배지용 승인 대기 휴가 수는 한 달 격자를 읽지 않는 count 쿼리로 따로 만든다.

### 3. 화면별

- **근무표(홈):**
  - 「오늘 내 근무」 카드: 오늘 근무와 시간, 내일 근무, 이번 달 OFF 수, 누적 OFF. 오늘은 서버의 서울 날짜(`requestToday`, E2E 가짜 날짜 포함)이고, 달력의 오늘 표시도 클라이언트 `Date`가 아닌 서버 값을 쓴다. 카드는 `?ym=`과 무관하게 오늘·내일 날짜로 따로 읽는다(월말이면 내일은 다음 달 근무표).
  - 내 근무 월 달력(‹ 달 ›). 날짜를 누르면 아래에 그날 같이 서는 사람. 근무 시간 안내(`ShiftTimesLegend`).
  - 「내 근무 / 전체」 전환. 전체 = 날짜 띠 + D·E·N·OFF(·S, 휴가) 묶음별 이름. 데이터는 기존 근무표 행에서 날짜 기준으로 다시 묶는다(읽기 DTO `dayRoster`).
  - 「전체」의 직군 전환: 간호사 홈은 의사표가 공개(`published`)됐을 때만 「의사」를 고를 수 있고, 의사 홈은 「간호사」를 늘 고를 수 있다. 의사 명단 묶기는 `calendar` 형태에서 따로 만든다.
  - 의사 홈: 같은 구조, 근무는 D·N·올데이.
- **신청:**
  - 위 카드: 마감일·남은 날, 내 신청 수·제출 상태, 「신청 제출」.
  - 달력: 내 신청(빨간 테두리, 관리자가 넣은 것은 파란 점), 날짜별 「쉼 n」(많으면 빨강).
  - 날짜를 누르면 시트: OFF/D/E/N 여러 개, S, 휴가 종류(연차·특휴·개원·병가·경조·공가·검진 오전/오후, 경조는 사유 선택), 메모, 저장·지우기. 아래에 **그날 신청한 동료와 내용**(메모·사유 제외). 편집 가능 범위(`editable`)와 받은 휴가 변경 요청(수락·거절)도 시트·카드로.
  - 서버 액션은 데스크톱과 같은 것을 쓴다.
  - 의사: 같은 달력 + 시트(D·N·올데이·OFF 신청, 철회, 내 근무 조건 보기).
- **교환:**
  - 받은 요청(수락·거절, 메시지), 보낸 요청(철회), 처리된 요청 접기. 협의 기간 안내.
  - 「＋ 교환 요청」 → 날짜 → 그날 근무별 동료 칩에서 **여러 명 선택** → 칩 두 개를 차례로 눌러 서로 맞바꾸는 방식으로 바뀐 뒤 상태를 만든다 → 기존 `checkInput` 규칙 검사 결과를 바로 표시 → 메시지와 함께 보내기.
  - 의사: 1:1 교환(데스크톱과 같은 범위).
- **관리(관리자):**
  - 간호사: 승인 대기 휴가 카드(인원 부족 경고, 대체 후보, 반려·승인), 처리 이력과 승인 취소. 확정된 달에 인원이 모자라면 「승인 · 대체 지정」 뒤 PC 격자(`/adjust`)가 아니라 근무표 「전체」에서 그 날짜·근무의 급한 변경 시트를 연다(`/?tab=all&date=…&shift=…`, `view`는 기존 의사·간호사 전환이 쓴다).
  - **급한 변경:** 근무표 탭 「전체」에서 관리자가 이름을 누르면 시트. 근무 칩(D/E/N/OFF/S), 바뀌는 인원과 규칙 결과(데스크톱 `Dock`과 같은 검사), 대체 후보를 함께 바꾸기, 휴가로 바꾸기, 사유, 「저장 · 바로 공개」. 저장은 기존 `saveEditsAction`.
  - **휴가로 바꾸기(모바일):** 부분 리롤 없이 그 칸을 휴가로 바꾸고, 인원이 모자라면 대체 후보를 함께 바꾸거나 사유를 적어 저장한다(`saveEditsAction`의 `leaves` + `override`). 신청 OFF 칸(`offLock`)은 D·E·N으로 못 바꾼다.
  - 시트 데이터는 홈에서 미리 읽지 않는다. 관리자가 시트를 열 때 관리자 전용 서버 액션이 그 달의 검사 입력과 대체 후보를 읽는다(`loadAdjustView`의 관리자 분기를 떼어 낸 로더). `Dock`의 대체 후보·해결 제안·검사 로직은 순수 함수로 꺼내 데스크톱과 같이 쓴다.
  - PC 안내 목록: 듀티 생성·생성안 검토, 근무 조정(전체 격자·부분 리롤), 규칙 설정, 간호사(의사) 관리. 이 주소들을 휴대폰 폭으로 열면 같은 안내 화면을 보여 준다.
  - 의사 관리자: 급한 변경만(휴가 없음).
- **더보기:** 간호사 = 내 정보, 휴가 잔여, 동료 현황, 규칙 안내, 내 설정, 로그아웃. 의사 = 내 정보, 규칙 안내, 내 설정, 로그아웃.
- **로그인·동의·첫 로그인·비밀번호:** 한 열. 로그인 화면 소개 영역(`LoginHero`)은 휴대폰에서 줄이거나 숨긴다.

### 4. PWA 「홈 화면에 추가」

- `app/manifest.ts`(이름, `display: standalone`, `start_url: /`, 테마색), 아이콘(192·512·maskable), `apple-touch-icon`. 루트 레이아웃에 `export const viewport`(`themeColor`, `viewportFit: 'cover'`)를 새로 둔다.
- `proxy.ts` matcher에서 manifest·아이콘 경로를 뺀다. 브라우저와 iOS는 이 파일들을 쿠키 없이 가져오므로, 빼지 않으면 로그인으로 302가 나서 홈 화면 추가가 깨진다.
- 서비스 워커·오프라인·푸시 알림은 **범위 밖**.
- standalone에는 브라우저 뒤로 가기가 없다. 시트 닫기, 달 이동, 하위 화면 뒤로 가기를 화면 안에 둔다.
- **로그인 유지:** iOS 홈 화면 앱은 Safari와 쿠키를 따로 쓴다. 홈 화면 앱에서 한 번 로그인하고 「로그인 유지」면 30일(사용 시 연장) 유지되는지 실기기로 확인한다(확인 과제).
