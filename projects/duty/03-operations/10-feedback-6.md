# [Stage 3-10] 운영 피드백 6 — 신청 권한 정리·휴가 합계·조정 사유·누적 OFF 휴가 제외·리롤에 수동 변경 유지·저장 전 비공개·권고 패턴·나이트 상하한·불가능 원인 찾기

## 요구사항 (사용자 2026-10-20, 간호사 쪽 13건)

1. 관리자 화면 근무 신청: 평간호사가 D·E·N을 신청한 칸은 관리자가 다른 근무를 누르지 못하게. (원문이 「but.」에서 끊김)
2. 평간호사 OFF 신청을 관리자가 지우지 못하게 했더니(3-9), 관리자가 넣은 신청도 지워지지 않는다.
3. 관리자가 넣은 신청은 근무 신청 화면에서도 파란색으로 보이게.
4. 근무 신청 표 맨 아래 「OFF 신청」 합계에 연차·검진 등 휴가도 모두 포함.
5. 근무 조정에서 「사유를 선택해 주세요」가 나오는데 사유를 어디서 고르는지 모르겠다.
6. 월말 누적 OFF 범위는 휴가를 뺀 값이어야 한다. 지금은 휴가가 들어가 있다.
7. 누적 OFF 최소·최대의 필수/권고가 같이 바뀐다. 따로 바뀌게.
8. 휴가 넣고 다시 생성은 되는데, 근무를 바꾼 뒤 다시 생성하면 그 변경이 유지되지 않는다. 예: 병가자 때문에 과장님이 D를 서기로 해서 과장님 칸을 D로 바꾸고, 병가를 넣고 리롤하면 과장님 D가 사라진다.
9. 근무 조정에서 「저장 · 재배포」를 하지 않았는데도 근무표에 변경이 보인다. 저장·재배포해야 바뀐 근무표가 보이게.
10. 수간호사가 평간호사에게 넣어 준 듀티(신청)를 평간호사가 지우지 못하게.
11. 하루 일하고 쉬고 하루 일하는 경우가 많다. 금지 패턴과 별도로 **권고(피하기) 패턴** 목록을 두고 OFF-D-OFF·OFF-E-OFF·OFF-N-OFF를 거기에 넣고 싶다.
12. 나이트가 6개씩 도는 것 같다. 월 나이트 목표를 없애고 상한·하한만 정하게.
13. 설정을 모두 필수로 하니 「해를 찾지 못했습니다 · 원인을 특정하지 못했으니…」가 나온다. 뭐가 안 되는지 모르겠다.

## 조사 결과 (코드·운영 데이터, 2026-10-20)

- **2:** 코드상 관리자가 넣은(`byAdmin`) 근무 신청은 지울 수 있다(`RequestPopover` 삭제 버튼 조건 `own || !isAdmin || cell.byAdmin`, 서버 `deleteShiftRequest`도 같음). 막히는 경우를 재현해서 고친다 — 후보: 3-9의 「OFF → 휴가로 바꾸기」로 생긴 휴가, 관리자가 간호사 신청 위에 덮어쓴 칸, 생성 화면 더블클릭 신청.
- **3:** 근무 신청 화면도 관리자 입력에 파란 테두리를 쓰지만 1.5px로 얇고 글자는 검정이라, 간호사 신청의 빨간 테두리·빨간 글자보다 눈에 덜 띈다. 생성 화면(2px)과 맞춘다.
- **4:** 지금 합계는 제출된 **단일 OFF 신청만** 센다(휴가·O/D 같은 복수 선택·임시 저장·수간호사 제외).
- **5:** 근무 조정 아래 「휴가 넣기」 줄에 **사유 고르는 칸이 없다**(버그). 경조·공가는 사유가 필수인데 이 줄은 검진 오전/오후만 사유를 넘긴다. 생성 화면의 빠른 휴가 버튼도 같다.
- **6:** 누적 OFF 계산 = 전월 누적 + 이달 OFF(일반·교육) − **이달 빨간 날 수**. 휴가 칸 자체는 OFF로 세지 않지만, 빨간 날(주말·공휴일)에 휴가가 걸려도 기준(빨간 날 수)에서 빠지지 않는다. 그래서 주말에 휴가가 낀 사람은 누적 OFF가 그만큼 마이너스로 보인다 — 「휴가가 들어가 있다」로 보이는 원인으로 판단.
- **7:** 두 행이 같은 심각도 키(`OFF_CARRY`)를 쓴다.
- **8:** 다시 생성은 DB의 칸만 읽는다. 저장하지 않은 변경(과장님 D)은 서버에 가지 않고, 리롤 결과가 화면의 미저장 변경을 통째로 덮는다. 저장한 관리자 변경도 시작일 이후면 다시 풀린다(수간호사·과장 칸만 달 전체 고정).
- **9:** 코드·근무 버튼 변경은 저장 전까지 간호사에게 안 보인다. 그런데 **「휴가 넣고 이후 다시 생성」의 휴가는 누르는 순간 바로 확정 근무표에 들어간다**(승인·칸 반영·변경 기록까지). 이것이 「저장 안 했는데 보인다」의 원인.
- **10:** 간호사는 관리자가 넣은 근무 신청을 지우거나 고칠 수 있다(고치면 간호사 임시 저장으로 바뀜). 관리자가 넣은 휴가는 화면에서 취소 버튼이 없지만 연차는 서버에서 취소가 통한다.
- **11:** 금지 패턴은 한 목록에 필수/권고 하나다. 패턴의 OFF는 OFF·연차·휴가 모두와 맞는다.
- **12:** 「월 나이트 목표」는 실제로 **두 번째 상한**이다(필수면 그 값이 곧 상한, 권고면 넘을 때 벌점). 나이트를 목표까지 끌어올리지는 않는다. 끌어올리는 것은 「월 나이트 최소」(운영값 5)다. 운영은 목표 6·필수라 사실상 상한 6이다.
- **13:** 운영 11월 입력으로 저장 없이 솔버만 돌려 봤다. 필수 17개 그대로면 불가능, **「D·E·N 고르게」(SHIFT_BALANCE) 하나만 권고로 풀면 바로 해가 나온다.** 나머지(나이트 목표·최대 인원·패턴·OFF-X-OFF·나이트 최소·N 뒤 D·E·OFF 전날 N 금지)는 하나씩 풀어도 여전히 불가능. 원인이 안 나온 이유는 진단 단계(10초·1스레드)가 시간 안에 증명을 못 해 빈 목록을 돌려줬기 때문이다. 「D·E·N 고르게」는 최근 3개월 D·E·N 개수 차이 2 이내인데, 지난달까지 이미 어긋난 사람은 이번 달만으로 맞출 수 없다.

## 결정 (사용자 답변 2026-10-20)

- **Q1:** 간호사가 D(또는 E·N)를 신청한 칸에서 관리자는 **신청한 그 근무 또는 OFF만** 줄 수 있다. 최대한 간호사 요청을 들어주는 쪽. 한 날에 너무 많이 몰리면 구두로 조율을 부탁하고 간호사가 직접 바꾼다. 지우기도 못 한다.
- **Q2(6번):** 지금 식 그대로(휴가는 OFF로 세지 않고 기준도 줄이지 않음, 예: 병가 5·OFF 8·기본 10 → −2). **다음 날 다시 확인할 수 있으니 확인 과제로 남긴다**(아래 검토 게이트).
- **Q3(8번):** 휴가 넣고 다시 생성할 때 과장님·다른 사람 칸 중 **관리자가 바꾼 칸(저장 여부 무관)은 고정**하고 나머지만 다시 만든다.
- **Q4(11번):** 「금지 권고 패턴」 목록을 새로 두고 OFF-D-OFF·OFF-E-OFF·OFF-N-OFF를 거기로 옮긴다.

## AI 해석 (제안)

1. (Q1 결정) 간호사가 낸 D·E·N 신청 칸에서 관리자 팝업은 **신청한 근무와 OFF만** 누를 수 있다(나머지 버튼 비활성 + 서버 거부). 지우기 막음.
2. 재현해서 관리자가 넣은 것(근무·휴가 모두)은 관리자가 지울 수 있게 고친다.
3. 근무 신청 화면의 관리자 입력을 생성 화면과 같은 2px 파란 테두리 + 파란 글자로.
4. 「OFF 신청」 행을 「쉬는 사람」 합계로: OFF + 모든 휴가(연차·특휴·개원·병가·경조·공가·검진). 제목도 맞춰 바꾼다. 3명 이상 빨간 표시는 그대로.
5. 「휴가 넣기」 줄에서 경조·공가를 고르면 사유 선택 칸이 나온다(신청 화면과 같은 목록). 생성 화면 빠른 버튼도 같게.
6. (Q2 결정) 이번에는 바꾸지 않는다. 확인 과제로 남김.
7. `OFF_CARRY` → `OFF_CARRY_MIN`·`OFF_CARRY_MAX` 두 키로 나눈다. 기존 설정값은 둘 다 그대로 이어받는다.
8. (Q3 결정) 다시 생성할 때 **화면의 미저장 변경과 저장한 관리자 변경을 고정**하고 나머지만 다시 만든다. 고정한 칸이 규칙과 부딪혀 해가 없으면 어느 칸 때문인지 알려 준다.
9. 「휴가 넣고 이후 다시 생성」도 다른 변경처럼 **미저장 변경**으로 둔다. 휴가·리롤 결과는 「저장 · 재배포」를 눌러야 확정 근무표·간호사 화면에 반영된다. 떠나면 버려진다(지금처럼 경고).
10. 간호사는 관리자가 넣은 근무 신청·휴가를 **지우거나 고치지 못한다**(화면에서 잠금 표시 + 서버 거부, 연차 취소 구멍도 막음). 바꾸려면 관리자에게 요청.
11. 규칙 설정에 **「권고 패턴(피하기)」** 목록을 금지 패턴 아래 새로 둔다. 항상 권고(벌점), 금지 패턴과 같은 입력 방식. (Q4 결정) 운영의 OFF-D-OFF·OFF-E-OFF·OFF-N-OFF는 배포 때 금지 → 금지 권고 패턴으로 옮긴다.
12. 「월 나이트 목표」를 없앤다. 남는 것은 **상한·하한**(각자 필수/권고). 운영값은 상한 7·하한 5를 그대로 둔다(지금은 목표 6 필수라 실제 상한 6이었음 — 없애면 7까지 나올 수 있다).
13. 원인 찾기를 보강한다: 진단이 빈 목록이면 필수 규칙을 하나씩 권고로 풀어 다시 풀어 보고, 풀리는 규칙을 「이 규칙을 권고로 바꾸면 만들 수 있습니다: D·E·N 고르게」로 알려 준다(생성 시간이 늘 수 있어 한 규칙당 짧게). 지금 운영은 「D·E·N 고르게」를 권고로 돌리면 바로 생성된다.

## 질문

- **Q1 (1번 「but.」 뒤):** 간호사 D·E·N 신청 칸에서 관리자가 할 수 있는 것은 무엇인가 — 휴가로 바꾸기만? 아니면 다른 예외가 있었나?
- **Q2 (6번):** 「휴가 제외」 = 휴가가 걸린 빨간 날을 기준에서 빼는 것이 맞나?
- **Q3 (8번):** 다시 생성할 때 고정할 범위 — 미저장·저장한 관리자 변경 모두 고정? 미저장만?
- **Q4 (11번):** OFF-X-OFF 세 패턴을 권고 패턴으로 옮겨 둘까, 빈 목록으로 두고 직접 옮기게 할까?

## 구현 결과 (2026-10-20, 브랜치 `feature/3-10-feedback-6`)

- **1:** 간호사 D·E·N 신청 칸 — 관리자 팝업은 신청 근무·OFF만 활성(교육·휴가 비활성, 신청 기간만). 서버도 거부. 확정된 달의 휴가(근무 조정 병가 등)는 막지 않는다.
- **2:** 원인 = 신청 화면 로딩(`loadRequestsRaw`)이 근무 신청의 `byAdmin`을 빠뜨려, 관리자가 넣은 칸에 삭제 버튼·파란 표시가 안 나왔다. 확정된 달에 관리자가 넣은 휴가는 신청 화면에서 취소하면 칸을 되돌린다.
- **3:** 관리자 입력 = 생성 화면과 같은 2px 파란 테두리 + 파란 글자(근무·휴가).
- **4:** 맨 아래 행 「쉬는 인원(OFF·휴가)」 = 제출된 OFF 신청 + 제출·승인된 모든 휴가, 사람·날짜당 한 번, 수간호사 제외. 3명 이상 빨간 표시 유지.
- **5:** 근무 조정 「휴가 넣기」에 경조·공가 사유 선택(신청 화면과 같은 목록, 공용 컴포넌트). 경조는 끝 날짜 자동.
- **8:** 다시 생성 때 미저장 편집 + 저장된 관리자 변경(시작일 이후)을 고정. 과장 S→D 미저장 변경도 유지. 결과는 기존 편집과 합쳐진다. 해가 없으면 고정한 관리자 변경 칸 수를 알려 준다.
- **9:** 「휴가 넣고 이후 다시 생성」은 아무것도 저장하지 않는다(가상의 휴가로 계산). 휴가·결과 모두 미저장 변경이며 「저장 · 재배포」 때 한 트랜잭션으로 휴가(승인·관리자 입력)와 칸을 쓴다. 실패하면 아무것도 저장되지 않는다. 저장 전 휴가 칸을 누르면 「휴가 넣기 되돌리기」.
- **7:** 심각도 키 `OFF_CARRY` → `OFF_CARRY_MIN`·`OFF_CARRY_MAX`. 검사 코드는 H-OFF-CARRY 하나, 어긴 쪽으로 심각도를 고른다. 예전 저장값 `OFF_CARRY`는 둘 다에 이어진다.
- **10:** 관리자가 넣은 근무 신청·휴가는 간호사가 고치거나 지우거나 휴가로 덮지 못한다(화면 잠금 안내 + 서버 거부, 연차 취소 구멍 막음).
- **11:** 「금지 권고 패턴」 목록(항상 권고, 벌점 1500 — 금지 패턴을 권고로 둘 때 5000보다 낮게). 마이그레이션 0015가 `soft_patterns` 열을 더하고, 최신 규칙에 OFF-D-OFF·OFF-E-OFF·OFF-N-OFF가 있으면 새 버전을 만들어 권고 패턴으로 옮긴다.
- **12:** 「월 나이트 목표」 제거(설정·검사·솔버·계약). 「월 나이트 최소」 → 「월 나이트 하한」, 검증은 하한 ≤ 상한. 예전 값은 읽을 때 버린다.
