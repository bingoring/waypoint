# [Stage 3-8] 운영 피드백 4 — 생성 중 신청·생성안에서 관리자 신청·확정 철회·근무 조정 흐름·KTAS 갱신 팝업

## 요구사항 (사용자 2026-10-19)

1. 관리자가 「이 안으로 확정」 전이면 근무 신청 가능. 생성 뒤 신청이 들어오면 생성 결과의 안 옆에 「신청 추가됨」.
2. N 근무 뒤 쉬고 다시 일할 때 첫 근무는 D·E 권장(필수 아님).
3. 신청한 OFF 전날은 D·E. N도 괜찮은 사람은 OFF 신청 때 팝업 「전날(날짜)에 N이 가능하면 전날 신청을 D·E·N·OFF 모두 골라 주세요」 → 확인.
4·6. 생성안 격자에서 관리자가 칸을 더블클릭해 D/E/N/OFF를 정하면 그 간호사의 신청(관리자 입력)으로 저장하고 「신청 근무로 저장하고 리롤하겠습니까?」.
5. 내 설정 KTAS 입력(3-6에 있음) + 만료 6개월 전(갱신 신청 시기)부터 로그인 때 「갱신 신청 가능합니다」 팝업, 3회까지.
7. 근무 조정: 「근무 조정」 버튼으로 선택 모드를 켜지 않고 바로 사람·날짜를 고른다. 「조정 끝내기」 대신 「조정 신청」.
8. 2인 재배정이면 팝업을 두 사람 근무를 맞바꾼 상태로 바로 연다.
9. 확정·배포 뒤에도 확정을 철회하고 다시 리롤.
10. 관리자는 협의 기간 밖에도 근무 조정(칸 편집·교환), 휴가는 근무 조정 화면에서 넣지 않음.

## 결정 (사용자 답변 2026-10-19)

- 2: N 연속 뒤 쉬고 다시 일할 때 첫 근무는 D·E(N으로 다시 시작하지 않게) — 권고(규칙 설정에서 필수/권고 전환 가능).
- 9: 철회 전 「확정 뒤 교환 N건·관리자 수정 N칸이 사라집니다」를 보여 주고 확인. 승인된 휴가는 유지(다시 생성할 때 고정 칸). 마감한 달은 철회 불가.
- 10: 관리자는 협의 기간과 상관없이 칸 편집·교환, 근무 조정 화면에서 휴가는 넣지 않는다(휴가는 근무 신청에서).
- 3 (AI): 「OFF 전날은 D·E」 규칙은 규칙 설정에 두고 기본 필수, 전날에 N을 포함한 신청이 있으면 그 날은 예외.
- 8 (AI): 두 사람이면 「변경 후」를 서로 맞바꾼 값으로 미리 채운다(사용자가 바꿀 수 있음).
