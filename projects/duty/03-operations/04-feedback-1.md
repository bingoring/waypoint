# [Stage 3-4] 운영 피드백 1 — 연차 직접 수정 · 행 순서 편집 · README

## 목적

운영 시작 전 사용자 피드백 세 가지를 반영한다.

1. 간호사가 남은 연차를 **언제든** 고친다(입사 1년 미만은 달마다 늘 수 있고, 조사 결과가 나올 때까지). 이력이 남고 관리자가 본다.
2. 근무표 행 순서(표 순서 `seniorityRank`)를 관리자가 바꾼다. 근무표·근무 조정·근무 신청·생성안·동료 현황에 모두 반영.
3. README에 운영 주소(offplz.com)와 현재 구성·배포 방식을 적는다.

## 결정 (사용자 2026-10-12)

- 연차 수정: **바로 반영 + 관리자 확인**(2-11 초기 설정과 같은 방식 — 원장 `self_input`, 제출 기록 `self_edit`, 간호사 관리 「본인 입력 확인 필요」에서 확인·되돌리기).
- 행 순서: 근무표에서 행을 끌면 칸 클릭·호버와 섞여 잘못 조작하기 쉬워, **간호사 관리 「순서 바꾸기」**(끌어서 놓기 + ↑↓)에서 바꾼다(AI 권장, 사용자 선택). → 같은 날 별도 모드를 없애고 목록 행의 ⠿ 손잡이로 바꿈(아래 「추가 반영」, DECISIONS).

## 구현 결과

- 내 설정 「연차」: 남은 연차 입력·저장(`saveAnnualAction`, 모드 `self_edit`, 초기 설정 해는 그대로).
- 간호사 관리: 확인 요청 카드에 종류(초기 설정·해마다 연차·연차 수정), 접는 「본인 입력 변경 이력」(최근 100건, 확인 대기·확인·되돌림과 메모).
- 간호사 관리 행 순서: `reorderStaff`(활성 전원 1..n, 사용자 행 잠금, 명단이 바뀌었으면 거부), 관리자 액션 가드 테스트에 포함. 화면은 처음 「순서 바꾸기」 모드였다가 ⠿ 손잡이로 바뀜(아래).
- README: 운영 주소, 기능 요약, 구성 표, 자동 배포·백업·감시. `.env.prod.example`에 운영 도메인 주석.
