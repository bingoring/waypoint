# [Stage R-1] Independent Code Review 🔍

## 목적

작성자(구현 주체)와 **컨텍스트가 분리된** 독립·적대적 리뷰어가 Construction 산출물(코드와 테스트) 전체를 검토한다. 설계 게이트가 놓친 코드 수준의 결함을 찾아 진짜 결함을 고치고, Operations(3-1 첫 공개) 진입을 게이트한다.

## 입력 (Inputs)

- 코드: `Sources/`, `Tests/`, `Tools/`, `scripts/`, `prototype/`, `.github/workflows/`, `Package.swift`(검토 기준 `main` `30ef8a8`, 약 8,600줄)
- 품질 기준선: [`../01-inception/03-architecture-decision.md`](../01-inception/03-architecture-decision.md) "리뷰 게이트의 품질 기준선"(정확성, 보안·개인정보, 성능 예산, 정적 분석, 화면)
- 명세: 각 유닛의 `business-rules.md`, `business-logic-model.md`, `domain-entities.md`, 스테이지 문서의 편차 로그, [`../DECISIONS.md`](../DECISIONS.md)
- 리뷰어 지시: [`../../../_templates/reviewer-brief-template.md`](../../../_templates/reviewer-brief-template.md)를 관점마다 채워서 사용

- **[LOW·설계] (R-C) 알림 본문에 세션 제목이 나감:** 명세대로다. README에 한 줄 알릴지는 사용자 결정으로 올린다.
- **[LOW] (R-B) stat, 지문, 읽기가 경로로 따로 열려 TOCTOU:** 보류. 같은 inode로 제자리에서 더 길게 다시 쓰는 경우만 해당하고, Claude Code는 기록에 덧붙이기만 한다. 창은 밀리초 단위다.

### INV4(프로토타입과 글자 단위 일치)의 적용 범위

INV4는 Claude Code가 실제로 쓰는 형식의 입력에 적용한다. 다음은 두 구현이 다르게 다루는 것을 확인하고 그대로 두는 예외다([DECISIONS](../DECISIONS.md) 2026-11-20).
- 마지막 줄에 줄바꿈이 없음: Swift는 쓰는 중일 수 있어 세지 않는다(2-1 R6).
- 심볼릭 링크인 `.jsonl`, `.jsonl` 이름의 폴더: Swift는 건너뛴다.
- 시간대 없는 타임스탬프, 날짜가 넘치는 타임스탬프 등 ISO 8601의 변형, 중복 키, `NaN`, 유니코드 이스케이프로 쓴 키
- 합계가 `Int64.max`(약 92억 달러)를 넘음: Swift는 포화한다.
- 소수 초의 마지막 비트: 간격이 경계에서 약 2.4e-7초 안일 때만 다르다.
