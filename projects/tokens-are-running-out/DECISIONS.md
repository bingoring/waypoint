## 2026-11-17 · 무엇을 만들 것인가: 한도 소진 원인 진단
- **결정:** Claude Code 사용량이 왜 줄었는지 원인별로 보여주는 macOS 메뉴 막대 앱을 만든다.
- **근거:** 사용자의 기준은 "많은 사람이 불평하지만 공급은 적은 것"이다. 공식 이슈 500개(반응순)를 주제별로 묶고 주제마다 기존 도구의 규모를 쟀다. 한도 소진 불만은 👍 2,746 · 댓글 3,490으로 가장 컸고, "왜"를 진단하는 도구는 가장 큰 것이 ★27이었다. 자세한 근거는 [inputs/design.md](inputs/design.md) 1장.
- **대안(탈락):**
  - 실행 중인 세션의 진행 상황 모니터: Claude Code가 완료와 질문을 이미 알려 주고, 데스크톱 앱에서 바로 볼 수 있다.
  - 자리를 비운 사이의 복귀 요약: 데스크톱 앱을 열면 볼 수 있다.
  - 반복 지시를 설정으로 옮기는 습관 코치: claude-reflect(★1,958)가 이미 같은 기능을 갖췄다.
  - 여러 계정 관리: 수요(👍 1,060)는 크지만, 계정별 데스크톱 앱 실행 도구가 6개 넘게 활발히 만들어지는 중이다.
  - 동반자(펫): 상태에 반응하는 펫은 이미 ★10k 규모 도구가 있다.
- **결정자:** 사용자

- **결정:** MIT 라이선스의 공개 저장소로, 무료로 배포한다.

## 2026-11-17 · 구현 방식: Swift 네이티브
- **결정:** SwiftUI 메뉴 막대 앱으로 만들고, 분석 코어는 별도 Swift 패키지로 분리한다.
- **근거:** 차별점은 가볍고 믿을 수 있는 진단 도구라는 데 있다. 실행에 추가 설치물이 필요 없고, 빨리 내놓을 수 있다. 코어를 분리해 두면 나중에 CLI로 확장할 수 있다.
- **대안(탈락):** Rust 코어 + Swift UI(빌드와 배포가 복잡하고 출시가 늦어짐), Tauri나 Electron(무거움), Claude Code Mods(세션 안에서는 그 세션만 보임).
- **결정자:** 사용자

## 2026-11-17 · 쉬었다 돌아온 재구축을 짧은 휴식과 긴 휴식으로 나눔
- **결정:** 캐시 만료 뒤 재구축을 경과 시간 3시간을 경계로 나누고, "줄일 수 있었던 양"은 짧은 휴식만 계산한다. 메뉴 막대에는 판단이 아니라 사실인 "쉬었다 돌아온 캐시 재구축의 비용 비율"을 보여준다.
- **근거:** 검증 기간(2026-11-10 ~ 11-17)의 만료 재구축 50건 중 34건이 3시간을 넘었고, 대부분 밤새 쉰 경우였다. 이런 경우는 더 일찍 돌아오는 방법으로 피할 수 없으므로, 전부를 "줄일 수 있었다"고 하면 반목표(근거 없는 단정 금지)에 어긋난다. 짧은 휴식만 따진 줄일 수 있었던 양은 전체 비용의 5.5%였다.
- **대안(탈락):** 만료 재구축 전체를 줄일 수 있었던 양으로 계산(16.1%, 과장).
- **결정자:** AI(권고)

## 2026-11-17 · 실행 중인 세션은 `~/.claude/sessions` 파일로 확인

## 2026-11-17 · 파일 간 중복 호출은 전체 기록 단위로 한 번만 센다 (1-2 계약 확장)
- **결정:** 같은 `message.id`는 모든 기록 파일을 통틀어 하나의 ApiCall이다. 비용과 개수는 소유 파일 하나에서만 센다. 소유 파일은 (메인 파일이면서 줄의 `sessionId`가 파일 ID와 같음) → 먼저 생성된 파일 → 경로 순으로 정한다. 복사된 호출도 그 파일 안의 순서를 정하는 맥락으로는 쓴다.
- **근거:** 고유 메시지 43,707개 중 4,628개가 두 개 이상의 파일에 있었다. 세션을 이어 가거나 갈라낼 때 이전 대화가 새 파일로 복사된다. 파일 단위로만 중복을 제거하면 나중에 복사가 생길 때마다 과거 기간의 수치가 바뀐다(기준값 기간 4,133건 → 4,413건). 전체 단위로 제거하면 기준값이 그대로 유지된다.
- **대안(탈락):** 파일 단위 중복 제거(시간이 지나면 결과가 바뀜). 줄의 `sessionId`만으로 소유 결정(310건은 복사할 때 `sessionId`도 바뀌어 판별 불가).
- **결정자:** AI(권고). 2-1 승인 게이트에서 확인.

## 2026-11-17 · 외부 의존성 없이 만든다
- **결정:** SQLite는 macOS에 포함된 `SQLite3`를 얇게 감싸서 쓰고, CLI 인자는 직접 파싱한다. 린터는 Swift 툴체인에 포함된 `swift format lint --strict`를 쓴다.
- **근거:** 모든 세션 기록을 읽는 앱이라서 신뢰가 핵심이다. 의존성이 없으면 공급망 위험이 줄고 빌드가 단순해진다. 필요한 SQL과 CLI 기능이 작다.
- **대안(탈락):** GRDB(편하지만 의존성 추가), swift-argument-parser(공식이지만 의존성 추가), SwiftLint(별도 설치 필요).
- **결정자:** AI(권고). 2-1 승인 게이트에서 확인.

## 2026-11-20 · 로그인 항목의 `.notFound`는 "꺼짐"으로 다룬다 (v0.1.1)
- **결정:** `SMAppService.mainApp.status`의 `.notFound`를 `.notRegistered`와 같이 "꺼짐"으로 다룬다. 설정의 토글은 켤 수 있고, 켜면 `register()`를 부른다. "사용 불가"는 앞으로 생길 알 수 없는 상태에만 남긴다. 결함은 `v0.1.1`로 고치고, 소개 글은 그 뒤에 올린다.
- **근거:** 처음 설치한 앱은 로그인 항목 데몬에 기록이 없어서 `.notFound`를 읽는다. 이것을 "사용 불가"로 보면 사용자가 이 기능을 영원히 켤 수 없다(3-1 첫 실행에서 발견, 개발자 포럼의 보고와 일치). 공개 소개 직후 첫 사용자에게 바로 보이는 결함이다.
- **대안(탈락):** README에 우회 방법을 적는 것(앱 안에서는 우회할 방법이 없다), 소개 글을 먼저 올리고 나중에 고치는 것(첫인상에 바로 드러난다).
- **결정자:** 사용자(v0.1.1로 고치기로 결정), 변환 방식은 AI(권고)

## 2026-11-23 · 큰 세션 정리 안내: 시험한 고정 프롬프트(A2)와 시점 안내, 두 위치
- **결정:** 실행 중인 세션 중 컨텍스트가 20만 토큰 이상인 것을 팝오버의 "큰 세션" 영역에 보이고, 그 세션에 붙여 넣을 `/compact` 프롬프트를 복사해 준다. 곧 만료되는 첫 세션이 큰 세션이면 "떠나기 전에 정리"를 안내한다. 프롬프트는 무엇을 남기고 버릴지만 정한 고정 지시문(A2)이고, 대화 본문을 읽지 않는다. 앱은 compact를 직접 실행하지 않는다.
- **근거:**
  - 7일 실제 기록에서 일반 작업이 47%, 그 비용의 68%가 캐시 다시 읽기였다. 일반 작업 비용의 93%는 20만 토큰 이상 호출에서 나왔다.
  - 자동 compact 88회의 압축 직전 크기 중앙값은 93.8만 토큰이었다.
  - 세션 복제본 두 개로 기본, A, A2를 블라인드 평가했다. A2가 두 세션 모두 1위였다(18점 만점에 18점, 17점).
- **대안(탈락):**
  - 앱이 세션 내용에서 체크리스트를 뽑아 덧붙이는 방식(B): 측정 뒤 정한다.
  - 스킬 파일 생성: 앱은 `~/.claude`에 쓰지 않는다.
  - 앱이 compact를 직접 실행: 사용량을 대신 쓰지 않는다는 약속과 어긋난다.
  - 기본 `/compact`만 안내: 블라인드 평가에서 가장 낮았고, 불필요한 식별자를 넣었다.
- **결정자:** 사용자(방식, 두 위치, 프롬프트 시험), AI(20만 기준과 문구). 2-5 게이트에서 확인.

## 2026-11-23 · compact 뒤의 세션은 만료 경고와 큰 세션 목록에서 뺀다 (2-3 계약 확장)
- **결정:** 메인 기록에서 마지막 호출보다 뒤에 compact 표시가 있는 세션은, 다음 호출이 기록될 때까지 만료 경고와 큰 세션 목록에서 뺀다. 예약된 알림도 취소된다.
- **근거:** compact 호출은 기록에 사용량을 남기지 않는다. 그래서 정리하고 떠난 세션에 대해 "62만 토큰에서 다시 만든다"는 경고가 계속 남는다. compact 뒤 다음 메시지가 다시 쓰는 것은 요약뿐이다. 색인은 compact 위치를 이미 저장하고 있다.
- **결정자:** AI(빌더 검토에서 발견). 2-5 게이트에서 확인.
