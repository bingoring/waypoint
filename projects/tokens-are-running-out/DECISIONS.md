## 2026-11-17 · 무엇을 만들 것인가: 한도 소진 원인 진단
- **결정:** Claude Code 사용량이 왜 줄었는지 원인별로 보여주는 macOS 메뉴 막대 앱을 만든다.
- **근거:** 사용자의 기준은 "많은 사람이 불평하지만 공급은 적은 것"이다. 공식 이슈 500개(반응순)를 주제별로 묶고 주제마다 기존 도구의 규모를 쟀다. 한도 소진 불만은 👍 2,746 · 댓글 3,490으로 가장 컸고, "왜"를 진단하는 도구는 가장 큰 것이 ★27이었다. 자세한 근거는 [inputs/design.md](inputs/design.md) 1장.
- **대안(탈락):**
  - 실행 중인 세션의 진행 상황 모니터: Claude Code가 완료와 질문을 이미 알려 주고, 데스크톱 앱에서 바로 볼 수 있다.
  - 자리를 비운 사이의 복귀 요약: 데스크톱 앱을 열면 볼 수 있다.
  - 반복 지시를 설정으로 옮기는 습관 코치: claude-reflect(★1,958)가 이미 같은 기능을 갖췄다.
  - 여러 계정 관리: 수요(👍 1,060)는 크지만, 계정별 데스크톱 앱 실행 도구가 6개 넘게 활발히 만들어지는 중이다.
  - 동반자(펫): 상태에 반응하는 펫은 이미 ★10k 규모 도구가 있다.
- **결정자:** 사용자

## 2026-11-17 · 공개 방식: 오픈소스 무료
- **결정:** MIT 라이선스의 공개 저장소로, 무료로 배포한다.
- **근거:** 앱이 모든 세션의 기록을 읽으므로, 코드를 공개하는 것이 신뢰를 얻는 가장 확실한 방법이다. 경쟁 도구도 대부분 오픈소스다.
- **대안(탈락):** 유료 판매.
- **결정자:** 사용자

## 2026-11-17 · 구현 방식: Swift 네이티브
- **결정:** SwiftUI 메뉴 막대 앱으로 만들고, 분석 코어는 별도 Swift 패키지로 분리한다.
- **근거:** 차별점은 가볍고 믿을 수 있는 진단 도구라는 데 있다. 실행에 추가 설치물이 필요 없고, 빨리 내놓을 수 있다. 코어를 분리해 두면 나중에 CLI로 확장할 수 있다.
- **대안(탈락):** Rust 코어 + Swift UI(빌드와 배포가 복잡하고 출시가 늦어짐), Tauri나 Electron(무거움), Claude Code Mods(세션 안에서는 그 세션만 보임).
- **결정자:** 사용자

## 2026-11-17 · 앱 이름: Tokens Are Running Out
- **결정:** 앱 이름은 "Tokens Are Running Out", 한 줄 소개는 "Where did my tokens go?" / "내 토큰 어디 갔어?"로 한다.
- **근거:** 한도가 줄어드는 불안을 그대로 짚어서 직관적이다. 2026-11-17 GitHub 저장소 이름 검색에서 같은 이름이 없었다. 이름이 남은 양을 보여주는 게이지처럼 읽힐 수 있으므로, 소개 문구에서 "왜"를 분명히 한다.
- **대안(탈락):**
  - Drainscope: 배터리 분석 앱이 같은 이름을 쓴다.
  - 질문형 이름(Where did my tokens go 등): 비슷한 도구 3~4개가 이미 쓰고 있어 검색에서 섞인다.
  - TokenWhy: 사용자가 원하지 않았다.
- **결정자:** 사용자

## 2026-11-17 · Waypoint 워크플로 채택
- **결정:** 이 프로젝트를 Waypoint로 진행하고, waypoint를 `docs/dlc`에 서브모듈로 둔다.
- **근거:**
  - 사용자의 다른 개인 프로젝트들이 같은 방식을 쓴다.
  - 작업이 여러 세션에 걸쳐 이어지므로, STATUS와 DECISIONS가 세션 사이의 연속성을 지켜 준다.
  - 재구축 판정과 원인 분류는 로직이 핵심이라서 Build Spec의 이점이 크다.
  - 반목표(근거 없는 단정 금지, 읽기 전용)를 지키는 데 독립 리뷰 게이트가 맞는다.
- **대안(탈락):** superpowers의 설계 문서와 구현 계획만으로 진행하는 방식. 문서가 waypoint와 따로 놀아 진실 공급원이 둘이 된다.
- **결정자:** AI(권고), 사용자가 조건부로 위임("안 따르는 게 낫다고 판단되면 하지 말 것")

## 2026-11-17 · 공개 저장소의 개인정보 원칙
- **결정:** 개발자 기기의 실제 Claude Code 기록, 세션 제목, 대화 내용, 회사 업무 내용을 커밋하지 않는다. 문서에는 집계 수치만 쓰고, 예시는 가상의 값으로 쓴다. 테스트 픽스처는 합성 데이터로 만든다.
- **근거:** 메인 저장소와 waypoint가 모두 공개 저장소다. 분석 대상이 개인 작업 기록이라서, 원본이 섞여 들어갈 위험이 크다. duty 프로젝트의 가명 원칙과 같은 취지다.
- **대안(탈락):** 없음.
- **결정자:** AI(권고)

## 2026-11-17 · 쉬었다 돌아온 재구축을 짧은 휴식과 긴 휴식으로 나눔
- **결정:** 캐시 만료 뒤 재구축을 경과 시간 3시간을 경계로 나누고, "줄일 수 있었던 양"은 짧은 휴식만 계산한다. 메뉴 막대에는 판단이 아니라 사실인 "쉬었다 돌아온 캐시 재구축의 비용 비율"을 보여준다.
- **근거:** 검증 기간(2026-11-10 ~ 11-17)의 만료 재구축 50건 중 34건이 3시간을 넘었고, 대부분 밤새 쉰 경우였다. 이런 경우는 더 일찍 돌아오는 방법으로 피할 수 없으므로, 전부를 "줄일 수 있었다"고 하면 반목표(근거 없는 단정 금지)에 어긋난다. 짧은 휴식만 따진 줄일 수 있었던 양은 전체 비용의 5.5%였다.
- **대안(탈락):** 만료 재구축 전체를 줄일 수 있었던 양으로 계산(16.1%, 과장).
- **결정자:** AI(권고)

## 2026-11-17 · 실행 중인 세션은 `~/.claude/sessions` 파일로 확인
- **결정:** 실행 상태는 `~/.claude/sessions/<pid>.json`과 `kill(pid, 0)`으로 확인하고, `claude agents --json`은 호출하지 않는다.
- **근거:** 두 출처 모두 데스크톱 앱 세션을 포함한다(확인함). CLI를 주기적으로 실행하면 유휴 CPU 목표에 어긋나고, CLI가 시작할 때 네트워크를 쓰는지 알 수 없다. 데스크톱 앱만 쓰는 사용자는 PATH에 `claude`가 없을 수도 있다.
- **대안(탈락):** `claude agents --json`(문서화된 공식 출처지만 위 이유로 탈락).
- **결정자:** AI(권고)

## 2026-11-17 · 디자인 기준: better-* 스킬
- **결정:** 화면은 jakub.kr의 better-* 디자인 스킬을 기준으로 만들고, 구현 뒤 better-interface로 실제 화면을 검토한다. HIGH가 남아 있으면 출시하지 않는다.
- **근거:** 사용자가 스킬을 설치하고 따르도록 지시했다. 시안 단계 검토에서 HIGH 3건(VoiceOver 이름 없음, 잘린 제목에 접근 불가, 복구 방법 없는 오류 상태)을 찾아 고쳤다.
- **대안(탈락):** 없음.
- **결정자:** 사용자

## 2026-11-17 · 서명과 배포
- **결정:** 개발자의 Apple Developer Program 계정으로 Developer ID 서명과 공증을 하고, GitHub Releases와 자체 Homebrew tap으로 배포한다. 공식 homebrew/cask는 등록 조건을 만족한 뒤 신청한다.

- **대안(탈락):** 서명 없이 배포하고 README에 우회 방법을 안내하는 방식.
- **결정자:** 사용자(계정 있음), AI(배포 경로 권고)
