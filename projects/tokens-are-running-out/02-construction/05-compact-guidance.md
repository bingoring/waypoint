# [Stage 2-5] 큰 세션 정리 안내 (compact 프롬프트 · 시점 안내)

## 목적

컨텍스트가 큰 세션을 팝오버에 보여 주고, 그 세션에 붙여 넣을 `/compact` 프롬프트를 복사해 준다. 곧 만료되는 큰 세션에는 "떠나기 전에 정리"를 안내한다. 사용자가 매일 팝오버를 열어 비용의 가장 큰 원인을 보고 행동을 바꾸게 하는 것이 목표다. 산출물은 앱 기능과 `v0.2.0` 릴리스다.

### 배경: 분석은 정확했고, 보여 주는 방식이 문제였다
사용자가 "내 환경에서는 캐시 만료보다 일반 작업 소비가 크다"고 알려 와, 개발자 기기의 최근 7일 기록(2026-11-13 ~ 20)으로 다시 계산했다. 집계만 출력했고, 임시 색인은 지웠다.
- **정확도:**
  - 원인별 비중은 일반 작업 47.0%, advisor 22.4%, 서브에이전트 16.9%, 쉬었다 돌아온 뒤의 재구축 12.6%였다.
  - 가격이 없는 모델은 없었다.
  - 재구축 판정 임계값을 5만에서 5천으로 낮춰도 재구축 비중은 12.6%에서 12.7%로 거의 그대로였다.
  - 분석은 사용자의 감각과 일치한다.
- **문제:** 앱의 중심 이야기인 캐시 만료는 비용의 8분의 1이다. 가장 큰 덩어리인 "일반 작업"은 속이 보이지 않는다.
- **일반 작업의 속:**
  - 비용의 68%는 호출마다 컨텍스트 전체를 캐시에서 다시 읽는 비용이다. 출력은 19%, 새 캐시 쓰기는 14%다.
  - 일반 작업 비용의 93%는 프롬프트가 20만 토큰 이상인 호출에서 나온다. 호출 한 번의 평균 비용은 40만 ~ 100만 토큰 구간이 약 $0.17로, 10만 ~ 20만 토큰 구간(약 $0.08)의 두 배다.
  - 세션 24개 가운데 상위 5개가 일반 작업 비용의 58%다.
- **compact 기록:**
  - 기록에 남은 compact 88회가 모두 자동이었다.
  - 압축 직전 크기의 중앙값은 93.8만 토큰, 압축 뒤는 2.2만 토큰이다. 세션이 1M 모델의 자동 compact 지점(약 96.7만)까지 커진 뒤에야 압축되고 있다.

### 목표 장면 (사용자)
- 매일 팝오버를 열어 비용 원인을 보고 행동을 바꾼다.
- 큰 세션을 보면, 앱이 그 세션에서 중요한 것을 잘 간직하게 하는 `/compact` 프롬프트를 만들어 준다. 사용자는 복사해서 그 세션에 붙여 넣고 Enter만 누른다. 스킬 파일 대신 프롬프트를 고른 이유는, 앱이 세션에 직접 명령할 수 없기 때문이다.

### 방식
| 방식 | 내용 | 결정 |
|---|---|---|
| **A. 고정 프롬프트** | 무엇을 남기고 버릴지 정한 지시문. 무엇이 중요한지는 세션 안의 Claude가 판단한다 | **채택(사용자)**. 대화 본문을 새로 읽지 않는다 |
| B. 앱이 세션 내용에서 체크리스트를 뽑아 덧붙임 | 편집 파일, 할 일, 첫 요청 | 후속 후보. 측정 뒤 정한다 |
| 시점 안내 | 작업이 끝났을 때, 쉬러 가기 직전 | **채택(사용자)** |

위치는 두 곳 모두로 정했다(사용자): ① 새 "큰 세션" 영역, ② 기존 "곧 만료되는 캐시" 줄.

### 프롬프트 시험 (2026-11-20)
- **방법:**
  - 개발자 기기의 큰 세션 두 개(23만, 32만 토큰)를 `claude -p --resume <id> --fork-session`으로 복제했다. 원본은 바뀌지 않는다.
  - 기본 `/compact`, 초안 A, 고친 A2로 각각 compact했다.
  - 요약을 X, Y, Z로 이름만 붙여 섞은 뒤, 작성 맥락이 없는 평가자가 블라인드로 점수를 매겼다.
  - 요약 원문과 평가 자료는 평가 뒤 지웠다.
- **1차(기본 대 A, 7개 항목, 만점 14):** 기본 10 / 10, A 12 / 14. A가 두 세션 모두 나았다. 결정과 이유, 현재 상태, 간결함에서 앞섰다.
- **A의 약점:**
  - 시스템·하네스 규칙을 사용자 지시로 적었다.
  - "다음 행동 하나"만 남기고 남은 작업 목록을 잃었다.
  - 지적만 하고 아직 고치지 않은 문제를 빠뜨렸다.
  - 이 셋을 고친 것이 A2다.
- **2차(기본, A, A2, 9개 항목, 만점 18):** 기본 16 / 11, A 15 / 16, **A2 18 / 17**. A2가 두 세션 모두 1위였다.
  - A2에는 사용자 지시 오귀속이 없었다.
  - 기본 요약은 두 차례 모두 이어서 작업하는 데 필요 없는 이메일과 클라우드 계정 ID를 넣었다. A와 A2는 넣지 않았다.
- **기계 비교:** 편집한 파일이 요약에 나온 수는 세 방식이 비슷했다(29개 중 7 ~ 9개, 6개 중 6개). 파일 지시는 효과가 없었다.
- **비용:** compact 호출은 세션 기록에 사용량이 남지 않는다. 그래서 압축 전 크기와 단가로 추정했고, 일곱 번(작은 시험 포함)을 합쳐 정가 기준 약 $9 ~ 17이다. `claude -p`가 보고한 금액은 재개한 세션의 누적 비용으로 보인다.
- **한계:** 세션 두 개, 두 차례 평가로 표본이 작다. 시험한 것은 한국어판이고, 영어판은 같은 구조의 번역이라 시험하지 않았다.

### 범위
- **포함:**
  - ① "큰 세션" 영역: 실행 중인 세션 중 컨텍스트가 20만 토큰 이상인 것. 세션마다 컨텍스트 크기, 호출당 다시 읽는 비용(정가), "정리 프롬프트 복사" 버튼을 둔다.
  - ② 만료 경고의 안내 줄: 가장 먼저 만료되는 세션이 큰 세션이면 "떠나기 전에 정리" 안내와 같은 복사 버튼을 붙인다.
  - 프롬프트: `/compact ` 뒤에 A2(한국어 시험본)를 붙인다. 영어판은 그 번역이다. 앱 언어를 따른다.
  - 한·영 문구, 스냅숏, 화면 검토(better-interface), 독립 리뷰, `v0.2.0` 릴리스
- **제외(후속 후보):**
  - B(세션 내용에서 뽑은 체크리스트)
  - 메뉴 막대 숫자 변경
  - 일반 작업 비용 분해와 advisor 비용 표시
  - compact 비용이 기록에 남지 않아 분석에서 빠지는 문제
  - 20만 기준을 설정으로 바꾸는 것(3-2에서 다시 본다)

### 지키는 선
- 앱은 `/compact`를 직접 실행하지 않고, 세션에 입력을 보내지 않는다. README의 "사용량을 대신 쓰지 않는다" 약속이다.
- 대화 본문을 새로 읽지 않는다. 프롬프트에는 세션 내용이 들어가지 않는다.
- 네트워크를 쓰지 않고, `~/.claude`에 쓰지 않는다. 복사는 사용자가 누를 때만 클립보드에 쓴다.
- 반목표 5번: "아낄 수 있다"는 단정을 하지 않는다. 컨텍스트 크기와 정가 기준 비용 같은 사실만 보여 준다.

### 빌더 검토 반영 (2026-11-23)
작성 맥락이 없는 검토자가 이 문서만 보고 구현을 계획할 수 있는지 확인했다. 질문 세 개를 이렇게 처리했다.
- **compact 뒤에도 예전 크기를 보여 주는 문제(AI 판단으로 해결):** compact 호출은 기록에 사용량이 남지 않으므로, 사용자가 정리하고 자리를 떠도 화면은 다음 메시지 전까지 예전 크기를 보여 준다. 만료 경고와 예약된 알림도 그렇다. 색인은 compact 위치를 이미 저장하므로, 마지막 호출 뒤에 compact가 있으면 큰 세션 목록과 만료 경고에서 그 세션을 뺀다(BR-C17, BR-C18). 2-3 만료 경고의 계약을 넓히는 변경이다.
- **대화형 세션에 붙여 넣었을 때 동작하는지(구현 전 확인):** 시험은 `claude -p`로 했으므로, 대화형 입력창에 여러 줄을 붙여 넣는 경로는 확인하지 않았다. 구현 전에 확인하고, 안 되면 같은 문장을 한 줄로 잇는다(BR-C19, BR-C20). 확인에는 사용자의 도움이 필요하다.

| 브랜치 리뷰(작성 맥락이 없는 리뷰어) | Critical 없음. Important 3건: 팝오버 높이 제한 없음(고침), 붙여 넣기 확인 미완료(머지 전 필수), Waypoint 기록 누락(이 절로 고침). 사소한 7건은 후속 후보 |

### 후속 후보 (브랜치 리뷰의 사소한 항목)
- compact가 들어오면 만료 경고와 예약된 알림이 사라지는지 앱 모델 수준에서 끝까지 확인하는 테스트
- 2초 안에 다시 누른 복사가 실패하면, 앞서 띄운 "복사됨"이 남는다
- 클립보드 쓰기가 실패해도 기존 내용은 이미 지워진다
- 두 목록을 갱신하는 사이에 색인이 바뀔 수 있다(다음 갱신에서 바로잡힌다). 코드 주석이 이보다 강하게 말한다
- compact 확인 쿼리가 마지막 호출의 순번을 다시 찾는다(조회 한 번 더)
- `check-strings.py`의 넓힌 패턴이 테스트 빌드 폴더도 맞춘다
- 제목 없는 세션의 한국어 접근성 이름이 "제목 없는 세션 세션의 정리 프롬프트 복사"로 읽힌다

### 붙여 넣기 확인 (2026-11-23, 사용자와 함께)
시험용 복제 세션을 대화형으로 열어 프롬프트를 붙여 넣었다.

| 붙여 넣은 것 | 결과 |
|---|---|
| 여러 줄 한국어(10줄) | 일반 메시지로 처리됨. compact 경계 없음 |
| 한 줄 한국어(527자) | `/compact`로 실행됨(6.6만 → 1.7만 토큰). 요약에 7개 항목 모두 |
| 한 줄 영어(1,070자) | 일반 메시지로 처리됨 |
| 한 줄 영어, 줄인 판(582자) | `/compact`로 실행됨(6.4만 → 1.7만 토큰). 요약에 7개 항목 모두 |

그래서 프롬프트를 한 줄로 바꾸고 영어판을 582자로 줄였다. 앞으로 문구를 고쳐도 600자를 넘지 않도록 테스트를 더했다. 다른 화면(데스크톱 앱, IDE)에서의 붙여 넣기는 확인하지 않았다.

### `v0.2.0` 공개와 회귀, `v0.2.1` (2026-11-23)
- **`v0.2.0`:** PR #10을 머지하고(`58836ba`), `main` CI 통과 뒤 태그를 올렸다. 승인 뒤 릴리스 잡과 tap 갱신(0.2.0)이 모두 성공했다. 공개 자산의 서명·공증·Gatekeeper와, 앱에 들어간 프롬프트가 시험한 두 문장인 것을 확인했다. 이 기기는 `brew upgrade`로 0.2.0이 되었다.
- **회귀:** 사용자가 팝오버를 열자 내용이 사라지고 설정·종료 버튼만 보였다. 브랜치 리뷰 반영(팝오버 최대 높이)에서 내용을 `ScrollView`에 넣었는데, 메뉴 막대 창이 내용보다 작은 높이를 제안하면 스크롤 영역이 그 높이까지 줄어든다. 테스트와 스냅숏은 제약 없는 크기(`fittingSize`)로만 재서 이 경우를 놓쳤다.
- **수정(`v0.2.1`):** 스크롤 영역의 높이를 내용 높이로 정하고, 최대 높이에서만 멈추게 했다(`fixedSize`와 `frame(maxHeight:)`). 작은 높이를 제안받는 경우를 재현하는 테스트(`smallProposalDoesNotCollapse`)를 먼저 써서, 고치기 전 코드에서 실패하는 것을 확인했다.
- **확인의 한계:** 이 기기에서는 프로그램이 메뉴 막대 항목을 누를 권한이 없어, 실제 창은 `v0.2.1` 설치 뒤 사용자 화면으로 확인한다.
