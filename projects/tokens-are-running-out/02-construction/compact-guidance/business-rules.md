# Business Rules — 큰 세션 정리 안내

> Build Spec [`build-spec-index.md`](build-spec-index.md)의 아티팩트. 규칙 ID는 `BR-C`(compact)로 시작한다. 2-3의 `BR-E`(만료 경고)와 `BR-S`(설정)는 그대로 유효하다.

## 대상
- **BR-C1 기준:** 실행 중인 세션 가운데, 마지막 메인 호출의 컨텍스트(입력 + 캐시 읽기 + 캐시 쓰기)가 **200,000 토큰 이상**인 세션만 큰 세션이다. 199,999는 아니고, 200,000은 맞다.
- **BR-C2 실행 중:** 레지스트리를 읽을 수 있으면 상태와 무관하게 실행 중인 모든 세션이 후보다. 작업 중인 세션도 포함한다. 같은 세션 ID를 두 프로세스가 열고 있으면 한 번만 보인다.
- **BR-C3 레지스트리 없음:** 레지스트리를 읽을 수 없으면, 최근 1시간 안에 호출이 있는 메인 세션을 후보로 하고 상태를 `.unreadable`로 둔다. 만료 경고의 대체 경로와 같다.
- **BR-C4 마지막 호출 없음:** 색인에 호출이 없는 세션(새로 연 세션 등)은 보이지 않는다.
- **BR-C5 정렬과 개수:** 컨텍스트가 큰 순서, 같으면 세션 ID 순서다. 최대 5개를 보이고, 넘치면 "세션 N개 더 있음"을 보인다. 만료 경고와 같은 개수 규칙이다.

## 수치
- **BR-C6 호출당 다시 읽는 비용:** `contextTokens × 캐시 읽기 단가`(정가). 모델은 마지막 호출의 모델이다. 장문 구간이 있는 모델은 `promptTokens = contextTokens`로 구간을 고른다.
- **BR-C7 가격 없는 모델:** 가격표에 없는 모델은 대체 모델 가격으로 계산하고, 금액을 "추정"으로 표시한다. 기존 만료 경고의 표기 규칙과 같다.
- **BR-C8 사실만:** 크기와 정가 기준 비용만 보인다. "아낄 수 있다", "줄어든다" 같은 금액 단정은 하지 않는다(반목표 5번). 시점 안내는 동작을 설명한다. 예: "돌아와서 다시 만드는 것은 요약뿐이다."

## 프롬프트와 복사
- **BR-C9 프롬프트 내용:** `CompactPrompt.text`는 [domain-entities](domain-entities.md#compactprompt)의 문자열과 글자 단위로 같다. 한국어는 시험한 A2다. 세션 제목이나 대화 내용 같은 세션 정보는 넣지 않는다.
- **BR-C10 언어:** 앱의 현재 언어를 따른다(영어 기본, 한국어 지역화).
- **BR-C11 복사:** 사용자가 버튼을 누를 때만 클립보드에 쓴다. 앱은 `/compact`를 실행하지 않고, 세션에 입력을 보내지 않으며, 다른 앱을 조작하지 않는다.
- **BR-C12 복사 확인:** 누른 버튼의 이름이 2초 동안 "복사됨"으로 바뀐다. VoiceOver에는 "정리 프롬프트를 복사했습니다"를 알린다. 움직임만으로 알리지 않는다.

## 위치
- **BR-C13 ① 큰 세션 영역:** 큰 세션이 하나 이상일 때만 보인다. "곧 캐시가 만료되는 세션" 아래, "사용량의 원인" 위에 둔다.
- **BR-C14 ② 안내 줄:** 만료 경고의 첫 줄(안내 문장이 붙는 줄)이 상태 `.idle`이고 `contextTokens >= 200,000`이면, 안내 문장 아래에 "떠나기 전에 정리" 문장과 복사 버튼을 붙인다. 다른 줄에는 붙이지 않는다. ①에도 같은 세션이 나오기 때문이다.
- **BR-C15 오류 상태:** 색인 오류, 기록 없음, 첫 색인 중에는 ①과 ②가 보이지 않는다. 기존 화면 상태 규칙을 따른다.

## compact 뒤의 상태 (2-3 계약 확장)
- **BR-C17 compact 표시:** 세션의 메인 기록에서 마지막 호출보다 뒤에 compact 표시(`marks`)가 있으면, 그 세션은 "캐시가 비워져 다음 메시지를 기다리는" 상태다. 이런 세션은 ① 큰 세션 영역에 보이지 않고, ② 안내 줄도 붙지 않는다. 다음 호출이 기록되면 그 호출의 크기로 다시 판단한다.
- **BR-C18 만료 경고에도 적용:** 같은 세션은 만료 경고(2-3 BR-E)에서도 빠진다. compact 뒤 다음 메시지는 요약만 다시 쓰므로, "62만 토큰에서 다시 만든다"는 경고와 예약된 알림은 틀린 말이 된다. 알림은 기존 동기화 규칙에 따라 취소된다. 이것은 2-3의 만료 경고 계약을 넓히는 변경이다([DECISIONS](../../DECISIONS.md) 2026-11-23).

## 붙여 넣기
- **BR-C19 붙여 넣기 확인:** 구현 전에, 복사한 여러 줄 프롬프트를 대화형 Claude Code 세션에 붙여 넣었을 때 `/compact <지시>`로 실행되는지 확인한다(§4 첫 항목).
- **BR-C20 대안:** 여러 줄이 한 명령으로 읽히지 않으면, 같은 문장을 공백으로 이어 한 줄로 만든다. 단어는 바꾸지 않으므로 블라인드 평가는 다시 하지 않고, 편차 로그에 남긴다(AI 판단).

## 지키는 선(검증 대상)
- **BR-C16:** 이 기능은 네트워크, `~/.claude` 쓰기, 대화 본문 읽기를 늘리지 않는다. `check-anti-goals.py`와 `check-binary.sh`가 통과해야 한다.
