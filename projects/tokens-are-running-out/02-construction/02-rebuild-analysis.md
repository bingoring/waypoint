### 2-2에서 새로 확인한 사실과 1-2 계약 정정
- **캐시 읽기 단가는 모델마다 다르다.** 설계 입력과 1-2는 "캐시 읽기 ×0.1"을 모든 모델에 적용했다. 공식 가격표는 다음과 같다.

| 모델 | 입력 | 5분 쓰기 | 1시간 쓰기 | 캐시 읽기(입력 대비) | 출력 |
|---|---|---|---|---|---|
| Claude Opus 5.5 | $4 | $5 | $8 | $0.20 (0.05배) | $20 |
| Claude Opus 5 | $5 | $6.25 | $10 | $0.50 (0.1배) | $25 |
| Claude Sonnet 5.5 | $2 | $2.50 | $4 | $0.10 (0.05배) | $10 |
| Claude Haiku 5.5 (프롬프트 10만 토큰 이하 / 초과) | $0.10 / $0.50 | $0.125 / $0.625 | $0.20 / $1 | $0.01 / $0.05 | $0.50 / $2.50 |
| Claude Fable 5.2 | $8 | $10 | $16 | $0.20 (0.025배) | $40 |
| Claude Fable 5.1 | $10 | $12.50 | $20 | $0.25 (0.025배) | $50 |

  - 출처: https://platform.claude.com/docs/en/about-claude/pricing (조회일 2026-11-17, 확인 수준: 공식 확인). 단위는 백만 토큰당 USD다. 4.x 이후 21개 모델을 가격표에 넣는다.
  - **1-2 계약 정정:** CostWeights는 "모델별 공식 가격표"다. 캐시 쓰기 배수(5분 1.25배, 1시간 2배)는 모든 모델에서 같고, 캐시 읽기 배수와 Haiku 5.5의 긴 프롬프트 구간은 모델마다 다르다.
- **실제 기록에는 여러 모델이 섞여 있다.** 전체 기간 기준 메인 세션은 Opus 5.5, Opus 5, Fable 5.2·5.1을 썼고, 서브에이전트는 Opus 5.5, Sonnet 5.5(7,104건), Fable 5.1, Haiku 5.5를 썼다. 그래서 모델별 가격이 필요하다.
- **fast mode와 미국 전용 추론은 0건이다.** `usage.speed`는 모두 `standard`였고, `inference_geo`는 `global` 또는 `not_available`이었다. 그래서 v1 가격표는 표준 요금만 다룬다.
- **가격을 반영하면 수치가 바뀐다.** 기준 기간(2026-11-10 ~ 11-17) 기준으로 다음과 같다. Opus 5.5의 캐시 읽기가 싸서 캐시 쓰기의 비중이 커졌기 때문이다.
  - 쉬었다 돌아온 캐시 재구축의 비용 비중: 17.0%(균일 가중치) → **23.9%**
  - 줄일 수 있었던 양: 5.5% → **7.8%**
  - API 정가 환산 비용: $616.33
  - 재구축 건수와 원인 분포는 그대로다(가격과 무관하다).
- **원인 불명 재구축이 실제로 있다.** 10월 기간에 8건이 나왔다(비용의 1.0%). v2의 버그 증거 정리 기능에 쓸 재료다.

### 결정 (작성자 판단, DECISIONS에 기록)
- **가격표 하나를 함께 쓴다.** 가격표 JSON 파일 하나를 앱(Swift 리소스)과 프로토타입이 함께 읽는다. 그래서 기준값이 어긋날 원인이 하나 줄어든다.
- **모델 ID는 가장 긴 접두사로 맞춘다.** 그래서 날짜가 붙은 예전 ID(예: `claude-sonnet-4-5-20250929`)도 맞는 가격을 찾는다.
- **표에 없는 모델은 보고한다.** 가격표에 없는 모델은 Claude Opus 5.5 가격으로 계산하고 "가격 미확인 모델"로 보고한다. 화면에서 그 사실을 알릴 수 있다.
- **Haiku 5.5는 프롬프트 길이로 구간을 고른다.** 입력, 캐시 읽기, 캐시 쓰기를 합친 프롬프트가 10만 토큰을 넘으면 높은 구간 가격을 쓴다(공식 규칙).
