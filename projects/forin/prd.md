# forin — Product Brief (PRD)

> 시드 제품 기획서. 상세 비주얼·화면·카피·상호작용의 단일 진실 공급원은
> [`inputs/design-handoff_v2/`](inputs/design-handoff_v2/) 핸드오프 문서다.
> 본 문서는 Inception 스테이지의 제품 입력물 역할을 한다.

## 한 줄 정의

해외(우선 미국) 취업을 준비하는 의료 종사자(우선 간호사)를 위한,
픽셀아트 병원을 탐험하며 임상 영어를 연습하는 **모바일 게임형 언어 학습 앱**.

## 문제 / 동기

- 한국 간호사가 미국 등으로 이직할 때, 시험 영어가 아니라 **실무 임상 영어**
  (통증 사정, SBAR 인계, 트리아지, 투약 계산 등)에서 막힌다.
- 기존 어학 앱은 임상 맥락·역할극·현장 상황이 없어 실전 전이(transfer)가 약하다.

## 타깃 사용자

- **1차:** 미국 취업을 준비하는 한국 간호사.
- 확장: 기타 의료 직군, 기타 목적지 국가 (온보딩에서 언어/목적지/직군 선택으로 일반화).

## 핵심 경험 루프

```
캠퍼스(병원 야외 맵) 탐험
  → 부서 인테리어 입장 (ER / OR / ICU / Pediatrics / Pharmacy)
    → "!" 핫스팟 진입
      → 시나리오 브리핑
        → 비주얼 노벨 다이얼로그  ⇄  다이얼로그 중간 미니 퀴즈
          → 시나리오 클리어
            → 성장 (XP · 평판 · 자격 · 스티커 보드)
```

## 메인 앱 구조 (하단 탭)

| 탭 | 역할 | 상태 |
|---|---|---|
| 캠퍼스 (Campus) | 맵 탐험 → 부서 인테리어 → 시나리오 플레이 | 설계 완료 |
| 상황판 (Event Board) | 매일 자동 갱신되는 시나리오 목록 | 설계 완료 |
| 리뷰랩 (Review Lab) | 오답노트(AI 교정 문장)의 간격 반복 복습 — PhraseCard·마스터리·🔊TTS·🎤따라말하기 | 설계 완료 |
| 나 (Profile) | 프로필(홈)·평판·커리어 패스·뱃지; **성장 리포트는 나 탭의 푸시 하위뷰**(별도 탭 아님) | 설계 완료 |

## 온보딩 흐름

```
Splash → Login(소셜 원탭) → Language/Destination → Job select → Level 진단
```

## 미니 퀴즈 (다이얼로그 중간 삽입)

**유형(8종):** 문장 조립 · 매칭 · 바이탈 라벨링 · 트리아지 · 해부 라벨링 ·
SBAR 순서 맞추기 · 듣고 입력(listen-and-type) · 투약 계산(dosage calc).

**콘텐츠 전략 — 대량 · 고다양성:**
- 퀴즈 뱅크는 **클수록 좋다 — 1000+ 문항을 목표**로 한다. 간호사가 해당 상황·병동에서
  반드시 알아야 하는 지식을 최대한 폭넓게 퀴즈화한다.
- 사용자는 **매일** 앱을 켜 그날의 상황을 푼다. 매번 같은 퀴즈가 반복되면 지루하므로,
  같은 유형이라도 항목·보기·맥락에 **최대한의 다양성(variation)**을 부여한다.
- 함의: 시나리오와 퀴즈를 느슨히 결합하고, 퀴즈를 **병동·주제·난이도로 태깅**해 풀(pool)에서
  변형·샘플링할 수 있는 콘텐츠 구조가 필요하다(도메인 모델 1-2에서 구체화).

## 상황 · 환자 이벤트 (핵심 콘텐츠)

forin의 학습 단위는 **"상황·환자 이벤트"**다. 현업에서 일할 의료인을 타깃하므로 **전문성**이
핵심이며, 폭넓고 다양한 이벤트를 철저히 조사해 준비한다. 상세 카탈로그·스키마·관계 모델은
[`events-catalog.md`](events-catalog.md)에서 관리한다.

**규모 · 다양성:**
- MVP에 **최소 300개**의 상황·환자 이벤트를 준비한다.
- 범위 예: **병원 비상 코드**(코드 블루/레드/핑크/그레이/옐로우/실버 등), **임상 상황**
  (흉통·패혈증·낙상·투약 오류·아나필락시스·수혈 반응·소아 발열·정신과적 초조 등),
  **대인 상황**(진상 환자·진상 의사·보호자 갈등·언어 장벽), **시설 이벤트**(화재 등).
  ※ 비상 코드 명칭은 병원·지역마다 다름 — 카탈로그에서 표준/주의 함께 표기.

**진행(progression) · 관계:**
- 초반에는 **필수·빈발** 상황을 배치하고, 해결한 사용자에게 **심화** 상황·환자를 제공.
- 각 이벤트의 **선행/연관 관계**를 관리해, 해결 후 연관 이벤트를 이어 제공 → 만족도·몰입↑
  (도메인 모델 1-2에서 prerequisite/관계 모델로 구체화).

**전달(delivery) 모델 — 권고: 하이브리드 (게이트에서 확정):**
- **메인 루트** — 항상 열린 커리큘럼 진행 경로(필수→심화, 선행관계 기반). 스킬 빌딩의 backbone, 리셋 없음.
- **일일 이벤트** — 매일 00:00(로컬) 갱신되는 3~5개 상황(레벨·병동·진행도 가중 샘플링). 습관 루프.
- **보상형 광고** — 일일 이벤트 소진 시 광고 시청으로 +N회 추가(burnout 방지 일일 상한).
  핵심 학습(메인 루트)은 **항상 무료**, 광고는 더 풀고 싶은 사용자를 위한 옵션이자 초기 수익화.
- 근거: 메인 루트=성취·리텐션, 일일=신선함·습관, 광고=참여 연계 수익화 → "계속 학습·실력 향상" 목표에 부합.

## MVP 범위

**포함:** 온보딩, 캠퍼스/인테리어 탐험, 시나리오 브리핑→다이얼로그→퀴즈→클리어 루프,
성장 시스템(XP/평판/자격/스티커), 상황판, 프로필 + 성장 리포트,
**AI 대화 + 음성(🎤/🔊) + AI 문맥 교정**, **리뷰랩(AI 교정 기반 간격 반복 오답노트)**,
상황·환자 이벤트 콘텐츠 + 하이브리드 전달.

**리뷰랩 — 설계 완료(`screens-review-lab.jsx`).** 시나리오에서 나온 **AI 교정 문장**을
PhraseCard로 만들어 SM-2식 간격 반복으로 복습. 데일리 복습 허브, 카테고리 필터,
마스터리 3-pip, 🔊 TTS, 🎤 따라 말하기(녹음·발음 비교), ★ 즐겨찾기.

## AI / LLM 레이어 — forin의 핵심 (MVP)

> **AI와 대화하며 상황을 해결**하고, 그 대화를 **AI가 문맥에 맞게 교정**하는 것이 forin의
> 핵심 가치다. 리뷰랩 카드도 이 교정에서 나온다. → 전부 MVP에 포함하며, 이 레이어는
> **확장성 있는 설계와 적절한 디자인 패턴**(제공자·모델 교체 가능, 비용·지연 통제)에
> **개발 리소스를 집중 투자**한다.

- **AI 대화(free-speak)** — 시나리오의 목표·가드레일 안에서 LLM이 자연스러운 대화를 이끈다.
  자연스러움이 중요하므로 상대적 **고급 모델** + 스트리밍 응답.
- **AI 문맥 교정** — 사용자 발화/답안을 문맥에 맞게 교정 → 리뷰랩 카드 생성. 비용 효율 위해 **저가 모델**.
- **음성** — 🎤 따라 말하기(STT·발음 비교) + 🔊 TTS. `expo-av`/`expo-speech` 우선, 부족 시 최신 클라우드.
- **아키텍처 원칙** — LLM·STT·TTS는 **포트/어댑터로 추상화**해 제공자·모델을 교체 가능하게(모델 티어링
  라우팅). 키·오케스트레이션은 서버(Go)에서, 비용·지연·캐싱·프롬프트 템플릿·가드레일을 일급으로 관리.
  세부는 `prd-tech.md` / 아키텍처 게이트(1-3).

## 비기능 요구 (초기)

- 한국어 UI 우선, 학습 콘텐츠는 영어. (i18n 일반화는 추후.)
- 오프라인 친화적 콘텐츠 전달이 바람직(시나리오는 정적 저작 콘텐츠).
- 고정밀(high-fidelity) 픽셀아트 — 디자인 토큰·컴포넌트는 핸드오프에서 final.

## 비목표 (현재)

- 실시간 멀티플레이/소셜(친구·랭킹) 기능, 인앱 결제·구독은 현 MVP 범위 밖
  (초기 수익화는 보상형 광고부터 — '상황·환자 이벤트' 참고).
- 강사/관리자 대시보드는 현 범위 밖.
- 시나리오를 LLM이 **무에서 통째로 생성**하는 것은 범위 밖(시나리오의 구조·목표·가드레일은
  저작; 그 안의 대화·교정은 LLM이 담당 — 위 'AI/LLM 레이어' 참고).
