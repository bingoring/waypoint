# Business Rules — 평판 획득

## 1. 규칙 표

| ID | 규칙 |
|---|---|
| R-1 | 평판은 **시나리오 클리어(등급 확정) 시점에만** 움직인다 |
| R-2 | 한 번의 클리어는 **정확히 한 차원**만 움직인다 — 여러 축이 동시에 흔들리면 원인을 알 수 없다 |
| R-3 | 차원은 `Resolve(profession, personaRole, acuity)`가 정한다. **부서 문자열은 입력이 아니다** |
| R-4 | 긴급도가 `routine`이 아니면 **긴급 차원이 우선** — 응급 상황에서 중요한 건 대응이지 상냥함이 아니다 |
| R-5 | 값은 항상 **0~100으로 클램프** |
| R-6 | 델타는 등급에서 파생한다. 합격선 이상은 +, 미만은 − |
| R-7 | 시간 감쇠 없음 (확정) |
| R-8 | 미등록 직업이면 **아무 것도 적용하지 않는다**(조용히 스킵) — 잘못된 축을 움직이느니 안 움직이는 게 낫다 |
| R-9 | 평판 적용 실패가 **클리어를 실패시키지 않는다** — 학습 결과가 부가 효과 때문에 사라지면 안 된다 |

## 2. 검증

| 입력 | 규칙 | 실패 시 |
|---|---|---|
| `acuity` | allowed-set 밖이면 `routine`으로 취급 + 로깅 | 조용한 폴백(콘텐츠가 앱을 깨지 않는다) |
| `score` | 0~100 밖은 클램프 | — |
| `profession` | 카탈로그에 없으면 스킵(R-8) | — |

## 3. 불변식

- **INV-1** 적용 후 값 ∈ [0, 100]
- **INV-2** 한 클리어가 바꾸는 차원 수 = 1 (또는 0: 스킵 시)
- **INV-3** 델타는 등급의 단조 함수 — 더 잘한 클리어가 더 적게 오르지 않는다

## 4. 엣지케이스

| 상황 | 처리 |
|---|---|
| 같은 시나리오 반복 클리어 | 그대로 적용. 반복 학습을 벌하지 않는다(상한이 클램프로 이미 있음) |
| 등급 없는 직접 클리어(`grade < 0`) | 평판 미적용 — 채점되지 않은 것을 평가할 수 없다 |
| 페르소나 역할 미기재 | 클라이언트(환자) 차원으로 — 대부분의 시나리오가 그렇다 |
| 값이 이미 100 | 클램프. 에러 아님 |
