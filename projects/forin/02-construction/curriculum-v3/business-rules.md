# 비즈니스 규칙 — 커리큘럼 v3

> curriculum-v2의 R1~R17을 대체한다. 유지되는 것은 명시하고, 바뀐 것은 v2 번호를 병기한다.

## 분류·조립 규칙

| # | 규칙 | 근거 |
|---|---|---|
| R1 | **한 상황은 정확히 한 주제(`theme`)에 속한다.** 주제=학습 단위이므로 중복 소속은 진도 이중 계산을 낳는다 | U1 · domain §1 |
| R2 | **한 주제는 상황 20개 이상을 갖는다(U2).** 20개 미만이면 인접 주제와 병합하거나 보강 생성한다(P2). 상한은 없다 — 실무상 필요하면 40개 이상도 허용(U5) | U2·U5 |
| R3 | **모든 상황이 정확히 한 주제로 덮인다. 고아 0.** 태그 없는 상황이 있으면 조립이 아니라 **테스트가 실패**한다. v2 R3("층의 주제를 정확히 한 번씩")을 상황 단위·전량으로 확장 | E1 |
| R4 | **주제는 3계층 중 하나(`track`): core · depth · collab.** core는 부서 무관(공통 1회), depth는 `dept`로 부서에 매임, collab은 `dept`=내 부서 + 상황 `collabWith`=상대 부서 | U3 |
| R5 | **주제 이름은 그 주제의 성격에서 나온다.** "첫 만남·사정"처럼 모든 주제에 쓸 수 있는 이름은 금지. 레지스트리 `name`이 트랙 안에서 유일 | v2 R4 계승 |
| R6 | **주제 키(`key`)는 안정 식별자.** 이름에서 생성하지 않는다 — 이름을 다듬어도 상황 태그·이어하기 대상이 유지돼야 한다 | v2 R3(Key) 계승 |
| R7 | **주제 조립은 명시 태그 그룹핑이다. 프록시(Diff/Acuity/Role) 유추 금지.** v2 D6(유추가 14/29 부서에서 깨짐)의 재발 방지 — 조립은 `theme` 태그만 읽는다 | v2 D6 |

## 주제 내 구조 규칙 (난이도 계단, U6)

| # | 규칙 | 근거 |
|---|---|---|
| R8 | **주제 안은 난이도 계단(Lv1→2→3).** 상황을 `briefing.difficulty`(1·2·3)로 티어에 나눈다. 해당 난이도 상황이 없으면 그 티어는 생략 | U6 |
| R9 | **티어는 순차 해금.** 앞 티어의 필수 스텝을 **충분히**(임계=그 티어 필수 스텝의 전부) 통과해야 다음 티어가 열린다. 티어 안 스텝은 동시 열림(계단 안에서는 순서 강제 안 함) | U6 |
| R10 | **주제 끝 스텝은 주제 시험(`boss`)** (`Theme.Exam`이면). 시험 통과 = 그 주제 PASSED 도장 | v2 R6 계승·주제 단위화 |
| R11 | **중간 `quiz`는 `optional`.** 진도를 막지 않고 `Total`/`Done`은 필수 스텝만 센다 | v2 R10 계승 |

## 해금 규칙

| # | 규칙 | 근거 |
|---|---|---|
| R12 | **주제와 트랙은 전부 열려 있다.** `CurriculumState.State`에 `lock` 없음(passed·here·open). 잠금은 주제 안 난이도 계단(R9)에만 존재 | v2 R9 계승 |
| R13 | **공통 코어는 부드러운 선행 관문.** 부서 심화 진입 전 코어 주제를 먼저 하도록 **권장**(여정에서 앞단 배치·이어하기 우선)하되, 강제 잠금은 아니다 | U3 |
| R14 | **부서 시험(트랙 마일스톤)은 그 트랙의 필수 주제가 전부 passed면 open.** 통과 시 여정 지도에 부서 도장 | v41 08 §5 · domain §5 |

## 이어하기 규칙 (v2 계승, 주제 단위화)

| # | 규칙 | 근거 |
|---|---|---|
| R15 | 이어하기 대상 = **가장 최근 시도한 상황이 속한 주제.** 클리어 여부 무관(실패한 시도도 "내가 하던 곳") | v2 R11 |
| R16 | 그 주제가 완료됐거나 최근 시도가 어느 주제에도 안 속하면 → **미완료 주제 중 학습 순서상 첫 번째**(공통 코어 우선, R13) | v2 R12 |
| R17 | 시도 이력이 없으면 → **공통 코어의 첫 주제.** 신규 사용자의 명확한 첫 행동 | v2 R13 |
| R18 | 이어하기 대상은 **전체에서 정확히 하나**(모든 주제 완료 시에만 0, 그때 홈은 휴식 카드) | v2 R14 |

## 표시·회귀 규칙

| # | 규칙 | 근거 |
|---|---|---|
| R19 | **스텝 이름은 시나리오 `title`에서 파생**(` · `/` — ` 앞 조각). 손저작 안 하므로 v2 D1(이름-내용 불일치) 원천 소거 | v2 R15 결함 |
| R20 | **자유 탐방 없음.** 부서 시트의 "커리큘럼 밖 상황" 목록은 사라진다 — 모든 상황이 주제에 편입되므로 갈 곳이 생겼다 | U4·E1 |
| R21 | **진도 표시 변화 허용.** 진도는 `scenario_attempts`에서 파생 → 마이그레이션 불필요·클리어 기록 무손실. 주제 경계가 바뀌어 "완료 수"만 달라진다 | v2 R17 |
| R22 | **결정성.** 같은 입력(themes.yaml + 태그)에 같은 카탈로그. 정렬은 명시 필드(`order`·`difficulty`·`id`), 맵 순회 금지 | index §3 NFR |
