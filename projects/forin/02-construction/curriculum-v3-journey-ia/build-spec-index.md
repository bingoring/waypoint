# Build Spec — 여정 지도 2단 구조 (P3-C)

    status: READY
    depth: standard
    supersedes: curriculum-v3-journey의 §1 컴포넌트 트리와 §5 상호작용 표 일부

착수 배경과 결정은 `../curriculum-v3-journey/NEXT-ia-change.md`에 있다. 이 문서는 그 결정을 지을 수
있는 형태로 옮긴 것이다.

## 1. 무엇을 고치는가

여정 지도가 **주제 35개를 정거장으로 놓고 점선으로 잇는다.** 길이라는 형태는 순서를 뜻하는데, 규칙은
정거장을 잠그지 않는다(J1·J3). **형태가 규칙보다 강하게 말한다.**

주제에도 권장 순서는 있다(`themes.yaml`의 `order`, 부서 코어가 트랙을 이끈다). 그러니 길이 거짓말은
아니지만 **"권하는 순서"를 "정해진 순서"처럼 과장한다.**

반면 **주제 안은 진짜로 선형이다.** 난이도 계단이 실제로 잠긴다(J2). 강한 은유는 그쪽에 있어야 한다.

## 2. 바꾼 뒤의 모양

**1단계 — 일터 탭: 부서의 주제 목록.** 길이 아니라 묶인 목록.
**2단계 — 주제 화면: 정거장 뷰.** 지금의 지도를 여기로 옮긴다. 정거장 = 그 주제의 상황들.

## 3. 규칙

| | 규칙 | 왜 |
|---|---|---|
| **K1** | **1단계는 길을 그리지 않는다.** 주제 사이를 잇는 선·화살표·순번을 쓰지 않는다. | 주제는 아무 데나 들어갈 수 있다. 선을 그으면 화면이 규칙과 다른 말을 한다. |
| **K2** | **권유는 하나만 한다.** "다음에 할 주제" 하나를 표시하고, 나머지에는 순서를 암시하는 표시를 쓰지 않는다. | 권장 순서는 실재하므로 버리지 않는다. 다만 사슬이 아니라 한 점으로 말한다. |
| **K3** | **묶음은 `track`을 따른다** — 부서 코어 먼저, 부서 심화 그다음. | 이미 콘텐츠가 갖고 있는 구분이고, 코어를 먼저 하라는 권유가 묶음만으로 전달된다. |
| **K4** | **2단계 안에서만 선형이다.** 정거장 사이 점선, 걸어가는 캐릭터, 끝의 구간 시험 깃발은 전부 2단계의 것이다. | 여기서는 계단이 실제로 잠기므로 선형이 진실이다. |
| **K5** | **잠긴 스텝으로는 걸어가지 않는다.** 누르면 짧게 거절하고 제자리에 둔다. | 갈 수 없는 곳으로 걸어가는 연출은 잠금을 부정한다. |
| **K6** | **걷는 시간은 지연을 가리는 데 쓴다.** 누르는 즉시 요청을 보내고 그 사이에 걷는다. | 걷기를 끝내고 요청하면 지연이 더해지기만 한다. 연출이 비용이 아니라 이득이 되는 자리다. |
| **K7** | **모션 줄이기 설정을 존중한다.** 켠 기기에서는 걷지 않고 즉시 이동한다. | `engine/AnimatedFace.tsx`가 이미 이 설정을 읽고 변경까지 구독한다. 같은 방식을 쓴다. |
| **K8** | **부서를 고르는 방법은 여전히 하나다**(J5). 1단계 상단 바와 자유 탐방 칩은 같은 경로를 탄다. | 이미 지켜지는 규칙이고 이 변경이 깨뜨리면 안 된다. |

## 4. 서버

**변경 없다.** 두 엔드포인트가 이미 이 경계로 나뉘어 있다.

- `GET /me/journey` → 주제별 개수(`track.curricula[]`: 이름·done·total·state·tiers·resume) = **1단계가 쓸 것**
- `GET /me/journey/stations/{themeKey}` → 그 주제의 스텝 행 = **2단계가 쓸 것**

계약도 그대로다. 이 변경은 표현의 문제다.

## 5. 1단계 — 주제 목록

- `부서 코어` / `부서 심화` 두 묶음, 세로 스크롤. 묶음 판정은 `curricula[].track`.
- 카드마다: 주제 이름 · 진행도(고정 개수 네모, `NbProgScale`) · `done/total`.
- **권유 표시는 `resume`가 참인 주제 하나에만.** 서버가 트랙당 0개 또는 1개를 보장한다.
- 상단에 목표 부서 바(그대로), 하단에 자유 탐방 칩(그대로).
- 카드를 누르면 2단계로 민다.

**잠금 없음.** 어떤 카드든 눌린다(J1).

## 6. 2단계 — 주제 화면

- 지금의 `JourneyMap`·`Station`·`PathSegment`·`MilestoneFlag`를 그대로 쓰되, **정거장이 스텝이 된다.**
- **스텝을 전부 그린다.** 한 주제가 41~47개이고 진행 전에는 그중 40여 개가 잠겨 있다. 그것을 줄이거나
  계단 단위로 묶자는 안을 검토했으나 **기각한다** — 앞이 다 잠겨 보이는 것은 결함이 아니라 **앞으로 할
  일이 보이는 것**이고, 그게 이 화면이 주는 동기의 근거다. 실제로 해야 하는 일들이므로 줄여 보일 이유가
  없다.
- 난이도 계단이 경로 위에서 드러나야 한다 — 어디부터 잠겼는지 보여야 K5가 말이 된다.
- 끝에 구간 시험 깃발.
- 뒤로 가면 1단계로 돌아온다.

**`StationSheet`는 이 화면에 흡수된다.** 시트가 하던 일(스텝 목록)이 곧 이 화면이므로 둘 다 두면 같은
것을 두 번 그리게 된다.

## 7. 걸어가는 캐릭터

- **학습자 자신의 아바타를 쓴다.** `useMyAvatar()` + `NbAvatar`가 이미 있다. 새 자산을 만들지 않는다.
- 마지막으로 진행한 스텝에 서 있는다. 주제를 다 끝냈으면 구간 시험 깃발 앞.
- 다음 스텝을 누르면 **점선을 따라 걸어가고**, 도착하면 상황 준비 화면이 뜬다.
- **첫 스텝은 화면 왼쪽 밖에서 걸어 들어온다**(읽는 방향과 같다).
- **이동 속도는 거리에 따라 정한다.** 한 칸 옆은 천천히, 40칸 밖에서 돌아올 때는 빠르게. 거리에 비례하되
  위아래를 묶어, 가까운 이동이 답답하지 않고 먼 이동이 지루하지 않게 한다. 주제가 47스텝까지 가므로
  비례만 두면 먼 이동이 견딜 수 없이 길어진다.
- 잠긴 스텝은 K5, 모션 줄이기는 K7.

## 8. 검증 규칙

| 입력 | 기대 |
|---|---|
| 1단계에 주제 35개 | 두 묶음으로 나뉘고, 주제 사이를 잇는 선이 없다 |
| `resume`가 참인 주제 | 정확히 하나만 권유 표시를 받는다 |
| `resume`가 없는 트랙(전부 통과) | 권유 표시가 0개. 지어내지 않는다 |
| 아직 안 간 주제 카드 탭 | 2단계로 이동한다(잠기지 않는다) |
| 2단계에서 잠긴 스텝 탭 | 걷지 않고, 짧게 거절한다 |
| 모션 줄이기 켬 | 걷지 않고 즉시 이동한다 |
| 스텝 목록이 빈 주제 | 화면이 서고, 지어낸 정거장이 없다 |
| 스텝 47개인 주제 | 47개가 다 그려진다. 줄이거나 묶지 않는다 |
| 1칸 이동과 40칸 이동 | 걸리는 시간이 다르되, 먼 이동에 상한이 있다 |

## 9. 하지 않는 것

- 서버·계약을 바꾸지 않는다.
- 부서 고르기 방식을 바꾸지 않는다(밀려 들어오는 화면 그대로).
- 주제 선택을 가로 칩으로 하지 않는다 — 35개는 가로 스크롤에 맞지 않는다. 전체 진도·묶음·찾기를
  모두 잃는다(`NEXT-ia-change.md`에 근거).
