# 비즈니스 규칙 — 커리큘럼 v3 라이브 전환 (P3-A)

> 라이브 전환이 지켜야 할 불변식. R-L* 는 이 스펙 고유 규칙. 기존 P1(R7·R22 등)·P2(R-P2-8 등) 규칙은
> 그대로 유효하며 여기서 반복하지 않는다.

## 포트·구조

- **R-L1** 라이브 소비자(HTTP 핸들러)는 구체 커리큘럼 패키지를 import하지 않는다. 오직 `learning.Journey`
  포트에만 의존한다. (전환 완료 후 `grep -rn 'internal/curriculum"' internal/adapters` = 0)
- **R-L2** `learning.Journey` 구현체는 정확히 하나(themed.Engine)다. 두 엔진 공존 금지. 구 형태(`/me/curriculum`
  BuildingGroup)는 엔진 위 **얇은 어댑터**로만 제공하며, 별도 계산 경로를 두지 않는다.
- **R-L3** 포트 메서드는 순수하다 — 부팅 캐시(Catalog)와 인자 `Progress`만으로 계산하며 I/O를 하지 않는다.
- **R-L4** 여정/스텝 응답 형태 타입의 주인은 도메인(learning)이다. 엔진·핸들러·계약이 이를 채우거나 매핑할
  뿐, 형태를 재정의하지 않는다.

## 파생 규칙 (하드코딩 금지)

- **R-L5** 커리큘럼·스텝·다음시나리오·가이드레벨·이어하기는 전부 (주제 레지스트리 + `theme` 태그 + 진도)에서
  파생된다. 시나리오 id를 나열하는 하드코딩 카탈로그(스텝 목록)는 존재하지 않는다.
- **R-L6** 스텝 이름은 그것이 가리키는 시나리오의 제목에서 파생된다(P1 R19 `stepName` 유지). 스텝 이름과
  시나리오 내용의 불일치가 원천적으로 불가능하다 — 구 `TestEveryStepNamesItsContent`가 잡던 결함 자체가
  발생하지 않는다.
- **R-L7** 정책(가이드·티어 해금·주제 시험)은 조립/해석 본문이 아니라 교체 가능한 정책 부품에 있다. 규칙
  변경이 엔진 함수 수정을 요구하면 안 된다.

## 확장 seam

- **R-L8** 새 부서·주제·상황은 데이터(themes.yaml + 태그)로만 추가된다. 엔진·핸들러·계약 코드 수정 0.
- **R-L9** 새 콘텐츠 소스(UGC USR-*·공유)는 같은 태그 스트림으로 유입된다(S1). 엔진은 소스를 구분하지 않는다.
  단, 시드/조립의 저작 스코프 게이트(P2 §0.6: 고아-0은 SCN-* 저작분에만 적용)는 유지된다.
- **R-L10** 새 트랙 종류·스텝 종류는 열린 문자열로 추가된다(S3·S4). 엔진은 track/kind 값을 열거로 강제하지
  않는다(확장성 > DB CHECK, 기존 원칙 [[feedback_extensibility]] 연장).
- **R-L16** 직업군(profession)은 1급 차원이다(S7). `Journey`는 직업군 하나의 범위이고, 라이브는 사용자
  직업군으로 `Journeys.For(prof)`를 통해 해석한다. 새 직업군은 `content/<prof>/` 추가만으로 붙으며 포트·핸들러·
  계약 코드는 바뀌지 않는다. themed Catalog 부팅의 `"nurse"` 하드코딩은 직업군 순회로 대체한다(잔존 금지).

## 동작 보존 (전환 리스크)

- **R-L11** 전환 전후로 `Next`·`Guidance`의 출력은 동일 입력에 대해 **의도된 차이만** 갖는다. L1에서 v2와
  themed를 대조하는 특성 테스트를 두고, 의도치 않은 회귀를 차단한다.
- **R-L12** 진도 오버레이(passed/here/open·티어 done/total·resume 정확히 1건)는 P1 Resolve 규칙(R15~R18)을
  그대로 따른다.

## 은퇴 (완료의 정의)

- **R-L13** 전환 완료 시 `internal/curriculum`(v2)·`catalog_gen.go` 생성·`cmd/gencontent`의
  `generateCurriculum`·가드 테스트는 저장소에 남지 않는다. 죽은 코드 방치 금지.
- **R-L14** 은퇴를 대체하는 엔진 불변식 테스트가 존재한다: 저작(SCN-*) 고아 0 · 모든 주제 상황 ≥ 임계 ·
  모든 스텝이 실재 시나리오로 해석 · 부서별 코어가 자기 부서 트랙을 이끎(P1 D-P2-D 테스트 유지).
- **R-L15** 은퇴 이후 어떤 부서를 seed 정본으로 전환해도 카탈로그 수동 재지정이 불필요하다(L-E1 종결). 이
  성질이 깨지면 전환이 불완전한 것이다.
