# 시나리오 콘텐츠 로드맵 — 목표 300+ (SoT)

시나리오는 forin의 **핵심 학습 자산**이다. 인테리어·퀴즈·상황판·대화 엔진은 모두 시나리오를 소비한다. 콘텐츠의 양·다양성이 곧 제품 가치이므로, 시나리오 확충을 **상시(ongoing) 최우선 작업**으로 계획에 고정한다. (사용자 지시, 2026-07-20: "적어도 300개는 되어야 한다.")

## 현황 (2026-07-20, 단계 B **완료 · 목표 달성 🎯**)
- **300 시나리오** · 30 quizzes(14 포맷) · 11 events. 전 부서(24) 커버.
- 부서별: ER 15 · OR/PEDS/ICU/PHARMA 각 14 · 신규 19부서 각 12.
- 다음: 단계 C(상시 운영) — 데일리 로테이션 품질·계절/이벤트성·실사용 로그 기반 보강·핫스팟 추가 배선.
- 파이프라인 검증 완료: yaml 저작 → `contentfile.Load` 검증(id·eventId·enum·briefing 왕복) → seed → 상황판 데일리 로테이션 → 브리핑/대화/퀴즈. **저작은 생성기+dict로 기계화** 가능(스크립트 경유).

## 목표
- **≥ 300 시나리오** (현 86 → 갭 ~214). 부서 평균 ~12개, 난이도(B1/B2/C1)·상황 유형 다양화.
- 각 시나리오: persona·briefing(dept·brief·difficulty·skills·rewards·reqs)·keyPhrases·steps(dialogue/quiz). 민감 도메인 가드레일.

## 저작 지침 (품질 기준)
- **임상 정확성** 우선. 실제 미국 병원 워크플로우·표현(SBAR·verbal order·read-back 등) 반영.
- **영어 라인**은 실제 현장에서 들리는 자연스러운 표현. keyPhrases는 학습 목표 문장.
- 민감 주제(임종·자해·부검·소아 응급)는 공감·비판단·안전 가드레일 필수.
- ID 컨벤션 `SCN-<DEPT>-NNNNN`, eventId는 건물/부서 이벤트 참조. 저작 후 반드시 로더 검증 + seed + 상황판/브리핑 렌더 확인.
- 생성기 활용(대량 저작): 소스/도메인 기반 dict → yaml 생성 → 검증. 서버 struct 변경 시 **API 재시작** 필수(실행 바이너리가 옛 struct면 jsonb 신규 필드 드롭).

## 배선/노출
- 인테리어 핫스팟(부서당 현재 1개) 추가 배선 → 각 부서 여러 시나리오 직접 진입.
- 상황판(board): `TodaysScenarios` 날짜 시드 로테이션이 전 부서 풀에서 12건 노출(구현 완료). 풀이 커질수록 로테이션 다양성↑.
- 건물 이벤트 `scenarios[]` 목록에 신규 시나리오 추가 유지.
