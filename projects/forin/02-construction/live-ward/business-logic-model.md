# 프레즌스 생명주기 — 폴링 + TTL

라이브 병동 프레즌스의 상태기계, Redis 스키마, 엔드포인트 계약을 정의한다. 핵심 원칙:
**하트비트의 지속 여부가 곧 온라인 여부다.** 별도의 명시적 "접속 종료" 신호에 의존하지 않고,
하트비트가 멈추면 TTL이 만료되며 자연히 이탈로 이어진다.

## 1. 두 관심사의 분리

| 관심사 | 언제 | 무엇 |
|---|---|---|
| **하트비트(내가 온라인인가)** | 앱이 **포그라운드**인 동안 전역 | 내 Redis 엔트리 TTL 갱신 |
| **로스터 폴링(누구를 보는가)** | **홈이 포커스**된 동안만 | 최근 활동 10인(자기 제외) 조회 |

병동은 홈에서만 보이므로 로스터는 홈에서만 읽는다. 그러나 내 표시 여부는 화면과 무관하게
앱 활성 상태에만 달렸다. 그래서 홈을 떠나 시나리오·퀴즈에 머물러도 하트비트가 계속 뛰어
병동에 남는다.

## 2. 상태 전이

```
[오프라인]
   │  앱 포그라운드 진입 (인증됨 · 옵트아웃 아님)
   ▼
[온라인·등록]  ── 하트비트 지속 (홈=6s GET /ward, 그 외=15s POST /ward/heartbeat)
   │                다른 화면으로 이동해도 하트비트 지속 → 계속 [온라인]
   │
   │  앱 백그라운드/종료
   ▼
[이탈 진행]  ── 선택적 POST /ward/leave 비컨 (즉시) │ 아니면 TTL 만료(≤40s)
   ▼
[오프라인]  ── 다른 사용자의 홈 로스터에서 사라짐 → 우측 이탈 애니메이션
```

- **등장**: 다른 사용자가 홈 로스터를 폴링할 때 새 uid가 나타나면 좌측 밖에서 등장.
- **이탈**: 로스터에서 uid가 사라지면 우측으로 이탈 후 언마운트.
- **크래시·강제 종료**: `leave` 비컨을 못 보내도 TTL이 정리한다. 유령 엔트리가 남지 않는다.

## 3. Redis 스키마

| 키 | 타입 | 용도 |
|---|---|---|
| `ward:live` | Sorted Set | member=uid, score=마지막 하트비트 epoch(초). 최근순 정렬·만료 판정 |
| `ward:av:<uid>` | String (JSON) | 해당 uid의 익명 아바타 스펙. TTL = 하트비트 TTL + 5s(로스터 읽을 때 존재 보장) |

**하트비트(등록/갱신):**
```
ZADD ward:live <now> <uid>
SET  ward:av:<uid> <avatarJson> EX 45
```
옵트아웃(숨김) 사용자는 이 두 쓰기를 **하지 않는다**(서버가 pref 확인 후 스킵).

**로스터 읽기(최근 10, 자기 제외):**
```
ZREMRANGEBYSCORE ward:live -inf (now-40)      # 만료 evict (지연 정리)
ZREVRANGE ward:live 0 10 WITHSCORES           # 최근순, 자기 제외 위해 1개 여유
→ 자기 uid 제거, 상위 10개로 컷
MGET ward:av:<uid> ...                         # 아바타 배치 조회
```

TTL은 zset score 기반(now-40 이전은 만료)으로 판정한다. 별도 키 만료 알림(keyspace
notifications)에 의존하지 않아 단순하다. 아바타 String의 `EX 45`는 안전망일 뿐 진실의
근원은 zset score다.

## 4. 엔드포인트 계약

모두 인증 필요(uid는 토큰에서). 프레즌스 쓰기는 **best-effort** — 실패해도 다른 흐름을
막지 않는다.

### `GET /ward`
홈에서 6초마다. 하트비트를 겸한다.
- 동작: (옵트아웃 아니면) 내 하트비트 갱신 → 로스터 조회.
- 응답: `{ "roster": [ { "id": string, "avatar": AvatarSpec } ], "self": AvatarSpec }`
  - `roster`: 최근 활동 최대 10인, **자기 제외**.
  - `self`: 클라이언트가 로컬 렌더에 쓸 내 아바타(서버 정본과 동기화용, 선택적).
- Redis 불가: `roster: []` 반환(내 캐릭터만 보임). 200 유지.

### `POST /ward/heartbeat`
홈이 아닌 포그라운드 화면에서 15초마다. 쓰기 전용.
- 동작: (옵트아웃 아니면) 내 하트비트 갱신.
- 응답: 204. 옵트아웃이면 등록 없이 204.

### `POST /ward/leave`
앱이 백그라운드로 갈 때 1회, best-effort 비컨.
- 동작: `ZREM ward:live <uid>` + `DEL ward:av:<uid>`.
- 응답: 204. 실패해도 무시(TTL이 결국 정리).

## 5. 도메인 로직 (`internal/domain/ward`)

Redis 어댑터와 분리해 순수 로직을 테스트 가능하게 둔다.

- `Roster(ctx, viewerID) ([]Member, error)` — 저장소에서 최근 엔트리를 받아 **자기 제외**하고
  상한 10으로 컷. 아바타 스펙을 `normalizeAvatarSpec`으로 정규화(네트워크·저장 값 방어).
- `Touch(ctx, uid, avatar, hidden) error` — hidden이면 no-op, 아니면 저장소 갱신.
- `Leave(ctx, uid) error`.
- 상한·자기 제외·정규화는 도메인에서, TTL·zset 연산은 저장소(W4)에서.

## 6. 옵트아웃

기본값은 **공개(익명)**. 나 탭에 토글을 둔다. 저장 위치는 기존 `colleague_prefs`에 컬럼
추가 또는 프로필 플래그 중 구현 시 확정(마이그레이션 최소화 우선). 서버는 하트비트 처리 시
이 플래그를 읽어 숨김이면 등록을 건너뛴다. 클라이언트도 숨김이면 하트비트를 아예 보내지
않아 트래픽을 아낀다(이중 방어).
