핸드오프 v42가 확정한 플로우는 **G 바인더 서가 → E 차트 바인더 간지 → H 불규칙 우표 산책길**이다.
이 문서는 그 세 화면을 우리 콘텐츠와 규칙에 맞게 옮긴 것이다.

P3-C가 세운 경계(주제 밖은 목록, 주제 안은 선형)는 **그대로 유효하다.** v42는 그 경계를 바꾸지 않고
겉모습과 깊이 하나를 바꾼다.

## 1. 무엇이 달라지는가

지금은 두 단이다.

    일터 탭 = 목표 부서의 주제 목록  →  주제 화면(정거장)

v42는 세 단이다. **부서를 고르는 일이 화면으로 올라온다.**

    일터 탭 = 부서 서가(G)  →  부서 간지(E)  →  주제 산책길(H)

## 2. 핸드오프에서 빼는 두 가지

핸드오프의 도안 두 곳이 우리 콘텐츠와 어긋난다. 그대로 옮기면 **화면이 사실과 다른 말을 한다.**

| | 핸드오프 | 우리 콘텐츠 | 처리 |
|---|---|---|---|
| **X1** | `공통 필수` 카드 — "모든 부서가 공유, 어느 바인더에서 해도 한 번만" | 코어 주제는 부서마다 따로 있다(`core-safety-er`, `core-safety-icu` …). **부서 없는 공통 주제는 0건.** | **뺀다.** 공통 코어가 콘텐츠에 생기면 그때 넣는다 |
| **X2** | 주제 `locked` 상태, "앞 주제 완료 시 열림", 추천 순서 메모 | **주제는 잠기지 않는다**(J1·J3). 잠기는 것은 주제 안의 난이도 계단뿐이다(J2) | **뺀다.** 권유는 `resume` 하나에만 붙인다(K2) |

X2는 P3-C가 직전에 고친 결함이다. 되돌리지 않는다.

## 3. 규칙

| | 규칙 | 왜 |
|---|---|---|
| **V1** | **서가는 부서를 잠그지 않는다.** 29개 전부 열린다. | 부서 사이에는 선행 조건이 없다. 잠긴 자물쇠를 그리면 없는 규칙을 지어낸다. |
| **V2** | **여는 것과 정하는 것은 다르다.** 서가에서 바인더를 열면 그 부서를 볼 뿐, 저장된 목표는 바뀌지 않는다. 목표 변경은 `내 부서` 카드의 명시적 동작 하나뿐이다. | J4·J5. 둘러보다가 목표가 갈아치워지면 학습자가 자기 목표를 잃는다. |
| **V3** | **서가는 추가 요청을 하지 않는다.** `GET /me/journey` 한 번이 `goalDept` + `freeRoam[]{dept,passed,total}`로 29부서 전부와 진행도를 이미 담는다. | 부서 수만큼 요청을 내는 설계를 막는다. |
| **V4** | **간지는 요청 한 번.** `GET /me/journey?dept=<코드>`. 바인더를 열 때만 부른다. | 서가에서 미리 29번 부르지 않는다. |
| **V5** | **진행도 바는 줄을 접는다.** 한 줄에 다 넣지 않고 칸 크기를 유지한 채 여러 줄로 흘린다. | 주제가 35개다. 한 줄에 밀어 넣으면 칸이 획 하나보다 얇아진다. |
| **V6** | **개수를 배열에 박지 않는다.** 부서당 주제는 15~35개, 주제당 상황은 20~23개로 **서로 다르다**. | 핸드오프의 5·34·36은 예시 값이다. 고정하면 부서 절반이 잘린다. |
| **V7** | **우표 격자는 상황 수만큼 그린다.** 줄여 보이지 않고 줄바꿈으로 흘린다. | P3-C §6에서 이미 내린 판단이다 — 앞이 다 보이는 것이 동기의 근거다. |
| **V8** | **산책길은 정거장의 형태만 바꾼다.** 걷기·잠긴 스텝 거절·모션 줄이기(K4~K7)는 그대로 살아 있다. | 규칙은 그대로고 표현만 바뀐다. |

## 4. 서버

`GET /me/journey`에 **부서 인자 하나**를 더한다. 그 외 변경은 없다.

- `?dept=<코드>` — 그 부서의 트랙을 그린다. **저장된 목표는 건드리지 않는다.**
- `goalDept`는 계속 진짜 목표를 뜻하고, `track.dept`가 지금 보고 있는 부서를 뜻한다.
- 저작된 주제가 없는 부서는 거절한다.
- `freeRoam`의 뜻은 그대로다 — 목표를 뺀 나머지 전부.

## 5. E — 부서 간지 (먼저 만든다)

지금의 일터 탭을 이 모습으로 바꾼다. 서가(G)는 아직 없으므로, 이 단계에서 일터 탭은 **목표 부서의
간지**다.

- **부서 표지**: 아이콘 액자(기울인 종이), 부서 이름, `주제 N · 상황 M · 우표 K 모음`.
- **부서 진행 게이지**: 주제별로 폭을 나눈 한 줄 잉크 게이지. 칸 폭은 그 주제의 상황 수에 비례한다.
- **간지 목록**: 세로 스크롤. 왼쪽에 바인더 링, 각 간지 오른쪽에 번호가 적힌 색 인덱스 탭.
- **간지 한 장**: 아이콘 · 주제 이름 · 상태 표시 · **우표 미니 격자**(상황 수만큼, 완료분은 채움) ·
  `done/total` · 진행 중인 주제에는 `이어서` 버튼.
- **상태는 세 가지뿐이다** — `완료`(도장) · `진행중`(테이프 + 강조 테두리) · 그 외. **잠금은 없다**(X2).
- 묶음은 `track`을 따른다(K3) — 부서 코어 먼저, 부서 심화 그다음.

## 6. G — 부서 서가 (그다음)

- 부서 바인더를 책장에 꽂아 늘어놓는다. 한 줄에 4개, 줄마다 선반 널.
- 바인더 한 개: 색 등, 코드와 이름 라벨, 아이콘, 바닥의 잉크 진행 바, `done/주제수`.
- 목표 부서에는 `내 부서` 표식. 마지막으로 보던 부서에는 테이프 표식.
- **`내 부서` 확장 카드**를 맨 위에 둔다 — 아이콘, 주제 게이지, `이어서` 버튼, 그리고 **목표를 바꾸는
  동작**(V2가 말하는 유일한 자리).
- 바인더를 누르면 E로 민다.

## 7. H — 주제 산책길 (마지막)

지금의 정거장 뷰를 우표 산책길로 바꾼다.

- **배치**: 10점 패턴을 600px 주기로 되풀이하고, 홀수 주기에는 x를 조금 흔든다.
  `[70,80] [200,130] [318,92] [300,232] [160,262] [64,372] [212,400] [330,372] [250,520] [96,540]`
- **우표**: 62px, 가장자리 구멍, 번호 도장. 완료는 겹줄 체크, 현재는 깃발.
- **길**: 지나온 구간은 빨간 실(핀으로 고정), 앞 구간은 연필 점선.
- **구간 경계**: 난이도 계단이 바뀌는 자리에 손글씨 라벨과 잔선. **경계는 실제 계단에서 온다** —
  12개씩 끊지 않는다(V6).
- 들어오면 현재 위치 근처로 스크롤한다.

## 8. 검증 규칙

| 입력 | 기대 |
|---|---|
| 주제 35개인 부서 | 진행도 바가 여러 줄로 접히고, 칸 크기가 줄지 않는다 |
| 주제 15개인 부서 | 같은 화면이 서고, 빈 칸을 지어내지 않는다 |
| 상황 23개인 주제 | 우표 격자가 23개다. 줄이거나 묶지 않는다 |
| 서가를 연다 | 네트워크 요청이 **0회 추가**된다 |
| 서가에서 다른 부서를 연다 | 요청 1회, 그리고 **`goalDept`가 그대로다** |
| 목표 아닌 부서를 보는 중 | 화면은 그 부서를 그리고, `내 부서` 표식은 여전히 목표 부서에 있다 |
| 저작된 주제가 없는 부서 코드 | 서버가 거절하고, 화면은 빈 바인더를 지어내지 않는다 |
| 어떤 주제든 탭 | 열린다. 잠긴 주제가 없다 |
| `resume`가 없는 트랙 | 권유 표시 0개 |

## 9. 하지 않는 것

- 배치고사·메인 루프·리텐션은 이 단계가 아니다(2026-09-23 보류).
- 주제를 잠그지 않는다(X2).
- 공통 필수 묶음을 만들지 않는다(X1).
- 부서 목록을 새로 만들지 않는다 — `/me/journey`가 이미 낸다(J9).
