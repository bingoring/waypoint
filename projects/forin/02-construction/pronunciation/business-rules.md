# Business Rules — 발음·스피킹 피드백

인덱스: [`./build-spec-index.md`](./build-spec-index.md) · 타입: [`./domain-entities.md`](./domain-entities.md)

## 1. 규칙 표 (Rules)

| # | 규칙 | 근거 |
|---|---|---|
| R1 | 음절 밴드는 `ok ≥ 80`, `weak 60–79`, `bad < 60`. 경계값 80·60은 각각 위쪽 밴드에 속한다 | SoT L149의 3색을 수치화. 경계 방향을 못 박지 않으면 구현자마다 갈린다 |
| R2 | `attempt_no`는 `(user_id, sentence_key)`마다 1부터 증가하며 **재사용·재번호 없음** | SoT L95가 "1차/2차/3차"를 이력으로 보여준다. 삭제해도 번호를 당기지 않는다 |
| R3 | 연습 대기 화면의 점수 이력은 **최근 3회**만, 오래된 것부터 위로 | SoT L95가 3행 고정. 4회차부터는 가장 오래된 것이 빠진다 |
| R4 | 교정 포인트는 **정확도 최저 음소 2개**. 동점이면 문장에서 먼저 나온 것 | SoT L198 "교정 포인트 2" — 개수가 고정이다 |
| R5 | 교정 포인트에 해당하는 한국어 팁이 없으면 **그 음소를 건너뛰고 다음으로 내려간다** | 팁 없는 카드를 빈 채로 렌더하느니 덜 보여주는 게 낫다 |
| R6 | 녹음은 최대 10초. 초과 시 자동 종료하고 그때까지의 오디오로 채점한다 | SoT L90 "최대 10초", L127 "남은 6초" 카운트다운 |
| R7 | 오디오 원본은 채점 후 **저장하지 않는다**. 파형은 진폭 배열로만 남긴다 | 개인정보 최소 수집. 파형 표시(SoT L190·L195)에 원본이 필요 없다 |
| R8 | `sentence_key`는 `sha256(normalize(text) + "\|" + locale)`의 앞 32자. `normalize` = 양끝 공백 제거 + 연속 공백 1칸 + 소문자화 | 같은 문장을 대소문자만 다르게 보내도 이력이 갈리면 R2·R3가 무의미해진다 |
| R9 | `SentenceReference`는 `sentence_key`당 **전역 1행**(사용자 무관) | 정준 발음은 사용자에 따라 다르지 않다. 사용자별로 만들면 Azure 호출이 사용자 수만큼 늘어난다 |
| R10 | Azure가 음절·음소를 주지 않은 응답도 **정상 처리**한다 — 총점·단어까지만 표시하고 음절 그리드·교정 포인트는 숨긴다 | granularity 변경 전 응답 형태와의 하위호환. 회귀 위험을 스펙에서 못 박는다 |

## 2. 검증 규칙 (Validation)

| 입력 | 규칙 | 위반 시 |
|---|---|---|
| `referenceText` | 비어있지 않음, 최대 300자 | 400 `invalid_reference_text` |
| 오디오 | WAV(RIFF PCM16) 16kHz mono, 최대 10초 · 최대 1MB | 400 `invalid_audio` |
| `locale` | 서버가 프로필에서 파생한다. **클라이언트가 보내지 않는다** | 클라이언트 값은 무시 |
| `origin` | [domain-entities §4](./domain-entities.md) 허용집합 | 모르는 값은 `freeform`으로 강등하고 경고 로그 |
| `reviewCardId` | 주어졌다면 **호출자 소유** 카드여야 함 | 403 — 남의 카드에 내 시도를 붙일 수 없다 |

## 3. 권한 / 접근 규칙 (Authz)

- 모든 엔드포인트 **인증 필수** (`POST /pronunciation`은 이미 `auth()` 뒤에 있다 — `router.go:136`).
- 시도 이력은 **본인 것만** 조회된다. `user_id`는 토큰에서 오고 쿼리 파라미터로 받지 않는다.
- `GET /speech/reference`는 사용자 데이터가 아니므로 인증만 요구하고 소유권 검사는 없다(R9).

## 4. 불변식 (Invariants)

| # | 불변식 | 깨지면 |
|---|---|---|
| I1 | `speech_attempts`는 append-only — `UPDATE`·`DELETE` 경로가 코드에 없다 | 이력이 사실이 아니게 된다 |
| I2 | 시도 1건은 `speech_phoneme_scores` 0..N행과 **같은 트랜잭션**에서 쓰인다 | 음소 집계가 시도 수와 어긋나 드릴이 조용히 틀린 값을 낸다 |
| I3 | `origin='drill'`인 시도는 `review_card_id`가 항상 `NULL` | 드릴 발화에 카드를 붙이면 리뷰랩 집계가 오염된다 |
| I4 | Azure 호출은 시도당 정확히 1회. 재시도 로직이 붙더라도 **저장은 1회** | 유료 API 중복 과금 + 이력 중복 |
| I5 | `attempt_no`는 DB에서 채번한다(같은 트랜잭션 내 `MAX+1`), 애플리케이션 카운터가 아니다 | 동시 요청 2건이 같은 번호를 받는다 |

## 5. 엣지케이스 · 에러 매핑

| 상황 | 처리 | 사용자에게 |
|---|---|---|
| `AZURE_SPEECH_KEY` 미구성 | 채점 시도 자체를 하지 않는다. `GET /me` 또는 설정 응답에 **기능 비활성 플래그**를 실어 앱이 진입점을 숨기게 한다 | 발음 버튼이 아예 보이지 않는다. **503을 던지고 화면에서 실패시키지 않는다** — 죽은 버튼이 더 나쁘다 |
| Azure 5xx / 타임아웃 | 저장하지 않고 502. 시도 번호도 소비하지 않는다 | "채점 서버가 응답하지 않아요. 잠시 후 다시." + 다시 녹음 |
| Azure가 `NBest` 빈 배열 반환(무음·잡음) | 저장하지 않고 422 `no_speech_detected` | "소리가 잘 안 잡혔어요. 조용한 곳에서 다시 해볼까요?" (SoT L90의 안내와 같은 어조) |
| 인식 결과가 참조와 전혀 다름 (`Completeness` 0에 가까움) | 정상 저장한다 — **낮은 점수도 이력이다** | 결과 화면 그대로. 점수가 낮을 뿐이다 |
| 마이크 권한 거부 | 서버 호출 없음 | 권한 안내 + 설정 열기. 녹음 버튼 비활성 |
| 녹음 10초 초과 | R6대로 자동 종료 후 정상 채점 | 카운트다운이 0에 닿으면 자동으로 결과로 넘어간다 |
| 참조 생성(TTS→assess) 실패 | 참조 없이 진행 — IPA 줄과 원어민 파형을 **숨긴다**. 채점은 정상 동작 | IPA가 없을 뿐 연습·채점은 된다. 가짜 IPA를 만들지 않는다 |
| 같은 문장 4회차 이상 | 정상 저장. 화면은 R3대로 최근 3회만 | — |
| `review_cards` 삭제 후 그 시도 조회 | `review_card_id`가 `NULL`이 된 채 남는다 | 이력은 유지, 카드 링크만 사라진다 |
