# 구현 계획 — 상황 학습 4단계 (v44)

**정본 스펙:** [`build-spec-index.md`](build-spec-index.md) · status READY

**목표:** 커리큘럼 상황 한 건을 `단어 → 문장 → 가이드 대화 → 자유 대화` 네 단계로 배우게 하되,
**네 단계가 한 줄로 이어지게** 한다.

## 전체 제약 (모든 작업에 걸린다)

- **연결은 지침이 아니라 데이터다.** 문장은 자기가 쓴 단어의 id를 들고, STEP 1은 그 참조를
  거꾸로 따라가 만든다. 검사할 수 있어야 한다(스펙 §2-1).
- **8개·5개는 최솟값이다.** 화면도 생성기도 개수를 배열에 박지 않는다(스펙 §2-2).
- 회차 사다리를 바꾸지 않는다 — STEP 3·4는 지금의 두 회차 그대로다(스펙 §1).
- 새 i18n 키는 네 카탈로그 전부(ko·en·ja·de)에 넣는다.
- enum 성격의 값은 코드 쪽 허용 집합으로 둔다. DB CHECK 제약을 쓰지 않는다.
- 커밋 메시지에 `Co-Authored-By` 줄을 넣지 않는다.

## 작업 순서

콘텐츠와 화면을 나란히 돌린다. 화면은 콘텐츠 없이도 지을 수 있고(고정 표본으로), ER 콘텐츠가
나오는 대로 붙는다.

    A 데이터 모델 ─┬─ B 생성기 → C ER 생성·검수 → D 전량 생성
                   └─ E 서버 API → F StepTrack → G 허브 → H 단어 → I 문장 → J 가이드 대화

## A. 데이터 모델 — 시드가 단어와 문장을 싣는다

**파일**
- 수정: `server/content/nurse/topics/<dept>.yaml` (스키마만; 값은 B·C가 채운다)
- 수정: `server/internal/domain/content/content.go` (시드·시나리오 구조체)
- 수정: `server/cmd/gencontent/seeds.go` (시드 → 시나리오로 실어 나르기)

**만드는 것**

주제 단위 단어 은행을 새 파일로 둔다 — 시드 파일은 상황 목록이라 주제 단위 값이 들어갈
자리가 없다.

    server/content/nurse/lexicon/<dept>.yaml
    - theme: core-safety-er
      words:
        - id: w-wristband
          en: wristband
          ipa: /ˈrɪstbænd/
          ko: 손목 밴드
          icon: bandage
          example: "Let me check your wristband."

시드에는 문장을 붙인다.

    - theme: core-safety-er
      title: 반복 신원확인 이유 설명
      ...
      sentences:
        - en: "I need to check your wristband every time."
          ko: "매번 손목 밴드를 확인해야 해요."
          chunks: ["I need to", "check your", "wristband", "every time"]
          words: [w-wristband]          # ← 연결. 이 문장이 쓴 은행 단어
          goal: 1                        # ← 시드 goals의 몇 번째를 향하는 문장인가

**인터페이스**
- 내놓는 것: `content.Word{ID,En,IPA,Ko,Icon,Example}`, `content.Sentence{En,Ko,Chunks,Words,Goal}`,
  `content.Lexicon{Theme,Words}`.
- 쓰는 것: `cmd/gencontent`가 시드의 `sentences`를 시나리오로 그대로 옮긴다.

**단계**
- [ ] 1. 구조체와 로더를 쓰는 실패 테스트 — 렉시콘 파일을 읽어 주제로 찾고, 시드의 문장이
      시나리오로 넘어오는지. **문장이 참조한 단어 id가 은행에 없으면 로딩이 실패해야 한다.**
- [ ] 2. 테스트가 실패하는 것을 확인한다
- [ ] 3. 구조체·로더·`gencontent` 전달을 구현한다
- [ ] 4. 테스트 통과 확인. **id 검사를 없애 보고 테스트가 실패하는지 확인한다**
- [ ] 5. 커밋

## B. 생성기 — 두 차례로 만들고 뒤가 앞을 참조한다

**파일**
- 생성: `server/content/tools/gen_lexicon.py` (1차 · 주제당 단어 은행)
- 생성: `server/content/tools/gen_sentences.py` (2차 · 상황당 문장)
- 생성: `server/content/tools/verify_lesson_content.py` (검사)

**규칙**

1. **1차**는 주제 하나와 그 주제가 품은 상황 전부(제목·brief·goals·keyPhrases)를 주고
   **단어 은행 30개 이상**을 받는다. 그 주제의 상황들이 실제로 쓸 말이어야 한다.
2. **2차**는 상황 하나와 **그 주제의 은행**을 함께 주고 문장 5개 이상을 받되,
   **은행에 있는 단어로만 짓고 쓴 단어의 id를 적게 한다.** 시드의 `keyPhrases` 3개는
   반드시 포함하고(청크 분해와 한국어 힌트를 붙여서), 나머지는 새로 짓는다.
3. 문장마다 시드 `goals`의 몇 번째를 향하는지 적는다 — STEP 3이 그 순서로 걷는다.
4. **모델은 Sonnet.** 런타임 대화가 쓰는 값싼 모델보다 나은 결과를 미리 확보하는 것이
   선생성을 고른 이유다(스펙 §6 결정 2).
5. **이미 있는 것은 건너뛴다.** 두 도구 모두 대상 파일에 그 주제/상황이 이미 있으면 넘어간다.
6. **YAML을 통째로 다시 쓰지 않는다.** 줄 단위로 끼워 넣는다 — 기존 `apply_locale_binding.py`가
   같은 이유로 그렇게 한다(사람이 저작한 주석과 배열을 보존한다).

**검사 도구가 잡아야 하는 것**

| | 검사 | 왜 |
|---|---|---|
| V1 | 문장이 참조한 단어 id가 은행에 있다 | 연결이 끊기면 STEP 1이 빈다 |
| V2 | 참조한 단어가 그 문장의 `en`에 실제로 나온다 | id만 맞고 문장에 없으면 거짓말이다 |
| V3 | 상황마다 문장 5개 이상, 모아진 단어 8개 이상 | 최솟값(스펙 §2-2) |
| V4 | `keyPhrases` 3개가 문장에 모두 들어 있다 | 사람이 저작·검토한 문장을 버리지 않는다 |
| V5 | 청크를 이으면 `en`과 같다 | 조립 문제가 풀리지 않는 것을 막는다 |
| V6 | `goal`이 시드 `goals`의 범위 안이다 | STEP 3이 걸을 순서의 근거 |
| V7 | 은행 단어가 어느 문장에도 안 쓰이면 경고 | 은행이 부풀기만 하는 것을 막는다 |

**단계**
- [ ] 1. `verify_lesson_content.py`를 **먼저** 쓴다 — V1~V7. 손으로 만든 어긋난 표본으로
      각 검사가 실제로 잡는지 확인한다
- [ ] 2. `gen_lexicon.py` — 주제 하나로 먼저 돌려 눈으로 본다
- [ ] 3. `gen_sentences.py` — 같은 주제의 상황 하나로 돌려 눈으로 본다
- [ ] 4. 두 결과에 검사 도구를 돌린다. 어긋나면 프롬프트를 고친다
- [ ] 5. 커밋

## E. 서버 API — 상황 하나의 4단계를 낸다

**파일**
- 수정: `server/internal/domain/learning/ports.go`
- 수정: `server/internal/adapters/http/` (새 핸들러)
- 수정: `server/internal/domain/learning/policy.go` (`GuideChoices` → `GuideGuided`)

**인터페이스**

    GET /me/lesson/{scenarioId}
    → { situation, steps: [ {kind, state, count}… ], words: [...], sentences: [...] }

`state`는 `done | now | lock | skip`. `skip`은 레벨별 건너뛰기(스펙 §4).

**`choices` → `guided` 개명**
- `GuideChoices "choices"` → `GuideGuided "guided"`. `GuideFree`는 그대로.
- **서버는 한동안 `choices`도 `guided`로 받는다.** 받아 주는 기간을 주석에 날짜로 적는다.
- 저장되는 진도는 회차 번호 기준이라 **데이터 이관이 없다.**
- 계약을 재생성하고 드리프트 0을 확인한다.

**단계**
- [ ] 1. 개명과 하위 호환을 쓰는 실패 테스트 — `guided`와 `choices` 둘 다 같은 회차로 풀린다
- [ ] 2. 실패 확인 → 구현 → 통과 확인. **하위 호환을 지워 보고 테스트가 실패하는지 확인한다**
- [ ] 3. `/me/lesson/{scenarioId}` 실패 테스트 — 건너뛴 단계가 `skip`으로 오고,
      **개수가 고정값이 아니라 실제 콘텐츠를 따른다**
- [ ] 4. 실패 확인 → 구현 → 통과 확인
- [ ] 5. 계약 재생성, 드리프트 확인
- [ ] 6. 커밋

## 검증 규칙 (스펙 §8이 되는 표)

| 입력 | 기대 |
|---|---|
| 어떤 상황이든 | STEP 1 단어가 전부 그 상황의 STEP 2 문장에 나온다 |
| 어떤 상황이든 | STEP 3의 목표 문장이 그 상황의 STEP 2 문장 안에 있다 |
| 문장이 12개인 상황 | 12개를 다 낸다. 5개로 자르지 않는다 |
| 단어가 20개인 상황 | 20개를 다 낸다. 8개로 자르지 않는다 |
| 레벨 b | 허브 분모가 3, `StepTrack`의 첫 칸이 빗금 |
| 레벨 c에서 `그래도 할래요` | 그 단계가 열리고 분모가 늘어난다 |
| `?guide=choices`로 들어온 옛 링크 | `guided`와 같은 회차로 풀린다 |
| 청크를 순서대로 이은 결과 | 문장의 `en`과 정확히 같다 |
