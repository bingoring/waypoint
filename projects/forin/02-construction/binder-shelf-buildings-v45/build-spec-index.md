핸드오프 v45는 서가를 **건물 인덱스 탭 5개**로 나눈다. 탭 = 색 띠 + 건물명 + 미니 진행 바(활성 탭만 `n/m`),
활성 탭은 종이색·넓게·아래 패널과 이어진다. 패널 안에 선반 4열. 상단 통계 `바인더 N권 · 건물 M`.

## §0. 개요 & 범위

**하는 것**
- A. 서버가 서가 항목마다 **건물**을 싣는다(건물 표는 이미 서버 `domain/campus/floors.go`에 있다).
- B. **피부과를 본관에서 외래·진단동으로 옮긴다**(사용자 결정 — 피부과는 대부분 외래 진료다). 캠퍼스 지도의
  엘리베이터 층과 서버 표를 같이 바꾼다.
- C. 서가를 건물 탭 + 패널로 바꾼다.

**하지 않는 것**(첨부 도안에 있지만 옮기지 않는다)
- `공통 필수` 카드 — v42 X1 그대로(우리 콘텐츠에 "어느 바인더에서 해도 한 번만" 규칙이 없다).
- 맨 아래 `추천` 상자("ER → ICU → 약국 순이 실무에 가깝다") — 그런 순서 규칙이 없는데 지어내는 말이다.
- "파란 테이프 = 읽던 곳" — 마지막으로 본 부서를 저장하지 않는다(v42 §6에서 이미 뺌).
- 6번째 건물 — 사용자 결정으로 5개 유지(§3).

### 왜 이 5개 건물인가 (조사 2026-10-07)
미국 대학병원 캠퍼스는 본관(응급·수술·중환자·입원) · 여성/소아 병원 · 암센터 · 행동건강/재활 동 · 외래 건물로
나뉘는 것이 흔하다(워싱턴대 BJC, 미시간대, RWJ, Medical City McKinney 사례; 서울대병원도 본관 1층 응급의료센터 ·
암병원 · 어린이병원). 앱의 캠퍼스(`ELEVATOR_BUILDINGS`)는 이미 이 모양이고, 어긋난 것은 본관 2F의 피부과 하나였다.
암·재활관에는 암·완화 묶음과 재활·정신 묶음이 함께 있다 — 둘 다 실제로 흔한 조합이라 나누지 않았다.

| 건물(서버 이름) | 탭 이름 | 부서 |
|---|---|---|
| 본관 | 본관 | ER · PHARMA · OR · ICU · WARD · SURGWARD · ORTHOWARD · **GEN** |
| 별관 1 | 여성소아 | WOMENKIDS · PEDS · LD · NURSERY · NICU · PICU |
| 별관 2 | 암·재활 | REHAB · PSYCH · ONCO · HOSPICE · GERI |
| 별관 3 | 외래진단 | RAD · SPECIALTY · INFUSION · DIAL · ENDO · **DERM** |
| 지원동 | 지원동 | MORGUE · SPD · LOUNGE · SIM |

## §1. 분해

    A 서버(건물 필드)  →  B 피부과 이동(서버 표 + 지도)  →  C 서가 화면
    A와 B는 서로 독립이지만 C는 A가 있어야 그려지고, B 전에 그리면 피부과가 본관 탭에 나온다.

### §D. 데이터

- `learning.FreeRoamEntry`에 `Building string \`json:"building"\`` — 그 부서의 건물(서버 이름, 예 `"별관 3"`).
- `JourneyView`에 `GoalBuilding string \`json:"goalBuilding"\`` — 목표 부서의 건물. 서가의 첫 탭을 정한다.
- `campus.BuildingOf(dept string) string` — `Floors`에서 그 부서가 처음 나오는 층의 건물. 표에 없는 부서는 빈 값.
  **예외 하나: `GEN` → `본관`**(§R2). 표에 GEN 층을 지어내지 않고 함수에 규칙으로 둔다 — 엘리베이터가 서는
  층이 아니기 때문이다.
- 건물 **순서**는 `campus.Floors`의 건물 등장 순서(본관 → 별관 1 → 별관 2 → 별관 3 → 지원동). 서가 목록
  (`summariseFreeRoam`)이 이미 이 순서로 정렬된다.
- 탭 이름: 모바일 i18n `building.<id>.short` 5개(ko·en·ja·de). 색은 기존 `BUILDING_STYLE[건물].accent`.
- 피부과: `floors.go`의 DERM 층을 `{Building: "별관 3", Label: "5F", Where: "별관 3 5F 피부과 센터"}`로.
  i18n 키 `본관|2F…`를 `별관 3|5F…`로(en·ja·de). 엘리베이터 `dx` 건물 맨 위에 5F를 더하고 `tower`의 2F를 뺀다.
  콘텐츠 `greet-wards.yaml`의 피부과 첫날 안내문("본관 2F")을 같이 고친다.

### §R. 규칙

| | 규칙 | 왜 |
|---|---|---|
| **R1** | 건물 집합과 순서는 **서버 표가 정한다.** 클라이언트는 건물을 지어내지 않고 부서 코드로 건물을 추측하지 않는다 | 표가 이미 서버에 있고(`floors.go` 머리말: "이 파일이 서버의 진실"), 지도와 서가가 갈라지면 같은 병원이 두 모양이 된다 |
| **R2** | `GEN`(공통 General)은 **본관 탭**에 꽂는다 | 사용자 결정(2026-10-07). 병원 공통 업무라 건물이 없지만 별도 자리를 두지 않는다 |
| **R3** | **목표 부서는 서가 패널에 다시 꽂지 않는다**(v42 G 그대로). 대신 첫 탭이 목표 부서의 건물이다 | v42에서 위쪽 `내 부서` 카드와 서가에 같은 부서가 두 번 나오는 것을 뺐다. 탭을 넘겨도 그 결정은 그대로다 |
| **R4** | 탭은 **항목이 1개 이상인 건물만** 그린다. 빈 탭을 지어내지 않는다 | 목표 부서 하나만 있는 건물(예: 지원동 목표)은 패널이 비게 된다 |
| **R5** | 탭의 미니 진행 = 그 건물 패널 바인더들의 `Σpassed / Σtotal`. 숫자 `n/m`은 활성 탭에만 | 핸드오프 그대로. 패널에 없는 목표 부서는 세지 않는다(R3과 같은 기준) |
| **R6** | 상단 통계 `바인더 N권 · 건물 M`: N = 서가 항목 + 목표 1, M = 그려진 탭 수 | 핸드오프의 `바인더 30권 · 건물 5`는 예시 값이다(V6) |
| **R7** | 서버가 모르는 건물 이름(빈 값 포함)은 탭을 하나 더 만들되 `DEFAULT_BUILDING_STYLE`로 그린다. 항목을 버리지 않는다 | 서버가 건물을 먼저 늘려도 화면이 부서를 잃지 않는다 |
| **R8** | 서가는 **요청을 늘리지 않는다**(v42 V3). 탭 전환은 로컬 상태다 | 응답 한 번에 건물이 다 실려 온다 |
| **R9** | 탭 선택은 기억하지 않는다. 들어올 때마다 목표 부서의 건물에서 시작한다 | 저장할 상태를 만들지 않는다(v42 '읽던 곳 테이프'와 같은 판단) |

### §F. 화면

- `BinderShelf`에 `goalBuilding` prop. 내부 상태 `tab`(건물 이름) — 초깃값 `goalBuilding`, 탭이 없으면 첫 탭.
- `BuildingTabs`(신규, `components/journey/BuildingTabs.tsx`): props `{ tabs: {building, label, accent, passed, total}[], active, onPick }`.
  탭 한 장 = 왼쪽 색 띠 + 이름 + 미니 진행 바, 활성 탭만 `n/m`·종이색·넓음·아래 테두리 없음(패널과 이어짐).
  5개가 한 줄에 들어가지 않으면 가로 스크롤(390pt 폭에서 확인).
- 패널: 테두리 상자, 머리에 `건물명 · 바인더 k권 · 주제 p/t`, 그 아래 기존 선반(4열).
- 상단 제목 줄 오른쪽에 `바인더 N권 · 건물 M`.
- 화면 상태: 로딩/오류는 v42 그대로. 서가 항목이 0개면(목표만 있는 계정) 탭·패널을 그리지 않는다.

## §3. 결정 (질문 해소 완료)

1. **건물은 5개 유지, 피부과만 외래·진단동으로** — 사용자(2026-10-07). 대안: 암센터와 행동건강·재활관을 나눈
   6개(실제에 더 가깝지만 엘리베이터 건물·지도 그림을 새로 그려야 하고 핸드오프 탭은 5개), 지금 그대로.
2. **GEN은 본관 탭** — 사용자(2026-10-07). 대안: 탭 위 별도 바인더.
3. 탭 이름은 핸드오프의 짧은 이름(본관·여성소아·암·재활·외래진단·지원동) — 캠퍼스 엘리베이터 건물 이름
   (`메인 메디컬 타워`·`여성소아 센터`·`암센터·특수 재활관`·`외래·진단 지원동`·`행정·백스테이지 윙`)을 줄인 것이라
   지도와 같은 건물을 가리킨다 — AI.

## §5. 검증

| 입력 | 기대 |
|---|---|
| 목표 ER | 첫 탭 본관, 본관 패널에 ER 없음(R3), 다른 본관 부서와 GEN이 있음 |
| 목표 DERM | 첫 탭 외래진단 |
| 탭 전환 | 네트워크 요청 0회 추가(R8), 패널 바인더가 그 건물 부서로 바뀜 |
| 건물 하나의 부서가 목표 하나뿐 | 그 탭이 없다(R4) |
| 서버가 모르는 건물 이름 | 탭이 하나 더 생기고 부서를 잃지 않는다(R7) |
| 탭 진행 | 패널 바인더 합과 같다(R5), 숫자는 활성 탭에만 |
| 상단 통계 | N = 항목 + 1, M = 탭 수(R6) |
| 피부과 | 엘리베이터 외래·진단 5F에서 들어가고, 본관에는 없다. 홈의 '오늘 배치'가 `별관 3 5F` |
