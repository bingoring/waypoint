# forin — 콘텐츠 워크스트림 (병행 트랙)

> 대규모 학습 콘텐츠(상황·환자 이벤트 300+, 퀴즈 1000+, 시나리오·다이얼로그·큐레이션 표현)를
> 작성·검수하는 **병행 트랙**. 엔지니어링 Construction 스테이지(2-1~2-8)와 나란히 진행한다.
> 상위 맥락: [`events-catalog.md`](events-catalog.md), [`prd.md`](prd.md).

## 결정 (2026-06-08)

- **작성 주체:** AI가 조사→초안 대량 생성, 이후 검수(임상 정확성 포함). 사람은 검수·승인.
- **착수 시점:** **2-2(도메인·콘텐츠 API)에서 콘텐츠 포맷·로더가 확정된 후** 본격 착수.
  (포맷 확정 전 대량 작성 금지 — 변경 시 전면 재작업 위험.) 그 전엔 소량 시드만.
- **이유:** 콘텐츠 분량·품질이 실제 출시를 좌우하는 제약. 전문성·다양성·버전 관리 필요.
- **필수 후속(사용자 강조 2026-06-09):** 현재 시드는 검증용 소량일 뿐 — **시드 분량을 반드시 대폭 증대**(300+)해야 출시 가능.

## 단계 (마일스톤)

1. **시드(소량) — ✅ 완료**(2-2 증분1). 파이프라인 검증용. 포맷·검증·적재 입증(화재 이펙트 포함).
2. **MVP 세트** — 메인 루트 + 일일 풀 운영 최소량. **착수 가능**(포맷 입증됨).
3. **확장 → 300+ 이벤트 / 1000+ 퀴즈**(고다양성). feature-complete 이후까지.

## 진료과(specialty) 범위

진료과는 데이터(스키마 변경 없이 확장). **결정: A**(2026-06-08) — MVP는 디자인된 워드 내 300+ 집중,
신규 진료과는 로드맵(인테리어 art 준비 시).
**확장(handoff v2, 2026-06-12):** 디자인된 인테리어가 **급성 5개(ER/OR/ICU/Peds/Pharmacy) + 외래 클리닉 4개
(내과/외과/정형외과/피부과)** = 총 9개로 늘었다. 외래는 **config 기반 `ClinicInterior` 엔진**이라 진료과 추가가
저렴(config 1개) → 콘텐츠 범위를 외래 4과까지 넓힐 수 있다. 상세·분포는 [`events-catalog.md`](events-catalog.md).

## 배치 작성 방식

AI가 진료과·병동·티어·카테고리별로 **배치 단위 초안 생성 → 시더 검증(참조·enum·슬러그) → 검수 → 적재**.
대량 스케일이 필요하면 다중 에이전트 오케스트레이션(워크플로) 옵션도 가능.

## 작성 규약 (2-2에서 확정)

- 버전드 파일(YAML/JSON) + `contentVersion`, 디렉토리·ID 규약(슬러그 ≥5자리), enum 코드측 허용집합.
- 퀴즈는 풀(pool) + 변형 변수로 다양성 확보. 이벤트는 prerequisites/follow_ups 그래프.
- 비상 코드 등 임상 사실은 신뢰 가능한 레퍼런스로 검증(지역차 표기).

## 검수 프로세스

AI 초안 → (임상/언어) 검수 → 승인 → 적재. 오류·지역차·난이도 라벨 점검. 도구는 2-2에서 정함.

## 구두처방(listen) 퀴즈 실제 오디오·파형 (2026-08)

기존 listen 퀴즈: 소리는 기기 TTS로 진짜 났지만 **파형·재생바·시간은 고정 장식**이었음.
사용자 요구: 재생하면 바가 이동하며 파형을 색칠하고, **파형이 실제 음성과 일치**.

- **서버 TTS+파형:** azurespeech에 `Synthesize`(Azure TTS, `tts.speech.microsoft.com/v1`,
  `riff-24khz-16bit-mono-pcm`, 같은 STT 키/리전) 추가. `GET /quizzes/{id}/audio.wav`(합성 WAV,
  **`http.ServeContent`로 Range/206 지원 — iOS AVPlayer 로드에 필수**) +
  `GET /quizzes/{id}/audio-meta`(48바 **RMS 진폭 포락선** + durationMs). audioText 해시로 캐시 →
  반복 재생 비용 0. 진폭은 WAV PCM16을 48버킷 RMS로 다운샘플(실제 loudness 모양).
- **클라이언트:** WAV를 **로컬 파일로 다운로드 후 재생**(expo-audio) — AVPlayer가 cleartext-http
  localhost 스트리밍을 ATS로 막으므로 로컬 파일 우회. 재생 위치(currentTime/duration)로 파형 바
  색칠(played=cyan)+재생헤드 이동+mm:ss 시간, 바 높이는 서버 진폭(실제 모양). 0.7×/1.0× 속도.
  합성 불가/오프라인이면 기기 TTS+정적 바로 폴백.
- **검증(시뮬레이터):** 재생 중 `L1P1 t1.5→3.1/5.0`, 재생헤드가 30%→75%로 이동하며 파형 실시간
  색칠 확인(스크린샷). Range 미지원 시 `L0P0`(로드 실패) → ServeContent로 해결. go/tsc/jest·E2E 24/0.

## 전체 퀴즈 타입 감사 (2026-08)

16개 타입(15 컴포넌트 + 기본 SentenceQuiz)이 실제 인터랙션·채점·완료 게이팅이 되는지 감사.

- **정상(10):** mcq · match_pairs · check · sbar(+order) · sort · monitor · gauge · spot_error · triage · sentence_build. 탭 선택/배치·정오 채점·정답시에만 완료.
- **수정한 버그(3):**
  1. **`match` 타입 dispatch 누락 → 깨짐** — `case 'match'`가 없어 default(SentenceQuiz)로 빠짐.
     pairs만 있고 template 없음 → 빈 카드 + **자동 통과**(빈 슬롯 `[].every`=true). `match_pairs`와 함께
     MatchQuiz로 매핑해 수정(시뮬 확인). 방어로 SentenceQuiz `allFilled/allCorrect`에 `blankCount>0` 가드.
  2. **CalcQuiz 문자열 채점** — `entry===answer`라 `.5`/`0.50`이 오답 처리. 숫자 파싱+허용오차(1e-6)로 수정,
     비수치는 문자열 폴백.
- **추가 개선(2026-08, 사용자 요청):**
  - **AbbrQuiz 정답 게이팅** — 다른 타입처럼 정답을 골라야 다음/완료로 진행. 오답은 빨강 표시·비활성화,
    정답 선택 시에만 잠금·진행. 점수는 첫 시도 정답 기준. 완료는 전 카드 해결 시에만 활성.
  - **MatchQuiz 핸드오프 디자인 1:1 포팅** — 기존은 단순 2열이라 핸드오프 `ScreenQuizMatching`과 달랐음.
    좌 단어/우 의미 사이 **SVG 커넥터 트랙**(정답=민트 실선+✓배지·끝점 도트 / 오답=빨강 점선+토스트),
    picked=노랑+점선 리드라인, MatchChip 코너 배지, **진행 사각형 푸터(✓□□□ n/총 · 다시 · 완료)**.
    QuizShell(크림 카드 on 다크)이 핸드오프 QuizCard와 동일 테마라 테마 변경 없이 보드만 교체.
    검증: NICU 신생아 용어(preterm↔미숙아 등) 커넥터·오답 토스트 시뮬 확인. tsc·jest 208.

## 전체 퀴즈 디자인 패리티 감사 (2026-08)

각 컴포넌트를 핸드오프 `screens-quiz*.jsx`와 대조.
- **충실(A):** Sentence·Listen·Triage·Calc(Listen/Calc는 실오디오·키패드로 핸드오프 초과).
- **보강한 요소 누락(B):**
  - SbarQuiz: 범례 S/B/A/R 아래 섹션명 + 푸터 'N/총 배치됨' 카운터.
  - MonitorQuiz: 디바이스 패널 하단 ECG 파형 스트립(앰비언트 트레이스). 라벨별 한글 부제는
    `bank`가 문자열 배열이라 콘텐츠 모델 제약으로 미적용.
- **Anatomy(C)→신규 구현(사용자 요청):** 전신 스프라이트 부위 라벨링 퀴즈. 서버 `QuizContent.BodyDots`
  (x/y % + 정답 라벨) 추가, `bank`로 단어(정답+오답) 공급. 클라 `AnatomyQuiz` = 핸드오프
  `PatientFrontPixel`(24×72 SVG) 1:1 포팅 + 번호 dots(탭 선택→단어 배정) + 채점(정답=민트 ✓,
  오답=빨강 취소선+"#n 여기는 <label>!" 피드백) + Tip. dispatch `case 'anatomy'`. 시드 QZ-GEN-00002.
  정식 포맷이 14→15개로 확장. 시뮬 렌더·채점 확인.
- **공통 크롬 미적용(의도):** 헤더 미션칩·라이브 타이머·CRT 스캔라인 배경. 타이머 기능이 없어
  가짜 장식은 배제(N/M 진행은 상단 칩으로 존재). QuizShell=핸드오프 QuizCard 동일 크림-on-다크.

## 다크모드 (2026-08)

**미지원(단일 고정 라이트 픽셀 테마).** `theme/tokens.ts`는 스킴 변형 없는 고정 팔레트,
`useColorScheme`/`Appearance` 대응 없음. 퀴즈·대화의 다크 배경은 VN 연출(다크 위 크림 카드)이지
OS 다크모드가 아님. `app.json userInterfaceStyle:"automatic"`이라 네이티브 요소(Alert·키보드)만
기기 다크를 따라갈 수 있음. **결정(사용자): `userInterfaceStyle:"light"` 고정** — 네이티브 요소까지
라이트로 잠가 일관성 확보. 실제 다크모드 테마는 미지원(향후 필요시 토큰 이원화).

## 대량 생성기 (`cmd/gencontent`, 2026-08)

**요구(사용자):** "부서별 최소 100개" — 한 부서만 파는 간호사도 부족함이 없도록. 학습·퀴즈·이벤트 포함, 타 부서 연계 확장성.

**설계 핵심:** 다이얼로그가 AI 런타임(persona+goals 기반)이라 **시나리오 = 임상 상황 + 페르소나 + 학습목표**.
따라서 손으로 대사 트리를 짤 필요 없이 **분량 = 큐레이션된 임상 토픽 × 환자 페르소나 × 난이도 스프레드**로 확보.

- **토픽 뱅크:** `cmd/gencontent/depts.go`(파트1: ER/ICU/OR/PEDS/PHARMA) + `depts2.go`(나머지 20과).
  25개 부서 × 실임상 토픽 10개. 각 토픽에 Title/Room/Brief/Role/Diff/Skills/Phrases/Goals.
  **확장:** 토픽 1줄 추가 = 다양성↑, `Dept` 1개 추가 = 신규 부서. 스키마 변경 불필요.
- **생성물(부서당):** 시나리오 100+ · 이벤트 8 · MCQ 퀴즈 ~30. 전체 **2500 시나리오 · 200 이벤트 · 750 퀴즈**.
  ID는 `00101`부터 → 손저작(00001~) 과 무충돌. 시더는 전체 교체이므로 손저작+생성분 공존.
- **부서 간 연계:** 이벤트 `related`가 다음 부서 첫 이벤트로 링크. 퀴즈 오답 보기는 **전 부서 표현 풀**에서 추출.
- **퀴즈:** "이 임상 상황에 맞는 영어 표현 고르기" MCQ. 정답=해당 토픽 KeyPhrase, 오답 3개=전역 풀에서 결정론적 추출(같은 토픽 제외). mcq당 정확히 정답 1개(무결성 검증 통과).
- **로더 확장:** `contentfile/loader.go`가 리스트-YAML을 우선 파싱(폴백 단일). 부서당 파일 1개(`gen-<code>.yaml`)로 수천 개 파일 방지.
- **재생성:** `go run ./cmd/gencontent --target 100` → `go run ./cmd/seed`. YAML은 커밋(재현 가능·검수 가능), 생성기는 결정론적.
- **검증(2026-08):** 25과 전부 ≥100(101~115), 퀴즈 ≥31/과. `go build/vet/test` 통과, E2E 스모크 24/0.

## 노출 경로 검증 + 부서 시트 페이지네이션 (2026-08, 시뮬레이터)

시뮬레이터 확인 결과 생성 콘텐츠는 정상 렌더링되나(브리핑·일일보드 스크린샷), **브라우징 갭** 발견:

- **일일 상황판(board):** 전체 2,800 후보(생성 2,500+손저작 300)에서 가중 샘플. 정상 노출.
  단, 일일 세트는 `(유저, 당일)` **동결**(설계상 당일 불변) — 시드 이전 세트는 다음 날/재샘플 시 반영.
- **부서 상세 시트(갭→수정):** `GET /me/situations`가 `LIMIT 8`이라 저번호 손저작 8개만 노출 →
  생성 100+가 안 보임. **한 부서만 파는 학습자가 못 브라우징 = 원래 요구와 충돌.**
  **수정:** `offset/limit` 페이지네이션(기본 20, clamp 1..50, `limit+1` 프로브로 `hasMore`),
  모바일 DeptSheet 무한스크롤(near-bottom 자동 로드 + "더 많은 상황 불러오기"). 정렬은 `ORDER BY id`(안정 페이징).
  **검증:** PEDS 114개가 페이지로 전부 도달(offset 100→마지막 00200, hasMore=false), tsc·go test·E2E 24/0.
