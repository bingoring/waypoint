# Business Logic Model — 하품 릴레이 (가칭)

> 규칙 ID는 [`business-rules.md`](business-rules.md), 데이터는 [`domain-entities.md`](domain-entities.md).
> 엔진은 **순수 Dart**(`lib/domain/`, Flutter 의존 없음)로 만들어 앱·레벨 도구·테스트가 같은 코드를 쓴다(2-7 `bojagi` 패턴).

## 1. 판 하나 (객차 화면)

```
역 선택 → Board.parse(map) → RunState.start(taps)
  ↓ 박자 시계 시작 (650ms, Y-BEAT-1)
  ├─ 플레이어 탭(승객 id) ── tap() ── Y-TAP-1~6 ──→ yawnNow에 추가 / 거절 피드백
  └─ 박자마다 beat():
       had = yawnNow가 비어 있지 않음
       step(yawnNow)            ← Y-BEAT-2 ①~⑥ (시선 → 하품·잠 → 회전 → 예약)
       yawnNow = 예약
       승리? (Y-WIN-1) → 끝(won)
       idleBeats 갱신
       패배? (Y-LOSE-1) → 끝(lost, 니어미스 여부 Y-NEAR-1)
```

- **박자 시계:** `Ticker` 하나로 경과 시간을 재고 650ms마다 `beat()`를 부른다. `Timer.periodic`을 쓰지 않는 이유는 프레임과 맞물려야 하품 애니메이션(4프레임)이 박자 경계에서 끊기지 않기 때문이다.
- **앱이 백그라운드로 가면 시계를 멈추고**, 돌아오면 그 박자 처음부터 잇는다(규칙 시간은 실제 시간이 아니라 박자 수이므로 결과가 같다).
- **한 박자 안의 연출 순서 (FC §4 움직임 표와 같은 값):** 0ms 예약된 사람 하품 시작(4프레임, 520ms) · 시선선이 빛나는 실선으로 바뀜 → 잠드는 사람은 하품이 끝나는 520ms에 꾸벅(3프레임, 200ms) → 다음 박자.
- **엔진과 화면 분리:** 엔진은 박자 결과(`BeatResult{yawned, fellAsleep, rotated, scheduled, outcome}`)만 내고, 화면은 그 결과로 연출을 고른다. 테스트는 엔진만으로 판 전체를 돌린다.

## 2. 판 끝

| 결과 | 동작 |
|---|---|
| 승리 | 진행 저장(`yawn.progress.v1` = max) → 0.5초 뒤(모두 꾸벅하는 장면을 다 본 뒤) 도착 카드. 「다음 역」 → (역 6부터) `RoundAds.roundTransition('interstitial_station')` → 다음 역 |
| 패배 | 0.45초 뒤 패배 카드. 니어미스면 깨어 있는 한 명을 강조하고 「광고 보고 한 번 더 툭」이 대표 버튼(Y-ADS-3 ①). 「다시」는 언제나 있다(1탭 재시작) |
| 한 번 더 툭 | `RewardGate.request('rewarded_extra_tap')` → 받으면 `tapsLeft = 1`, `idleBeats = 0`, `outcome = playing`, 시계 다시 시작. 판마다 1회 |
| 힌트 | 같은 역 실패 3회부터. `RewardGate.request('rewarded_hint')` → `solution[0]`의 승객을 박동 표시, 박자가 정해진 역이면 「n번째 박자」 표시. 판을 다시 시작한다 |

## 3. 레벨 도구 (`tool/build_stations.dart`, 오프라인)

### 3.1 풀이기 — 프로토타입 풀이기와 같은 정의
- **기준 구현:** 메인 저장소 `prototypes/yawn-relay/solver.js` (2026-10-16, 프로토타입 기록 §2 표의 시작점·니어미스 수 16개를 모두 재현).
- **정의:** 툭 T개 = 서로 다른 `(승객, 박자 0~7)` 쌍의 **순서 없는 묶음**. 각 묶음을 박자 0부터 돌려 승·패를 본다. 무효 묶음(그 박자에 이미 잠들었거나 커피이거나 이미 하품 중인 사람을 툭)은 세지 않는다.
- **지표:** `winningStarts` = 이기는 묶음에 쓰인 승객 조합의 가짓수, `winningCombos`, `nearMissCombos`(진 판에서 깨어 있는 사람 1명).
- **비용:** 승객 18명·툭 2개면 묶음 약 1만 개 × 판당 수십 박자 — 역 하나에 1초 안팎(Dart AOT). 툭 3개 역은 승객 12명 이하로 제한한다.

### 3.2 생성기
- `SplitMix64(시드)`로 노선의 요소(Y-LV-4)에 맞는 판을 만든다: 크기(4×4 → 6×6, 2026-10-17부터 가로 5 × 세로 8까지 — 크기 단계는 `yawn_config.dart` `sizes`), 승객 수, 종류 비율, 창문 수, 툭 수가 역 번호에 따라 오른다.
- **채택 조건:** ① `winningStarts` ≥ 1 ② 노선 앞 2개 역은 `winningStarts` ≥ 2(Y-LV-2) ③ 노선 끝 역은 `nearMissCombos` ≥ 1(Y-LV-3) ④ 「요소 없이도 풀리는」 역은 그 요소의 노선에 넣지 않는다 — 해당 요소를 기본 승객으로 바꿔도 이기면 탈락(새 요소가 실제로 쓰이게).
- **난이도 지표 (초안):** `winningCombos / 전체 묶음`이 작을수록 어렵다. 노선 안에서 롤러코스터(쉬움 → 어려움 → 쉬움, 리서치 §3)로 배치한다.
- 사람이 고른 역(프로토타입 8개)은 그대로 넣고 `stats`만 채운다. 2·3·5·7번 역은 니어미스가 0이므로 노선 끝에 두지 않는다.
- `solution`은 이기는 묶음 중 첫 툭 박자가 가장 이른 것 하나를 저장한다(힌트용).

### 3.3 결정성
같은 시드·같은 도구 버전 → 같은 `levels.json`. 테스트가 몇 개 역을 다시 만들어 파일과 비교한다(2-7 `levels_test` 패턴).

## 4. 골든 테스트 (구현의 이식 판정)

| 테스트 | 기대 |
|---|---|
| 프로토타입 8개 역을 Dart 엔진 + Dart 풀이기로 | 시작점 `1·2·1·1·1·1·1·1`, 니어미스 `8·0·0·64·0·8·0·128`, 이기는 묶음 `8·16·64·64·8·8·2·64` (solver.js 출력과 같다) |
| 역 1: 맨 왼쪽 승객(아무도 안 보는 사람)을 박자 0에 툭 | 하품이 한 박자에 한 사람씩 오른쪽으로 옮아, 4번째 박자 처리에서 4명 모두 잠듦 → 승리 |
| 역 1: 두 번째 승객을 툭 | 3명 잠듦, 1명 깨어 있음 → 니어미스 |
| 잠든 승객이 시선을 막는다 (Y-SIGHT-2) | A→B→C 일렬에서 B가 잠들면 C는 A를 못 본다 |
| 커피 툭 (Y-TAP-2) | 거절, `tapsLeft` 그대로 |
| 말똥말똥이 마주 보는 사람과 하품을 주고받음 (Y-BEAT-5) | 하품 2번 뒤 잠듦 |
| 두리번: 시선 판정이 회전보다 먼저 (Y-BEAT-3) | 박자 k에 보고 있던 방향으로 옮음 |
| 패배는 하품 없는 박자 1번 뒤 (Y-LOSE-1) | 연쇄가 끝난 박자에는 지지 않는다 |
| 툭이 남아 있으면 지지 않는다 | 100박자 뒤에도 `playing` |

## 5. 앱 시작·진행

```
앱 시작 → levels.json 읽기(한 번) → progress 읽기 → 노선도(현재 역에 열차)
노선도 「다음 역」/역 탭 → 객차(판 시작)
도착 카드 「다음 역」 → 객차(다음 역)   |   「노선도」 → 노선도(열차가 다음 역으로 이동하는 움직임)
```
