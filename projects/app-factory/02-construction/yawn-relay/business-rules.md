# Business Rules — 하품 릴레이 (가칭)

> **SoT:** `prototypes/yawn-relay/index.html` `#engine` + UI 스크립트. 각 규칙의 `출처` 열이 함수다. 프로토타입은 오너 재미 판정을 통과했으므로(2026-10-16)
> **판정 규칙은 바꾸지 않는다.** 바꾸면 §편차에 적고 오너 확인을 받는다. 데이터 형태는 [`domain-entities.md`](domain-entities.md).

## 1. 시선

| ID | 규칙 | 출처 |
|---|---|---|
| Y-SIGHT-1 | 승객은 바라보는 방향(상·하·좌·우)으로 한 칸씩 나아가며, **처음 마주치는 승객 한 명**만 본다. 빈칸은 지나친다. 판 밖으로 나가면 아무도 보지 않는다 | `trace` |
| Y-SIGHT-2 | 처음 마주치는 승객은 **상태와 종류에 상관없이** 시선을 막는다. 잠든 사람·커피·휴대폰 승객도 그 뒤 사람을 가린다 | `trace` (grid는 상태를 보지 않음) |
| Y-SIGHT-3 | 창문 반사 칸에서 시선이 꺾인다: `/` 는 오른쪽↔위, 왼쪽↔아래 / `\` 는 오른쪽↔아래, 왼쪽↔위. 창문 칸에는 사람이 없다 | `trace` `MIR` |
| Y-SIGHT-4 | 시선 추적은 최대 64칸에서 멈춘다(창문이 고리를 이뤄도 끝난다) | `trace` |
| Y-SIGHT-5 | **볼 수 있는 사람** = 깨어 있고, 커피도 휴대폰도 아닌 승객. 잠든 사람·커피·휴대폰 승객은 아무도 보지 않는다(그래서 아무 하품도 옮지 않는다) | `canSee` |

## 2. 박자

| ID | 규칙 | 출처 |
|---|---|---|
| Y-BEAT-1 | 박자는 650ms마다 한 번, 판이 시작되는 순간부터 쉬지 않고 돈다(툭을 안 해도 돈다 — 두리번 타이밍 퍼즐의 전제) | UI `BEAT`, `restartClock` |
| Y-BEAT-2 | 한 박자 처리 순서: ① 이번 박자 하품 집합 `yawnNow`를 정한다 ② **볼 수 있는 사람** 중 시선 대상이 `yawnNow`에 있는 사람을 「다음 박자 하품」으로 예약 ③ `yawnNow`의 모든 사람 하품 횟수 +1, 횟수 ≥ 필요 횟수면 잠든다 ④ 깨어 있는 두리번 승객이 시계 방향으로 돈다 ⑤ 예약에서 잠든 사람을 뺀다 ⑥ 예약이 다음 박자의 `yawnNow`가 된다 | `step`, UI `beat` |
| Y-BEAT-3 | 시선 판정(②)은 같은 박자의 회전(④) **전에** 한다. 두리번 승객은 「이번 박자에 보고 있던 방향」으로 판정된다 | `step` 순서 |
| Y-BEAT-4 | 두리번 승객은 깨어 있는 동안 박자마다 돈다(위 → 오른쪽 → 아래 → 왼쪽). 잠들면 멈춘다 | `step` `CW` |
| Y-BEAT-5 | 이번 박자에 하품하는 사람도 남을 볼 수 있다. 그래서 마주 보는 두 사람은 하품을 주고받는다(말똥말똥 승객이 두 번째 하품을 받는 방법) | `step` ②에 `yawnNow` 제외 없음 |

## 3. 툭 (플레이어 조작)

| ID | 규칙 | 출처 |
|---|---|---|
| Y-TAP-1 | 승객을 탭하면 그 사람이 **지금 진행 중인 박자**의 `yawnNow`에 들어간다(다음 박자 처리 때 하품한 것으로 센다). 툭 1 소모 | `tap` |
| Y-TAP-2 | 커피 승객은 툭을 거절한다: 흔들림 + 「커피 마시는 중」, **툭은 소모되지 않는다** | `tap` |
| Y-TAP-3 | 잠든 사람, 이미 이번 박자에 하품하는 사람을 탭하면 아무 일도 없다(툭 소모 없음, 피드백 없음) | `tap` |
| Y-TAP-4 | 툭이 0이면 흔들림 + 「툭이 없어요」 | `tap` |
| Y-TAP-5 | 휴대폰 승객은 탭할 수 있다(하품하고, 남들이 그 사람을 볼 수 있다) | `tap` (휴대폰 거절 없음) |
| Y-TAP-6 | 판이 끝난 뒤(승·패 카드)에는 탭이 무시된다 | `tap` `ended` |

## 4. 잠·승패

| ID | 규칙 | 출처 |
|---|---|---|
| Y-SLEEP-1 | 필요 하품 횟수: 말똥말똥 2, 그 밖 1. 잠든 사람은 다시 깨지 않는다 | `parseLevel` `need`, `step` |
| Y-WIN-1 | **커피 승객을 뺀 모두가 잠들면 승리.** 박자 처리 직후 패배보다 먼저 판정한다 | `isWin`, `beat` |
| Y-LOSE-1 | 패배 = 툭이 0 **그리고** 다음 하품 예약이 없음 **그리고** 하품 없는 박자가 1번 지남. 툭이 남아 있으면 연쇄가 멈춰도 지지 않는다(플레이어가 다시 툭 할 때까지 기다린다) | `beat` `beatsIdle` |
| Y-NEAR-1 | **니어미스** = 패배했을 때 깨어 있는 사람(커피 제외)이 정확히 1명. 결과 문구를 바꾸고(「딱 한 명이 안 자요」) 그 사람을 강조한다 | `finish`, `awakeCount` |

## 5. 레벨·진행

| ID | 규칙 | 출처 |
|---|---|---|
| Y-LV-1 | 역은 순서대로 연다. 역 N을 깨면 N+1이 열린다. 깬 역은 언제든 다시 할 수 있다 | UI `progress` |
| Y-LV-2 | 레벨 1~3은 「지지 않게」: 이기는 툭 조합이 여러 개거나, 지더라도 니어미스가 나오는 배치(리서치 §3). 역 1은 손가락 안내를 띄운다(`guide`) | 리서치 §3, `LEVELS[0].guide` |
| Y-LV-3 | 모든 역은 도구의 풀이기가 **이기는 조합 ≥ 1**을 확인한 것만 넣는다. 니어미스 조합이 0인 역은 노선 끝 역에 쓰지 않는다(프로토타입 교훈) | 프로토타입 기록 §2 |
| Y-LV-4 | 새 요소는 한 번에 하나, 그 요소만 있는 쉬운 역에서 먼저 나온다. 노선(장)마다 요소 하나 | 리서치 §3 (CrazyLabs) |
| Y-LV-5 | 판 크기는 최대 6×6, 승객 최대 18명 (손가락 64dp 이상 확보, NFR) | NFR |

## 6. 광고 (코어 1-2 §4 정책 위)

| ID | 규칙 |
|---|---|
| Y-ADS-1 | 배너는 노선도(홈)에만. 객차 화면과 결과 카드에는 배너가 없다 |
| Y-ADS-2 | 전면은 승리 뒤 「다음 역」을 누를 때만(`RoundAds.roundTransition`), **역 1~5는 부르지 않는다**. 간격·세션 상한·초기 세션 면제는 코어 `AdPolicyConfig` 값을 따른다. 패배 뒤 「다시」에는 전면이 없다(실패를 벌하지 않음) |
| Y-ADS-3 | 보상형 ① **「광고 보고 한 번 더 툭」**: 패배 카드에서 판마다 1회, 툭 1개를 받고 판이 그 자리에서 이어진다(프로토타입 동작). 니어미스면 대표 버튼, 아니면 보조 버튼 ② **「광고 보고 힌트」**: 같은 역 3번 실패 뒤부터 패배 카드에 보인다. 누르면 `solution`의 첫 툭 대상 승객과 박자를 보여 준다 |
| Y-ADS-4 | 보상형 버튼에는 받는 것을 적는다. 광고를 거절해도 「다시」는 언제나 있다. `unavailable`이면 지급(1-2 D3), 광고 제거 구매자는 광고 없이 지급(키트 `RewardGate`) |
| Y-ADS-5 | 앱 오프닝 광고는 쓰지 않는다(판이 짧아 재진입이 잦다) |

## 7. 화면·아트

| ID | 규칙 |
|---|---|
| Y-UI-1 | **이모지 금지**(DECISIONS 2026-10-16). 승객·아이콘·말풍선·효과는 전용 에셋이다 |
| Y-UI-2 | 새 요소가 처음 나오는 역에는 판 바로 위에 한 줄 힌트를 둔다(프로토타입 `hint`). 튜토리얼 화면·슬라이드는 없다 |
| Y-UI-3 | 시선 방향은 색이 아니라 **얼굴·몸의 방향**으로 읽혀야 한다(색약 대응). 시선선은 보조 |
| Y-UI-4 | 실제 지하철 노선 색 조합·로고·역명·안내 방송 문구를 그대로 쓰지 않는다. 노선·역은 가상이다 |
| Y-UI-5 | 「애니메이션 줄이기」면 승객 상태가 즉시 바뀌고(하품·꾸벅 프레임 생략), 시선선은 그대로 보인다. 박자 길이는 바뀌지 않는다(규칙이 시간에 묶여 있음) |

## 8. 코어 `factory_game_kit` 재사용
- `SplitMix64`(레벨 생성 도구), `RewardGate`·`RoundAds`(Y-ADS), `GameFeedback`(효과음·진동), `BestScores`는 쓰지 않는다(점수 없음).
- `ShareGrid`는 이모지 격자라 Y-UI-1과 충돌한다 → 1차 출시에 공유 기능을 넣는다면 이미지 공유로 따로 설계한다(미해결 질문).
