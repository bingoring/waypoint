- **규칙 문서:** `waypoint/projects/app-factory/02-construction/yawn-relay/business-rules.md`(규칙 ID Y-*), `business-logic-model.md`.

## 2. 할 일

1. 프로토타입 엔진에 **기믹 6종**(§3)을 넣는다. 기존 규칙과 역 8개의 동작은 바꾸지 않는다.
2. 기믹마다 **역 2개**를 만든다: ① 소개 역(그 기믹만, 쉬움, 이기는 시작점 ≥ 2) ② 조합 역(앞서 나온 기믹과 섞음, 니어미스 조합 ≥ 1). 총 12개를 기존 8개 뒤(역 9~20)에 붙인다. 소개 역에는 프로토타입 형식의 한 줄 힌트를 단다.
3. `solver.js`가 새 기믹을 그대로 쓰도록 유지하고(엔진을 `index.html`에서 불러오는 구조 유지), **새 역 12개 모두 `winningStarts ≥ 1`** 을 확인한다. 「그 기믹 없이도 풀리는」 역은 버린다(기믹을 기본 승객/빈칸으로 바꿔도 이기면 탈락).
4. UI: 새 승객·타일 표시(프로토타입이므로 이모지·도형 임시 사용 가능), 코골이·울음·잠꼬대·문 열림 순간의 피드백(말풍선·흔들림), 역 목록에 새 역 추가.
5. 오너가 휴대폰으로 해 볼 수 있게 프로토타입을 공개한다. 앞선 공개본은 claude.ai Artifact였다(`https://claude.ai/artifact/Q8pudmz7ca6538N7QMj3dK`). 같은 Artifact를 갱신하거나 새로 공개하고, 링크를 기록한다.
6. 기록: `waypoint/.../hypercasual/yawn-relay-prototype-2026-10-16.md`에 「§4 기믹 확장(2026-10-16~)」 절을 덧붙인다 — 각 기믹의 확정 규칙, 새 역 12개의 풀이기 표(solver.js 출력), 오너 판정 칸(비워 둠).

## 3. 기믹 6종 규칙 (초안 — 구현하며 모호한 점은 가장 단순한 해석을 고르고 기록에 적는다)

공통: 「이웃」 = 상·하·좌·우로 붙은 칸의 승객. 「깨운다」 = `asleep = false`, `count = 0`(방향 그대로). 깨어난 사람은 다음 박자부터 다시 본다. 커피 승객은 깨울 대상이 아니다(애초에 잠들지 않음).

| 기믹 | 토큰 | 규칙 | 노리는 퍼즐 |
|---|---|---|---|
| **코골이 아저씨** | 종류 `z` | 평소엔 기본 승객과 같다. **잠든 뒤** 2박자마다(잠든 박자를 0으로 세어 2, 4, 6…) 코를 골아 **잠든 이웃을 깨운다**. 자기 자신은 깨지 않는다 | 이 사람은 마지막에 재워야 한다(순서) |
| **우는 아기** | 종류 `b` | 기본 승객처럼 보고 하품을 받는다. **깨어 있는 동안** 4박자마다(박자 번호 `k % 4 == 3`) 울어서 **잠든 이웃을 깨운다** | 아기를 먼저 재워야 한다(코골이와 반대) |
| **잠꼬대 승객** | 종류 `t` | 잠드는 박자의 다음 박자에 한 번, **바라보는 방향의 바로 옆 칸**에 깨어 있는 승객(커피 제외)이 있으면 그 사람을 하품 예약에 넣는다(시선·가림과 무관) | 시선이 닿지 않는 곳으로 건너가는 다리 |
| **마스크 승객** | 종류 `m` | 하품은 받는다(보고, 따라 하품하고, 잠든다). 하지만 **이 사람의 하품은 남에게 보이지 않는다** — 다른 사람의 시선 대상이 마스크 승객이면 옮지 않는다. 시선은 여전히 가린다 | 휴대폰 승객의 반대, 연쇄가 끊기는 곳 |
| **스테인리스 기둥** | 타일 `O.` | 사람이 없는 칸. 시선이 기둥에 닿으면 **진행 방향의 양옆(90°) 두 갈래**로 나뉘어 계속 나아간다. 한 사람이 최대 두 명을 볼 수 있고, 둘 중 하나라도 하품하면 따라 한다. 갈라진 시선이 다시 기둥을 만나면 한 번만 더 가른다(무한 분기 방지) | 갈림길 |
| **출입문** | 레벨 속성 `doors: [[r,c],…]`, `doorEvery: N` | N박자마다(`k % N == N-1`) 문이 열린다. 문 칸의 승객이 「내리고」 **깨어 있는 같은 종류·같은 방향의 새 승객이 탄다**(= 깨움, 하품 예약도 지움). 문 칸에는 커피 승객을 두지 않는다 | 시간 압박, 「문 열리기 전에」 |

처리 순서(한 박자): 기존 `step` ①~⑥(시선 → 하품·잠 → 두리번 회전 → 예약) 다음에 ⑦ 잠꼬대 예약 추가 ⑧ 코골이·울음 깨움 ⑨ 문 열림. 승리 판정은 ⑨ 뒤에 한다. 이 순서를 바꾸면 기록에 이유를 적는다.

## 4. 지켜야 할 것

- **기존 역 8개의 풀이기 출력이 그대로여야 한다:** 시작점 `1·2·1·1·1·1·1·1`, 니어미스 `8·0·0·64·0·8·0·128`, 이기는 묶음 `8·16·64·64·8·8·2·64`. 바뀌면 기존 규칙을 건드린 것이니 되돌린다.
- 출시 앱에서는 이모지를 쓰지 않는다(DECISIONS 2026-10-16). 프로토타입은 예외지만, 새 아이콘을 그릴 수 있으면 도형으로 그린다.
- 판 크기 최대 6×6, 승객 최대 18명, 툭 3개 역은 승객 12명 이하(풀이기 비용).
- 실제 지하철 노선 색·로고·역명을 쓰지 않는다. 새 역 이름도 가상(뜻이 있는 이름).
- 응답·문서는 한국어. 코드 주석·커밋 메시지는 저장소 관례(한국어 커밋, 마지막 줄 `Co-Authored-By`)를 따른다.
