### 1.2 이식 동일성

| ID | 규칙 | 위반 시 |
|---|---|---|
| Y2-PORT-1 | Dart 엔진은 프로토타입 엔진과 **박자마다 상태 전체가 같다**(박자·배치·사람마다 위치·방향·잠·하품 수·잠든 박자·다음 하품 목록과 순서·사건 목록). 검사: JS로 뽑은 고정 자료(무작위 판 + 툭 + 박자별 상태) | 테스트 실패 = 버그 |
| Y2-PORT-2 | Dart 생성기는 같은 (노선, 역, 시드, 복습)에서 **JS 생성기와 글자 단위로 같은 판**(지도·툭 수·특수 설정·사람·사슬·기믹·필수 판정·시도 수·돌린 박자 수)을 낸다. 검사: JS 고정 자료 28노선 × 12역 × 시드 2 + 복습 판 | 테스트 실패 = 버그 |
| Y2-PORT-3 | 난수는 프로토타입 `weaveRng`(mulberry32)를 32비트 연산 그대로 옮긴다. `Math.imul` = 32비트 곱, `>>>` = 부호 없는 오른쪽 이동 | — |
| Y2-PORT-4 | 정렬은 **안정 정렬**(JS `Array.sort`는 안정, Dart `List.sort`는 아님 → `package:collection` `mergeSort` 또는 직접 구현). 동점 순서가 다르면 판이 달라진다 | 대조 실패 |
| Y2-PORT-5 | 집합·맵은 넣은 순서대로 돈다(Dart 기본 `LinkedHashMap`/`LinkedHashSet`). 방향 순서는 늘 U·R·D·L | — |
| Y2-PORT-6 | 생성 한도는 시간이 아니라 **돌린 박자 수**(단계마다 18만 박자, 40시드) — 기기 속도와 상관없이 같은 판 | — |
| Y2-PORT-7 | 생성기 전용 빠른 박자 계산(시선 기억)은 엔진과 결과가 같아야 쓴다 — Y2-PORT-1과 같은 고정 자료로 빠른 계산도 검사. 규칙의 기준은 엔진 하나 | — |

### 1.3 생성기 (엮기) — `weave.js`의 결정

| ID | 규칙 |
|---|---|
| Y2-GEN-1 | 계획: `base = 5 + 1.6·L'`(L' = 노선 번호(0부터), 단 빌런 노선 21~27은 14), `P = base + 0.9·min(n,12)`, 다섯 역마다(n % 5 = 4) ×0.7, 첫 두 역은 `max(5, base·0.85)`, 반올림 후 최대 46. 사슬 수 K = P<8:1, <16:2, <28:3, 그 밖 4 (노선 1 이상이면 최소 2). 판 크기 = 넓이 P/0.42, 열 3~7, 행 3~11 |
| Y2-GEN-2 | 판당 기믹: 노선 기믹 + 앞 노선 기믹 최대 2개(무작위). 복습 기믹이 있으면 그 하나를 반드시 넣는다(Y2-MAS-6). 이어폰 노선은 코골이를 함께 |
| Y2-GEN-3 | 창문·기둥·까치발·잠꼬대·대머리 판당 상한: 노선 기믹이면 2+⌊P/8⌋, 아니면 1+⌊P/16⌋(말똥말똥 노선은 기둥을 노선 기믹처럼) |
| Y2-GEN-4 | 사슬 기르기: 80% 확률로 가장 작은 사슬, 목표 ⌈P/K⌉+2명에 닿은 사슬은 쉼. 후보 점수 = 다른 사슬 시선과 겹침 ×3 + 다른 사슬 이웃 + 0.15·연결 길이 + 난수·1.5 + 기믹 가점 |
| Y2-GEN-5 | 사람을 붙일 때마다 계획 풀이(시작점을 박자 0에 툭)로 이기는지 확인, 못 이기면 되돌림 |
| Y2-GEN-6 | **장식 0:** 기믹마다 「쓰임」 검사 — 연결(창문·기둥·두리번·말똥말똥·고양이·잠꼬대·까치발·커플·대머리): 없애면 계획 풀이가 깨지거나 잠드는 박자가 바뀜 / 속임(휴대폰·커피·마스크·근시): 없애면 가장 가까운 시작점 툭 없이 이김 / 함정(그 밖): 계획 풀이 잠드는 박자가 바뀌거나 시작점 툭 박자 조합(시작점 K개 × 박자 S개, K≤2:6, 3:5, 4:4) 중 이기는 수가 달라짐 |
| Y2-GEN-7 | 판 검증: 계획 풀이 승리 · 고립 승객 0 · 사슬마다 3명 이상 · 사람 수 ≥ max(4, 0.8P) · 노선 기믹 포함 · 장식 0 |
| Y2-GEN-8 | 실패하면 시드를 바꿔 40번, 박자 18만 한도 — 그래도 못 만들면 규모 90% → 80%로 다시. 복습 기믹을 넣은 판을 못 만들면 복습 없이 |
| Y2-GEN-9 | 28호선(호통이 노선 기믹)은 맞는 판을 셋까지 만들어 툭 박자 조합 중 이기는 비율이 가장 낮은 판 |
| Y2-GEN-10 | 짐수레 짐표 색: 판의 짐수레 승객에게 행·열 순서로 0,1,2,3,0… (핸드오프 v3.3) |
| Y2-GEN-11 | 힌트·「한 번 더 툭」 정답은 **계획 풀이**(시작점을 박자 0에 툭)를 쓴다 — 풀이기 탐색 없이 즉시 |

### 1.4 노선 길이 적응 (2-13, `factory_adaptive` mastery)

| ID | 규칙 |
|---|---|
| Y2-MAS-1 | 노선마다 `LineMastery`, 플레이어마다 `Pace`. 판이 끝날 때(이김·짐·나감) `PlayRecord`로 `update`. 계단 높이 = 다음 판의 역 번호 n(생성기 `weavePlan`의 n) |

| Y2-MAS-4 | 진 시도 분류: 그 시도에서 툭 한 **사람 묶음**을 어떤 박자 조합으로 툭 하면 이길 수 있으면 손 실수(`executionFails`), 없으면 풀이 실수(`planFails`). 묶음 크기 K·박자 S는 Y2-GEN-6과 같고, 박자 한도(2만 박자) 안에 못 끝내면 모름(`otherFails`). 패배 카드가 떠 있는 동안 백그라운드에서 계산 |
| Y2-MAS-5 | 고민 시간: 시도마다 판이 보인 순간 ~ 첫 툭까지. 앱이 뒤로 간 시간, 입력 없이 60초 넘은 구간은 뺀다. 복잡도 = 사람 수 |
| Y2-MAS-6 | 복습: 강제 졸업(`forced`) 기믹은 `ReviewPlanner.pick`으로 뒤 노선 3판마다 하나에 넣는다(Y2-GEN-2), 복습 판은 `reviewed` |
| Y2-MAS-7 | 도움: 보상형 「한 번 더 툭」·힌트를 쓴 판은 `helped`. 광고 시청 여부·매출은 난이도 입력이 아니다(A-ETH-1 그대로) |

## 3. 권한 / 접근
N/A — 기기 안 게임 로직. 실력·고민 시간은 기기 밖으로 보내지 않는다(A-PRIV-1). 분석 이벤트는 §5 BLM 통합 지점의 익명 값만.

## 4. 불변식

- 생성된 모든 판은 계획 풀이로 이긴다(Y2-GEN-5·7).
- 같은 입력 → 같은 판(Y2-PORT-2·6). 기기·속도·언어(JS/Dart)와 상관없음.
- 호통 승객은 툭 대상이 아니다 — 생성기 시작점·힌트·풀이기·화면 모두.
- 노선 길이는 `minBoards` ≤ 졸업 판 수 ≤ `maxBoards`.
