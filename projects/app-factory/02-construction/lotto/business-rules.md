# Business Rules — 로또

| ID | 규칙 | 위반 시 |
|---|---|---|
| L-GEN-1 | 한 게임 = 1~45에서 서로 다른 6개, 오름차순 | — |
| L-GEN-2 | 고정수 ≤ 5개. 고정수와 제외수는 겹칠 수 없다 | 선택 UI가 막는다 |
| L-GEN-3 | 제외하지 않은 번호(45 − 제외수)가 6개 이상이어야 한다 → 제외수 ≤ 39 (고정수는 제외수와 겹치지 않으므로 이 조건만으로 충분) | 선택 UI가 막는다 |
| L-GEN-4 | 무작위는 `Random.secure()` 사용 (예측 가능한 시드 금지, 테스트만 주입) | — |
| L-GEN-5 | 한 번에 1~5게임. 같은 생성 묶음 안에 동일 게임이 나오면 다시 뽑는다 | — |
| L-RND-1 | 회차 계산은 **기기 시간대와 무관하게 KST**. 1회 = 2002-12-07(토). 판매 마감 토요일 20:00 KST 이후 저장한 번호는 다음 회차 대상 | — |
| L-WIN-1 | 등수: 6개 1등, 5개+보너스 2등, 5개 3등, 4개 4등, 3개 5등, 그 외 낙첨. 보너스는 2등 판정에만 쓴다 | — |
| L-WIN-2 | 대상 회차 데이터가 없으면 "추첨 전" 또는 "결과 대기"로 표시하고 판정하지 않는다 | — |
| L-DATA-1 | 당첨 데이터 = 에셋 ∪ 원격. 같은 회차가 겹치면 에셋 우선. 원격 JSON이 깨졌거나 형식이 틀린 항목은 버리고 비치명 오류 기록 | 에셋만 사용 |
| L-DATA-2 | 각 회차: 번호 6개 1~45 중복 없음, 보너스는 6개와 다름 | 해당 항목 버림 |
| L-STAT-1 | 통계 범위 = 최근 100회 (`app_lotto_stats_window`, 기본 100, 범위 20~500) | 기본값 |
| L-STAT-2 | 통계 추천 = 최근 범위의 출현 횟수 + 1을 가중치로 한 비복원 가중 추첨. 고정·제외수도 적용 | — |
| L-STAT-3 | 통계 화면·추천 결과에 "과거 출현 빈도일 뿐 당첨 확률을 높이지 않습니다"를 항상 표시 | — |
| L-STAT-4 | 잠금 해제는 보상 지급(`RewardOutcome.grants`) 시 KST 그날 자정까지. 광고 제거 구매자는 항상 열림 | — |
| L-HIST-1 | 이력은 최근 200개만 보관(오래된 것부터 삭제). 삭제는 사용자 확인 후 | — |
| L-ADS-1 | `interstitial_generate`(everyN 3): 결과를 본 뒤 "다시 생성"을 누를 때 `onTransition` (1-2 §4: 결과 확인 → 다음 행동) | — |
| L-RATE-1 | 번호를 저장할 때 `positiveMoment()` | — |
| L-AGE-1 | `audience.minAge: 18` | — |
