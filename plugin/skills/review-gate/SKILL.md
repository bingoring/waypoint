## 리뷰 게이트 (Code Review Gate) 🔍

코드를 산출하는 Construction phase 이후, Operations(배포/운영) 진입 전에 **독립 코드 리뷰 게이트**를 둔다.
Waypoint 의 사람 승인 게이트는 *설계*는 검토하지만 *코드 자체*는 검토 공백이 있고, 코드를 쓴 AI 가
테스트 통과까지 자기보고하는 **자기확증 편향**이 있다. 이를 구조적으로 메운다.

### 독립성은 "태도"가 아니라 "구조"다 (가장 중요)

- 리뷰어는 **작성자(구현 주체)와 컨텍스트를 공유하지 않아야 한다.** 별도 서브에이전트 · 별도 세션 ·
  (가능하면) 다른 모델 · 또는 사람이어야 한다.
- **"적대적으로 리뷰하라"는 지시만으로는 부족하다.** 같은 컨텍스트의 AI 는 코드를 *있는 그대로*가 아니라
  *의도한 대로* 읽으며, "왜 이 줄이 있는지"를 알기에 의심 대신 합리화한다. 지시(태도)는 이미 독립적인
  리뷰어를 *증폭*시킬 뿐, 독립성을 *제조*하지 못한다.
- 따라서 **같은 컨텍스트의 작성자가 인라인으로 수행하는 자기리뷰는 이 게이트를 충족하지 못한다.**
  (가벼운 self-lint 정도의 보조 가치만 인정)

### 절차

1. 리뷰어에게 `${CLAUDE_PLUGIN_ROOT}/templates/reviewer-brief-template.md`(적대적 리뷰 지시 템플릿)를 채워 전달한다.
   - refute 기본값(불확실하면 결함으로 가정), 사냥 대상 체크리스트, severity 등급, 출력 형식을 포함.
2. 받은 findings 를 **맹목 수용하지 않는다.** 각 항목을 검증하여 채택/반박하고, 반박은 근거를 남긴다.
3. 진짜 결함은 **수정 + 회귀 테스트**를 추가한다.
4. 결과(채택/반박/수정)를 리뷰 스테이지 문서에 정리하고 `AI_PROPOSED` → 사람 승인.

### 리뷰 기준선

리뷰어가 "결함"을 판정하는 기준은 리뷰어의 취향이 아니라 프로젝트가 미리 정한 **품질 기준**이다.
아키텍처 결정 스테이지(보통 1-3)에서 정적 분석 규칙, 보안 요건, 성능·메모리 예산, 테스트 범위를 정의하고,
리뷰어 지시(`reviewer-brief`)에 그 절을 입력으로 넣는다. 기준이 정의되지 않은 프로젝트는 리뷰 게이트 전에 먼저 정의한다.

### 적응형 깊이

- **단순/저위험**: 독립 리뷰어 1패스 + 단일 검증.
- **복잡/고위험**: 다관점(정확성·보안·동시성·운영) 적대 리뷰, 핵심 결함은 다수결 검증.

> 깊이는 조절하되 **독립성(컨텍스트 분리)은 타협하지 않는다.** 얕은 리뷰라도 독립이어야 의미가 있다.

## 코드 스테이지의 리뷰어 서브에이전트

Operations 앞의 리뷰 게이트와 별도로, 코드를 만드는 스테이지는 결과 검토를 요청하기 전마다 독립 리뷰를 한 번 거친다. 오너의 결과 검토에 오기 전에 결함을 고쳐 두려는 것이다.

- 리뷰어는 서브에이전트(`Agent` 도구)로 부른다. 가능하면 작성자와 다른 모델을 쓴다. 리뷰를 위해 별도 세션을 열지 않는다.
- 넘기는 것: diff(`git diff origin/<기본 브랜치>...HEAD`), 스테이지의 계획(스테이지 문서와 Build Spec), 위 「리뷰 기준선」의 품질 기준, `reviewer-brief-template.md`. 작성자의 설명이나 결론은 넘기지 않는다.
- 깊이는 위 「적응형 깊이」를 따른다.
- findings는 위 「절차」 2·3번대로 검증해 채택하거나 반박한다. 결과(결함 N건 가운데 수정 M건, 반박 K건)는 스테이지 문서와 그 「검토 요약」에 남긴다(`waypoint:stage`).
- Operations 앞의 `🔍` 리뷰 게이트를 맡은 세션도 리뷰어를 서브에이전트로 돌린다.
- 설계 스테이지(코드를 만들지 않는 스테이지)는 리뷰어 서브에이전트 없이 오너 검토를 한 번 거친다.

템플릿: 스테이지 문서 `${CLAUDE_PLUGIN_ROOT}/templates/review-stage-template.md`, 리뷰어 지시 `${CLAUDE_PLUGIN_ROOT}/templates/reviewer-brief-template.md`.

> 템플릿 파일은 Read 도구로 읽어 Write 도구로 프로젝트에 복사한다. Bash 명령 안에서는 `${CLAUDE_PLUGIN_ROOT}`를 쓰지 않는다(환경변수로 노출되지 않는다).
